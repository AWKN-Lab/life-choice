# 东方玄学知识库 - 数据库架构设计（详细版）

**版本**: v2.0
**更新**: 2026-06-05

---

## 一、设计原则

1. **案例驱动**：每条记录包含"原始信息→排盘→分析→断语→验证"完整链路
2. **字段完整**：不遗漏任何有价值的信息（如十神、纳音、大运详情）
3. **可追溯**：每条数据有来源、提取时间、验证状态
4. **统一规范**：统一命名、格式、编码

---

## 二、数据分层架构

```
┌──────────────────────────────────────────────────────┐
│                    案例层（Cases）                    │
│   命例 ←→ 卦例 ←→ 盘例 ←→ 风水案例                    │
├──────────────────────────────────────────────────────┤
│                    规则层（Rules）                    │
│   起盘规则 ←→ 格局规则 ←→ 断语规则 ←→ 调候规则        │
├──────────────────────────────────────────────────────┤
│                    知识层（Reference）                │
│   干支 ←→ 五行 ←→ 神煞 ←→ 星曜 ←→ 宫位 ←→ 卦象        │
├──────────────────────────────────────────────────────┤
│                    典籍层（Classics）                 │
│   滴天髓 ←→ 子平真诠 ←→ 穷通宝鉴 ←→ 三命通会          │
└──────────────────────────────────────────────────────┘
```

### 3.1 命例主表（bazi_cases）

```sql
CREATE TABLE bazi_cases (
    -- ========== 核心ID ==========

    name            TEXT,                         -- 姓名（可匿名）
```

### 8.3 命名规范

- 表名：`系统_模块`（如 bazi_cases, yao_cases）
- 字段：snake_case（如 birth_year, day_master）
- 案号：`系统-年份-4位序号`（如 BZ-2024-0001）
- 时间：ISO 8601（如 2024-03-15）
- JSON 字段：数组用 `[]`，对象用 `{}`
