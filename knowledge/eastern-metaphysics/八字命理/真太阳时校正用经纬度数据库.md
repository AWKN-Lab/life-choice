\## 一、真太阳时校正原理



真太阳时是以太阳实际位置为依据的时间，与平太阳时（如北京时间）存在时差，主要由两方面引起：



1\. \*\*经度差异\*\*：北京时间以东经 120° 为基准，当地经度每偏离 1°，时间差 4 分钟（东经为正，西经为负）。

2\. \*\*均时差\*\*：地球公转速度不均匀导致的微小波动，最大约 ±16 分钟（一般占卜用途可忽略）。



\*\*校正公式\*\*（忽略均时差）：

```

真太阳时 = 北京时间 + (经度 - 120°) × 4 分钟

```



因此，获取用户所在地点的精确经度是校正的关键。

\### 2.3 GeoNames API 兜底查询



当用户输入的地点不在内置数据库中时，调用 GeoNames API 实时查询。



\*\*接口地址\*\*：

```

http://api.geonames.org/searchJSON?q={城市名}\&maxRows={最大返回条数}\&username={你的用户名}

```



\*\*参数说明\*\*：

\- `q`：查询关键词（支持中文）

\- `maxRows`：建议设为 3（返回最匹配的 3 个结果）

\- `username`：已注册的用户名（如 `lay10919669`）



\*\*返回示例\*\*：

```json

\## 三、真太阳时计算函数（JavaScript 示例）



```javascript

/\*\*

&#x20;\* 将北京时间转换为当地真太阳时

&#x20;\* @param {Date} beijingDate - 北京时间（未校正的用户输入时间）

&#x20;\* @param {number} lng - 当地经度（东经为正）

&#x20;\* @returns {Object} { solarDate, description }

&#x20;\*/

function beijingToLocalSolarTime(beijingDate, lng) {

&#x20; // 经度差引起的时差（分钟）

&#x20; const lonDiff = lng - 120;

&#x20; const timeDiffMinutes = lonDiff \* 4;



&#x20; // 计算真太阳时（忽略均时差）

&#x20; const solarDate = new Date(beijingDate.getTime() + timeDiffMinutes \* 60000);



&#x20; // 生成说明文本

&#x20; const absDiff = Math.abs(timeDiffMinutes);

&#x20; const direction = lonDiff > 0 ? '晚' : '早';

&#x20; const description = `经度校正时差约 ${absDiff.toFixed(1)} 分钟，当地真太阳时比北京时间${direction} ${absDiff.toFixed(1)} 分钟`;



&#x20; return { solarDate, description };

}

```

\## 五、内置数据获取与更新



\### 5.1 数据来源

\- \*\*中国地级市\*\*：可从国家地理信息公共服务平台或 GeoNames 中国数据集中提取 `PPLA2` 特征码的地点。

\- \*\*世界主要城市\*\*：从 GeoNames `cities15000.zip`（人口>15000的城市）中筛选各国首都及主要城市。



\### 5.2 数据格式建议

将数据保存为 `builtin\_locations.json`，置于智能体可访问的路径。文件结构如 2.2 节所示。



\### 5.3 查询函数示例

```javascript

function searchBuiltin(place) {

&#x20; // 简单模糊匹配：去除“市”“区”“县”等后缀，逐级查找

&#x20; // 此处为伪代码，实际需根据内置数据结构实现

&#x20; const normalized = place.replace(/\[市县区]$/, '');

&#x20; for (const province in builtinData.中国) {

&#x20;   for (const city in builtinData.中国\[province]) {

&#x20;     if (city.includes(normalized) || normalized.includes(city)) {

&#x20;       return builtinData.中国\[province]\[city];

&#x20;     }

&#x20;   }

&#x20; }

&#x20; // 查找其他国家

&#x20; for (const country in builtinData) {

&#x20;   if (country !== '中国') {

&#x20;     for (const city in builtinData\[country]) {

&#x20;       if (city.includes(normalized)) return builtinData\[country]\[city];

&#x20;     }

&#x20;   }

&#x20; }

&#x20; return null;

}

```

\## 六、注意事项



1\. \*\*时区问题\*\*：真太阳时计算只依赖经度，与用户所在时区无关。但返回的时间对象仍可使用原时区标记（如 UTC+8），只需调整小时数。

2\. \*\*地点匹配精度\*\*：用户可能输入街道级地址，内置数据仅到城市级。城市级经度误差一般在几分钟内，对占卜时辰影响可接受（除非恰好卡在时辰交界点）。

3\. \*\*API 限流\*\*：务必控制调用频率，建议每用户每分钟不超过 10 次，每小时不超过 100 次。

4\. \*\*备用方案\*\*：若 GeoNames 服务不可用，可回退到仅使用内置数据，并在输出中提示“部分地点校正可能不精确”。

5\. \*\*均时差处理\*\*：若需极高精度（如时辰交界时刻），可引入天文算法库计算真太阳时，但一般占卜场景可忽略。
