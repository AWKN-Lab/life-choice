# 类型债务管理机制

> 建立日期: 2026-06-18
> 触发事件: 2026-06-17 前端 254 处 TS 类型错误一次性清算后，建立长效机制防止债务再累积

---

## 一、为什么需要这个机制

**根因**: 项目缺乏类型债务管理，错误累积到 254 处才危机式清算。本次建立机制，让类型错误**产生即发现、发现即修复**，避免再次累积。

**核心原则**: 类型错误像财务债务——小额持续偿还，比大额危机清算成本低 10 倍。

---

## 二、机制组成（4 层防护）

### 第1层：本地检测（开发者自助）

```bash
# 手动检查（开发中随时用）
npm run typecheck

# 生成报告（含错误分布、趋势对比）
npm run typecheck:report
```

**使用时机**:
- 开发中怀疑有类型问题时
- 提交前自检
- 拉取新代码后验证

### 第2层：提交门禁（pre-commit hook）

```bash
# 一键启用（每个开发者执行一次）
npm run setup:hooks
```

启用后，每次 `git commit` 自动运行 `tsc --noEmit`：
- ✅ 0 errors → 提交通过
- ❌ 有 errors → 提交被阻止，显示前 20 条错误

**紧急跳过**: `git commit --no-verify`（仅紧急情况，需事后补修复）
**禁用**: `git config --unset core.hooksPath`

### 第3层：趋势追踪（基线日志）

每次运行 `npm run typecheck:report` 会追加一行到 [typecheck-baseline.log](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/typecheck-baseline.log)：

```
2026-06-17 | 0 | 0 | 初始基线 | 254→0 修复完成
2026-06-18 | 2 | 1 | 增加 | +2    ← 机制立即发现回归
2026-06-18 | 0 | 0 | 减少 | -2    ← 修复后归零
```

**趋势判读**:
- 持续为 0 → 健康
- 单次 +N → 有回归，立即修复
- 缓慢上升 → 类型债务累积，安排偿还

### 第4层：偿还流程（当错误出现时）

```
发现错误 (typecheck:report)
    ↓
按文件归类 (报告自动输出 Top 10)
    ↓
按错误数排序，优先修最多的文件
    ↓
小步批量修复（每批 5-30 处）
    ↓
每批验证: typecheck + test:run
    ↓
git commit（独立 commit，可回滚）
    ↓
重复直到 0 errors
```

## 三、常见错误模式速查

| 错误码 | 含义 | 修复模式 |
|--------|------|---------|
| TS1361 | `import type` 导入了 enum | enum 改用普通 `import` |
| TS2304 | 找不到名称 | 检查 import 是否缺失 |
| TS2322 | 类型不匹配 | 检查字段名/类型定义 |
| TS2345 | 参数类型不匹配 | 加 `as any` 断言或修正类型 |
| TS18046 | unknown 类型 | 加类型守卫或 `as` 断言 |
| TS18047 | possibly null/undefined | 用局部变量保存可选属性 |

## 四、开发者工作流

### 新功能开发时

```bash
# 1. 开发中随时检查
npm run typecheck

# 2. 提交前（hook 自动运行，也可手动）
npm run precommit   # = typecheck + test:run

# 3. 提交
git add . && git commit -m "feat: xxx"
# → hook 自动运行 typecheck，通过才提交
```

### 拉取代码后

```bash
git pull
npm run typecheck:report   # 确认无新错误引入
```

### 修复类型错误时

```bash
# 1. 看全貌
npm run typecheck:report

# 2. 按文件归类，优先修错误最多的文件
# 3. 每批修复后验证
npm run typecheck && npm run test:run

# 4. 提交（hook 会再次验证）
git add . && git commit -m "fix(types): xxx"
```

## 五、机制维护

### 每月检查

```bash
# 查看趋势
cat typecheck-baseline.log

# 如果有累积，安排偿还
npm run typecheck:report
```

### 新成员入职

```bash
# 第一件事：启用 hooks
npm run setup:hooks

# 验证
npm run typecheck:report
```

### 机制升级触发条件

- 错误数连续 3 次提交上升 → 检查 hook 是否被绕过
- 单月累积 > 20 处 → 评估是否需要类型重构
- 重复出现同类错误 → 更新速查表或加 ESLint 规则
