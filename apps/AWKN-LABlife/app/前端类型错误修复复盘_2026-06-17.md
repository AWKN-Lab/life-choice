## 一、标准复盘 10 步

### 第一步：问题定义

**本质**: 项目在持续迭代中积累了 254 处 TypeScript 编译错误，涉及 43 个文件。这些错误不是"警告"，而是 `tsc` 实际报错——意味着代码库存在类型不一致、import 误用、字段名不匹配、闭包内类型收窄丢失等问题。

**核心矛盾**: 快速开发过程中，类型系统被绕过而非被遵守。每次绕过都留下一个"类型债务"，累积到临界点后必须一次性清算。

### 第四步：原因分析（三层拆解）

#### 表层原因（直接触发）
- `import type` 导入了 enum（TS1361）
- 字段名拼写不一致（`id` vs `record_id`）
- 闭包内可选属性类型收窄丢失
- 第三方库 API 变更（echarts `EChartsOption` → `EChartsCoreOption`）

#### 机制原因（流程/系统层）
1. **缺乏类型门禁**: 开发过程中没有 `tsc --noEmit` 作为 pre-commit hook
2. **类型定义分散**: `resultTypes.ts`、`knowledgeGraph.ts`、`card.ts` 等多个类型文件，维护者难以跟踪所有字段名
3. **Zod schema 与 TS 类型脱节**: zod v4 API 变化导致 `.default()` 语义改变
4. **批量修复依赖 Task agent**: 第六批后改用 Task agent 批量修复，虽然高效但缺乏人工逐行审查

#### 根因（不解决会复发）
**没有"类型债务"管理机制**。项目像管理代码债一样管理类型债是缺失的——没有定期扫描、没有优先级分级、没有偿还计划。本次是"危机式清算"而非"渐进式偿还"。

## 三、经验沉淀（E 编号列表）

### E59｜import type 误导入 enum 的诊断与修复
**类型**: FIX（修复型教训）
**场景**: TS1361 错误（'X' cannot be used as a value because it was imported using 'import type'）
**根因**: enum 是运行时值，`import type` 只保留类型信息，运行时值为 undefined
**修复步骤**:
1. 搜索 `import type { ... EnumName ... }` 模式
2. 将 enum 从 type import 移到普通 import
3. 验证 `npx tsc --noEmit` 错误消除
**证据**: npcFateStore.ts、KnowledgeGraphViz.tsx、multiEndingStore.ts 均出现同类错误
**预防**: 新建文件时，enum 相关导入默认用普通 import，除非 100% 确定只使用类型

### E60｜闭包内类型收窄丢失的修复模式
**类型**: DERIVED（推导型经验）
**场景**: setTimeout/setInterval 回调中使用可选属性
**根因**: 闭包捕获的是变量的引用而非快照，可选链 `?.` 在回调执行时可能已改变
**修复步骤**:
1. 在闭包外保存可选属性到局部常量：`const x = obj?.prop;`
2. 在 if 块内使用局部常量：`if (x) { setTimeout(() => { use x }, 0) }`
3. 验证回调内不再报 "possibly undefined"
**证据**: ResultChat.tsx L240-247（memoryAnchor 闭包问题）
**预防**: 任何 setTimeout 回调中使用可选属性时，先在外部保存为局部变量

### E61｜字段名一致性检查清单
**类型**: CHECKLIST（检查清单）
**场景**: 访问对象属性时报 "Property 'X' does not exist on type 'Y'"
**修复步骤**:
1. 搜索类型定义文件（interface/type）确认正确字段名
2. 检查是否驼峰/下划线命名不一致（`record_id` vs `recordId`）
3. 添加 `?? defaultValue` 或 `as any` 断言（仅作为临时方案）
**证据**: ResultChat.tsx `result?.id` → `result.record_id`
**预防**: 跨文件引用类型时，先用 Grep 搜索字段名确认

### E62｜zod v4 `.default()` 行为变更
**类型**: FIX（修复型教训）
**场景**: zod schema 的 `.default()` 导致 TS 类型从可选变必填
**根因**: zod v4 中 `.default()` 改变了类型推断
**修复步骤**:
1. 移除 `.default()`，改用运行时默认值
2. 或使用 `.optional().default()` 分离可选性和默认值
**证据**: stateMachine.ts 中 `priority: z.number().optional().default(0)` 导致问题
**预防**: zod schema 变更后，检查所有 `.default()` 的 TS 类型推断

### E63｜小步批量修复 + 每批验证的 TS 错误修复 SOP
**类型**: SOP（标准操作流程）
**场景**: 项目积累大量 TS 类型错误需要修复
**修复步骤**:
1. `npx tsc -p tsconfig.app.json --noEmit` 看全貌
2. 按文件归类错误，优先修错误多的文件
3. 每批修复 5-30 处，修复后立即 `tsc --noEmit` 验证
4. `npx vitest run` 确认无回归
5. `git add` + `git commit`（独立 commit，可回滚）
6. 重复 1-5 直到 0 errors
**证据**: 本次 254→0，11 个 commit，每批独立验证
**预防**: 任何 TS 错误修复任务都应遵循此 SOP
