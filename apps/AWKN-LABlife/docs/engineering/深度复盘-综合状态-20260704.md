## 2. P0 阻断卡点（5 项，必须部署前解决）

### P0-1: 生产 Git 真相缺失
- **证据**: 生产 HEAD `02227c4` 本地无法解析；生产工作区 5 个已修改文件未回流 Git
- **影响**: 无法从本地复现生产构建，无法追溯生产真实代码版本
- **完成标准**:
  1. 从生产源码建立可追溯分支
  2. 提交生产真实源码、依赖清单、锁文件
  3. 生成不可变发布清单（commit + dist hash + schema hash + asset manifest）
  4. 清理生产工作区，`git status` 归零
  5. 本地、生产、发布包可通过同一 commit 对齐

### P0-2: 显式路由没有最高优先级
- **证据**: 生产日志显示用户传入 `routeType=ziping` + 事业财运问题，调度器却记录 `defaulting to liuyao` + `parallel generation: liuyao + qimen`
- **影响**: 用户明确选择八字后系统切换到六爻/奇门，入口契约被覆盖
- **完成标准**:
  1. 路由优先级：`用户显式 routeType > 上下文已锁定术数 > 意图分类 > 关键词匹配 > 默认回退`
  2. 新增真实回归用例：`routeType=ziping` + 事业财运问题，最终主 Agent 仍为 Ziping
  3. 任何显式路由被覆盖时触发告警

### P0-3: ReAct 没有完整事实账本（FactLedger）
- **证据**: 生产日志显示请求已包含出生日期/时间/性别 + 排盘完成，ReAct 仍反复要求用户补充年龄/大运/出生信息
- **影响**: 增加模型调用次数 + 延迟 + 用户感知"系统没记住"
- **完成标准**:
  1. 出生信息、排盘结果、当前大运、流年、用户背景进入统一 FactLedger
  2. 已存在字段禁止再次追问
  3. 每次追问记录缺失字段与来源
  4. 无新增信息时强制收敛到已有事实答案

### P0-4: 五层输出与 LLM 结构协议不稳定
- **证据**: 生产日志出现 `5层输出校验失败：缺少 数术断句、半山落句、具体落点、下一步动作`；JSON 截断、Schema 字段缺失、质量分低至 20、`finish=length`、Ziping 总耗时 177s、L2 超时 150s 回退 L1
- **影响**: 深推质量、响应时间、输出完整性均未达到稳定生产标准
- **完成标准**:
  1. Provider 级别配置足够 `max_tokens`
  2. 使用 JSON Schema 或可靠结构化响应模式
  3. 截断检测后允许一次针对性补全
  4. 质量门返回缺失字段列表给修复器
  5. 真实 Golden Case 连续运行通过，不依赖模板兜底

### P0-5: L2 知识来源不可追溯
- **证据**: 16 条规则知识绑定引用的源文件在生产服务器**全部缺失**（10 confirmed + 6 placeholder，生产可访问源文件 = 0）
- **影响**: 证据包可审计性、典籍引用纠错、发布包完整性、独立环境复现、知识版本升级全部受阻
- **完成标准**:
  1. 将典籍源文件作为发布资产部署，或改为 `sourceId + sourceSha256 + excerpt + edition`（运行时不依赖外层目录）
  2. 构建阶段生成最小可审计知识包
  3. 所有 `confirmed` 片段都有可验证来源、版本、hash
  4. 启动预检发现缺失时阻断证据包启用

## 8. 关键根因分析

### 8.1 为什么 Phase 4/5 完成后仍有多项卡点？
**根因**: Phase 3-5 + G4-7 是"工程闭环"，不是"生产闭环"。工程闭环只保证 tsc + jest + build 通过，不保证生产流量下行为符合预期。
**证据**: Phase 4 多轮对话无流量、Phase 5 成本看板 routeType 全部 unknown、P0 装甲命中 0 条规则。
**进化建议**: 在 DSPBRSE 七阶段中，"Build 完成"≠"Review 完成"。需在 Build 阶段末尾增加"预发灰度验证"环节，强制至少 5 次真实流量验证。

### 8.2 为什么文档治理反复成为遗留事项？
**根因**: 缺乏"文档分层前置"机制。当前流程是"先写文档，事后梳理分层"，导致每次都积压。
**进化建议**: 新建文档时强制头部声明 `**文档分层**: HANDOFF/EXECUTION/REFERENCE/ANALYSIS/RAW/LESSON`，并按分层放入对应子目录。

### 8.3 为什么 G6 v3 索引反复延期？
**根因**: v3 索引依赖外部 embedding 模型选型，被"先看 TF-IDF 效果"无限期推迟。
**进化建议**: 设定硬截止日期（部署后 7 天内必须选定），否则默认使用 BGE-M3 兜底。

### 8.4 为什么生产 Git 真相缺失？
**根因**: 历史部署采用"本地 push + SSH 手动部署"模式，生产服务器未配置 Git remote，直接 cp 文件导致工作区 dirty。
**进化建议**: 部署流程改为"生产 git pull + npm ci + npm run build"，或在部署后强制 `git add -A && git commit`。

### 8.5 为什么 P0 装甲命中 0 条规则？
**根因**: RuleMatcher 规则集（4 类 8 条）覆盖不足，与生产真实问题分布不匹配。
