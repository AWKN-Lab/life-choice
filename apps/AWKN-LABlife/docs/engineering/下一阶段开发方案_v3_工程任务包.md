### 任务 2：K线/潮汐图接入问事结果（第二优先级，项目差异化）

**目标**：让命运K线/潮汐图从"运势图表"升级为"人生状态仪表盘"，并进入问事结果。

**必须做**（沿用现有模块，不新建平行模块）：
1. 增强 `kline-tide.service.ts` / `kline-decision.service.ts`：新增 `getCurrentStage(input: KlineStageInput)` 返回 6 种状态（进攻/蓄势/回撤/修复/等待/突破）
2. 增强 `tide-inference.service.ts` / `tide-judgment.service.ts`：新增 `get12DimStatus(input: TideStatusInput)` 返回 12 维解释
3. `orchestrator.service.ts` 注入 K线/潮汐状态到 prompt（`prompt-layers.ts` 加 `lifeStage` 字段）
4. 前端结果页增加"此事所处状态窗口"卡片
5. 前端 KlinePage 节点增加"问此事"按钮 → 跳转 `/question` 携带预设问题

**输入参数类型定义**（不绑定单一 birthDate，支持问事 × K线融合）：

```typescript
interface KlineStageInput {
  userId?: string;
  profileId?: string;
  birthDate?: string;
  targetDate?: string;    // 目标月份/日期，默认当前
  questionType?: string;  // 问事类型，用于阶段聚焦
  recordId?: string;      // 关联问事记录，可选
}

interface TideStatusInput {
  userId?: string;
  profileId?: string;
  birthDate?: string;
  targetDate?: string;
  questionType?: string;
  recordId?: string;
}
```

**验收**：
- `/kline` 能显示当前阶段解释
- `/tide` 能显示 12 维状态解释
- 至少 3 条问事结果引用 K线/潮汐状态
- 至少 1 个 K线节点能触发问事
- 不破坏现有 `/question` 和 `/result/:recordId`

### 任务 3：单事深推支付闭环（第三优先级，商业化基础）

**目标**：用户可对当前这一件事支付 ¥1 深推，支付成功自动解锁 fullResult，并获得当前 recordId 下 3 次追问额度。

**必须做**（复用现有支付体系，四重条件识别 ¥1 深推）：
1. 复用 `PaymentModule` + `MembershipModule` + `Order` + `ConsultRecord.unlockStatus`
2. **短期继续用 `productType='single'`**，通过四重条件识别 ¥1 单事深推：
   - `metadata.deepDive='true'`
   - `amount=100`（**单位待确认**：执行前必须先读 `payment.service.ts` 中 Stripe checkout session 的 amount 字段单位。若 Stripe 用"分"则 ¥1 写 `amount=100`；若项目内部用"元"则 ¥1 写 `amount=1`。**不允许猜**）
   - `productId=recordId`
   - `metadata.recordId=recordId`
3. `UnlockModuleDto` 增加 `orderId?`
4. `unlockModule` 增加已支付订单校验分支（第 5 条分支）
5. Stripe webhook `checkout.session.completed` 主动解锁 `ConsultRecord.unlockStatus='unlocked_full'`（不依赖前端回调）
6. `analysisData.followupQuota += 3`
7. 前端关闭支付页也不能丢权益（webhook 兜底）

**验收**：
- 订单能创建（productType='single' + 四重条件）
- 支付成功后 `Order.status='paid'`
- webhook 自动写 `ConsultRecord.unlockStatus='unlocked_full'`
- 当前 recordId 获得 3 次追问额度
- 退款/失败可追踪
- 不依赖前端回调完成解锁
