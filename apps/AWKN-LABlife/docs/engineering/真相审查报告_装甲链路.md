## 6. EVIDENCE_PACKAGE_ENABLED 默认值与开启/关闭路径

### 6.1 默认值

| 来源 | 默认值 | 证据 |
|------|-------|------|
| `.env.example`（通过 TECHNICAL_DOCUMENTATION.md L1190 引用） | `EVIDENCE_PACKAGE_ENABLED=false` | 文档明确标注 |
| `zhangbanshan-scheduler.service.ts` L473 | 严格判 `=== 'true'` | 未设置 / false / 任意非 'true' 字符串 → 走旧路径 |
| 部署复盘文档 `_log.md` L89 | "未设置 = 默认 false（符合设计）" | 部署时确认 |
| 测试代码 `zhangbanshan-scheduler.evidence.spec.ts` L110 | `delete process.env.EVIDENCE_PACKAGE_ENABLED` 显式清理 | 测试隔离 |

**结论**：默认 `false`，需手动显式设置为 `'true'` 才会启用装甲链路。

### 6.2 开启 / 关闭时的两条路径

**开启（`EVIDENCE_PACKAGE_ENABLED=true`）走装甲链路**：
1. `ruleMatcherService.match(matchInput)` → 命中规则（chonghe/dayun/risk/shishen 4 类 8 条）
2. `safeLogAgentRun({ agentName: 'RuleMatcher' })` → 内存日志（P2-B 埋点 1）
3. `evidenceComposerService.compose({...})` → 打包 `EvidencePackage`（含 matchedRules + knowledgeFragments + chartSnapshot + ruleBasedScore）
4. `safeLogAgentRun({ agentName: 'EvidenceComposer' })` → 内存日志（P2-B 埋点 2）
5. `prompt-layers.formatEvidencePackage(pkg)` → 注入 prompt 的【命中规则】【知识片段】【用户描述】【规则化评估】段
6. LLM 调用
7. `safeLogAgentRun({ agentName: 'LlmProvider' })` → 内存日志（P2-B 埋点 3）

**关闭（默认 false / 未设置）走旧路径**：
1. 跳过 RuleMatcher / EvidenceComposer / AgentRun 三处埋点
2. `evidencePackage = undefined`
3. `prompt-layers` 中 `if (input.evidencePackage)` 条件不成立 → 不拼装 evidence 段
4. LLM 仅基于原 prompt + chartSnapshot 生成（与 P1-B 之前的行为完全一致）

**降级路径（运行时失败时）**：
- RuleMatcher 抛错 → catch → `evidencePackage = undefined` → 自动回退到旧路径
- EvidenceComposer 抛错 → 同上
- AgentRunLogger 抛错 → `safeLogAgentRun` 内部捕获 → 不阻断主链路（仅 WARN 日志）
