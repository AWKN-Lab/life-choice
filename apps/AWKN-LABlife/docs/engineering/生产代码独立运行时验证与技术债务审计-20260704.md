## 5. 生产真实日志发现

以下问题均来自当前生产轮转日志，属于真实用户链路证据。

### 5.1 五层输出校验失败

日志出现：

```text
5层输出校验失败：缺少 数术断句、半山落句、具体落点、下一步动作
```

影响：深度结果生成后仍被质量门拒绝，用户最终获得 L1 降级结果或失败记录。

### 5.2 显式八字请求被错误调度

请求已经传入：

```json
{
  "routeType": "ziping",
  "question": "我最近事业不太顺，想看看今年财运怎么样"
}
```

调度器日志却记录：

```text
no keyword match ... defaulting to liuyao
parallel generation: liuyao + qimen
```

影响：用户明确选择八字后，系统仍可能切换到六爻与奇门，入口契约被调度器覆盖。

### 5.3 ReAct 重复索取已有信息

请求已经包含出生日期、出生时间、性别，排盘也已经完成。ReAct 仍反复要求用户补充年龄、大运和出生信息。

影响：

- 增加模型调用次数与延迟。
- 用户感知为“系统没有记住刚填写的信息”。
- 多轮状态机无法稳定收敛。

### 5.4 三法融合类型错误

日志出现：

```text
ziweiAnalysis.slice is not a function
```

影响：三法融合降级，紫微结果没有稳定进入融合层。

### 5.5 紫微 Python CLI 导入失败

日志出现 Python traceback。随后链路又记录紫微同步排盘成功，失败与成功语义混在同一轮请求中。

影响：

- 运行状态难以判断。
- 回退引擎来源没有明确标记。
- 用户结果可能来自不同实现，审计日志无法快速区分。

### 5.6 知识检索超时降级

日志出现：

```text
hybrid_search failed: This operation was aborted, falling back to /retrieve
```

影响：v3 混合检索未稳定服务主链，知识召回质量会随降级路径波动。

### 5.7 Redis 关闭后的能力缺口

生产中 `REDIS_ENABLED=false`：

- 生成队列降级为同步直跑。
- Follow-up 仅写数据库，无法进入 BullMQ。
- 高峰期缺少排队、重试、削峰和任务追踪。

当前文档仍把 Redis/BullMQ 写成生产运行组件，需改为“已配置、当前关闭”。

### 5.8 LLM 结构化输出不稳定

日志出现：

- JSON 截断与解析失败。
- Schema 字段大面积缺失。
- 质量分低至 20。
- `finish=length`。
- 巴纳姆表达检测后降级模板。
- Ziping 总耗时约 177 秒。
- L2 超时 150 秒后回退 L1。

影响：深推质量、响应时间和输出完整性均未达到稳定生产标准。

### 5.9 ReAct JSON 解析失败

日志出现：

- `Unexpected end of JSON input`
- `Unterminated string in JSON`
- 解析失败后强制收敛

影响：ReAct 的思考、动作、观察和反思协议缺少稳定的结构化输出约束。

- Provider 级别配置足够的 `max_tokens`。

1. 将典籍源文件作为发布资产部署。

完成标准：所有 `confirmed` 片段都有可验证来源、版本和 hash；启动预检发现缺失时阻断证据包启用。

## 10. 建议的进化架构

### 10.1 不可变发布清单

每次构建生成：

```json
{
  "commit": "...",
  "sourceTreeHash": "...",
  "distHash": "...",
  "schemaHash": "...",
  "assetManifestHash": "...",
  "migrationHead": "...",
  "builtAt": "..."
}
```

健康接口增加 `releaseId`，生产日志、AgentRun 和咨询记录都携带同一个版本标识。

### 10.2 路由决策追踪

每次咨询记录：

- 用户显式 routeType。
- 分类器结果。
- 关键词结果。
- 最终 Agent。
- 覆盖原因。
- 灰度开关。

任何显式路由被覆盖时触发告警。

### 10.3 FactLedger

统一存放：

- 出生信息。
- 排盘结果。
- 大运流年。
- 用户现实背景。
- 已问问题。
- 已确认事实。
- 未知字段。

ReAct、澄清器、调度器和生成器只读取同一份事实对象。

### 10.4 结构化 LLM 适配层

每个 Provider 建立独立能力档案：

- JSON Schema 支持情况。
- 最大输出长度。
- 截断率。
- 解析成功率。
- 平均延迟。
- 质量门通过率。
- 模板降级率。

路由器依据真实指标选 Provider。

### 10.5 知识来源包

证据包中的每段典籍内容使用：

```text
sourceId + edition + excerpt + sha256 + locator + status
```

构建阶段校验全部 `confirmed` 来源，生产运行时只加载已经签名的最小知识包。

### 10.6 端到端可观测性

统一 `runId` 串联：

```text
HTTP 请求 → 排盘 → 路由 → 知识检索 → Agent → LLM → ReAct → 质量门 → 入库 → 回访
```

核心指标：

- 首字延迟。
- 总耗时。
- L1/L2 降级率。
- JSON 解析失败率。
- 五层输出通过率。
- 模板兜底率。
- 路由覆盖率。
- 知识检索超时率。
- 每次咨询成本。
