## 六、关键链路验证

### 链路 1：¥1 深推下单 → 支付 → 主动解锁（不依赖前端回调）

```
用户点击 ¥1 深推按钮
  → POST /payment/deep-dive/:recordId
    → createDeepDiveOrder(userId, recordId, 'stripe')
      → 校验 recordId 归属当前用户
      → 幂等性检查（同一 recordId 已有 paid 深推订单则返回 alreadyPaid=true）
      → createOrder(四重条件: productType='single' + amount=1 + productId=recordId + metadata.deepDive='true')
      → Stripe Checkout Session 创建（metadata 含 deepDive + recordId）
    ← 返回 { orderId, paymentUrl }
  → 前端跳转 window.location.href = paymentUrl
  → 用户在 Stripe 完成支付
  → Stripe webhook → POST /payment/webhook/stripe
    → handleStripeWebhook
      → order.update status='paid'
      → 识别 metadata.deepDive='true'
      → consultRecord.update unlockStatus='unlocked_full'  ← 主动解锁
      → consultRecord.findUnique 读取 analysisData
      → consultRecord.update 写入 deepDiveBonus=3 + deepDiveOrderId + deepDiveUnlockedAt
    ← 返回 { received: true }（不阻断）
  → 用户回到结果页，刷新即可看到完整结果 + 3 次追问额度
```

**关键保证**：即使用户关闭支付页或未点击"返回商家"，webhook 仍会主动解锁，权益不丢失。

### 链路 2：积分通道降级（订单未找到时）

```
unlockModule(userId, moduleId, recordId, orderId)
  → 分支1: 管理员 → 走积分路径
  → 分支2: 免费模块 → 直接放行
  → 分支3: 会员层级检查 → 有会员直接放行
  → 分支5: 深推订单校验（新增）
    → 订单已支付 → 直接解锁 unlocked_full，source='deep_dive'
    → 订单未找到 → 降级走分支4（积分通道）
  → 分支4: 积分通道 → 扣积分解锁
```

### 链路 3：追问额度提升

```
handleFollowup(recordId, question)
  → 读取 analysisData
  → deepDiveBonus = analysisData.deepDiveBonus || 0
  → effectiveMaxRounds = MAX_FOLLOWUP_ROUNDS(3) + deepDiveBonus(3) = 6
  → followupCount < 6 → 继续追问
  → followupCount >= 6 → 触达限额，返回 paywallTriggered=true
```
