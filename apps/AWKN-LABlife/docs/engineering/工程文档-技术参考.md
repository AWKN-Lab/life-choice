## 2. 核心模块说明

### 2.1 P0装甲就位（RuleMatcher + EvidenceComposer）

#### 2.1.1 RuleMatcher Lite

**位置**：`src/consult/orchestrator/rule-matcher/`

**功能**：从八字排盘结果中自动识别冲合刑害、十神格局、大运流年引动，输出结构化命中规则列表。

**输入**：
```typescript
interface RuleMatcherInput {
  chartSnapshot: {
    male: BaziFullResult;
    female?: BaziFullResult;
  };
  questionType: 'marriage_decision' | 'career_decision' | 'wealth_decision' | 'health_decision';
  userContext: {
    background: string;
    concerns: string[];
  };
}
```

**输出**：
```typescript
interface RuleMatcherOutput {
  matchedRules: MatchedRule[];
  summary: {
    totalRulesMatched: number;
    highSeverityCount: number;
    mediumSeverityCount: number;
    primaryConflict: string;
  };
}
```

**规则分类**：
- 冲合刑害（R001-R006）：子午冲、卯酉冲、夫妻宫冲等
- 十神格局（R007-R011）：伤官见官、财星引动、官杀混杂等
- 大运流年（R012-R015）：大运引动夫妻宫、流年合动、伏吟反吟等
- 风险决策（R016-R020）：共同负债、父母边界、价值观冲突等

**调用点**：`zhangbanshan-scheduler.service.ts` 第500行

**灰度开关**：`EVIDENCE_PACKAGE_ENABLED=true`

#### 2.1.2 EvidenceComposer Lite

**位置**：`src/consult/orchestrator/evidence-composer/`

**功能**：把排盘结果 + 命中规则 + 用户上下文合成结构化证据包。

**输入**：
```typescript
{
  chartSnapshot: RuleMatcherInput['chartSnapshot'];
  matchedRules: MatchedRule[];
  userContext: RuleMatcherInput['userContext'];
}
```

**输出**：
```typescript
interface EvidencePackage {
  meta: {...};
  userQuestion: string;
  chartSnapshot: {...};
  matchedRules: {
    high: MatchedRule[];
    medium: MatchedRule[];
    low: MatchedRule[];
  };
  knowledgeFragments: KnowledgeFragment[];
  userContext: {...};
  ruleBasedScore: {...};
}
```

**调用点**：`zhangbanshan-scheduler.service.ts` 第513行

#### 2.1.3 Prompt证据包改造

**位置**：`src/consult/orchestrator/prompt-layers.ts`

**功能**：LLM输入从"裸八字+裸问题"变成structured evidence package。

**关键代码**（第245-315行）：
```typescript
evidencePackage?: EvidencePackage;  // 输入参数
if (input.evidencePackage) {
  evidenceSection = formatEvidencePackage(input.evidencePackage);
}
const { matchedRules, knowledgeFragments, userContext, ruleBasedScore } = pkg;
// 使用matchedRules和knowledgeFragments生成提示词
```

**证据驱动约束**：
- 禁止"我推算出"
- 禁止自行识别规则
- 禁止凭空引古籍
- 每条结论对应matchedRules

## 7. 关键约束与注意事项

### 7.1 不可修改项

- **14段输出骨架**：已验证有效，不可修改
- **LLM模型配置**：deepseek-direct已达标，不可更换
- **SQLite单实例**：不支持水平扩展（PostgreSQL迁移延后）
- **Nginx路由**：路由配置不变
- **PM2 fork模式**：不支持cluster模式（SQLite约束）

### 7.2 必须遵守的规则

1. **所有中间件必须用async/await**，禁止callback风格
2. **路由文件在中间件重构时不可修改**
3. **TypeScript代码必须通过`npx tsc --noEmit`验证**
4. **积分扣减必须用乐观锁**：`where: { creditBalance: { gte: cost } }`
5. **免费试用检查必须用乐观锁**：`where: { id: userId, freeTrialUsed: false }`
6. **解锁操作必须包含幂等性检查**：使用`creditLedger`记录
7. **后端定价必须与前端一致**：`pricing.service.ts`与`i18n/membership.json`匹配
8. **数据库文件(*.db)必须排除版本控制**
9. **.env文件必须排除版本控制**
10. **Dockerfile必须包含Python环境+ sxtwl依赖**

### 7.3 部署后必做

1. **5件套验证**：`bash scripts/verify-deploy.sh`
2. **健康检查**：`curl /api/v1/health`
3. **PM2稳定性**：`pm2 describe | grep unstable`（必须为0）
4. **P0装甲激活**：`pm2 logs | grep evidence`（必须有日志）
5. **核心链路无降级**：发起1次问事，检查日志无降级错误
