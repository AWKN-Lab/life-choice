## 7. 问题分级

### P0 (阻断): 无

### P1 (高风险): 无

### P2 (中风险)

**P2-1: ZipingAgent TypeError**
- 现象: `TypeError: Cannot read properties of undefined (reading '0')` at ziping-agent.service.js:413
- 根因: `input.preCalculatedBazi.yearPillar` 为 undefined (六壬路由未构造完整八字数据)
- 影响: ZipingAgent 失败，但 LlmGateway 标记 failed=false，consistency=consistent，主链路未阻断
- 生产对比: 生产环境 ZipingAgent 是 LLM JSON 解析失败 (不同根因)，降级到模板
- 修复建议: 六壬路由调用 ZipingAgent 时，应检查 preCalculatedBazi 是否完整，不完整时跳过

**P2-2: npm run build 失败**
- 现象: 3 个 TypeScript 编译错误 (gpt-tokenizer, zod, symbol index)
- 根因: gpt-tokenizer/zod 在 apps/api-server/node_modules，根目录 build 找不到类型声明
- 影响: 无法 fresh build，只能从生产复制 dist
- 修复建议: 将 gpt-tokenizer, zod 添加到根目录 package.json，或改用 apps/api-server 目录 build

### P3 (低风险)

**P3-1: KnowledgeRetriever hybrid_search 失败**
- 现象: `hybrid_search failed: This operation was aborted`
- 影响: 降级到 /retrieve，非阻断
- 可能原因: 向量检索超时或资源不足

**P3-2: MemoryExtractor JSON 解析失败**
- 现象: `LLM extract failed: Unexpected end of JSON input`
- 影响: 记忆提取失败，非阻断
- 可能原因: LLM 返回的 JSON 不完整

**P3-3: Redis 未启用**
- 现象: REDIS_ENABLED=false, BullMQ 队列跳过
- 影响: 走同步降级模式，deep_consult 在 HTTP 线程同步执行
- 注意: 生产环境可能也是此配置 (需确认)

## 9. 关键根因分析

### 9.1 evidencePackage 仅支持八字场景

**代码位置**: orchestrator.service.ts L454-463
```typescript
if (cd && cd.yearPillar && cd.xingChongHeHai) {
  chartSnapshot = { male: cd as any };
}
```
chartSnapshot 构造依赖八字专有字段 (yearPillar, xingChongHeHai)。六壬/六爻/奇门等路由的 calcData 不含这些字段，导致 chartSnapshot=undefined，evidencePackage 未注入。

**影响范围**: 所有非八字路由的 deep_consult 都不会注入 evidencePackage。

### 9.2 ZipingAgent 作为 secondary agent 时数据缺失

六壬路由 (primary=liuren) 调度 ZipingAgent 作为 secondary。但 orchestrator 未为 ZipingAgent 构造完整的 preCalculatedBazi (八字排盘数据)，导致 `bazi.yearPillar[0]` 报错。

### 9.3 build 与运行时 node_modules 路径不一致

gpt-tokenizer, zod 在 apps/api-server/node_modules，运行时 Node.js 能找到，但根目录 TypeScript 编译找不到类型声明。
