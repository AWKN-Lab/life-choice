## 1. 系统概述

### 1.1 系统定位

知识服务（knowledge-service）是人生决策宗师的核心检索组件，为命理咨询主链提供术数典籍检索能力。

**在主咨询链中的位置**：
```
用户提问 → 后端 orchestrator → 路由分发 → 知识服务（本系统）→ 检索 passages → LLM 引用 → 五层输出
                                       ↓
                                  紫微/八字/六壬等 Agent
```

### 1.2 当前规模

| 指标 | 值 | 来源 |
|---|---|---|
| 书籍数 | 1,126 本 | `_manifest.json` books 字段 |
| passages 总数 | 357,359 条 | `_manifest.json` count 字段 |
| 分类数 | 13 个 | `_manifest.json` categories 字段 |
| 向量维度 | 1,024 维（v2 TF-IDF） | `embeddings.npy` shape[1] |
| 向量库大小 | 1.46 GB | `embeddings.npy` 文件大小 |
| 索引文件大小 | 267 MB | `classics_index.jsonl` 文件大小 |
| FTS5 索引大小 | 380 MB | `passages_fts.db` 文件大小 |

## 3. 核心模块说明

### 3.1 loader.py（数据加载）

**职责**：从 `knowledge/processed/classics_index.jsonl` 加载全量 passages，按 `system_type` 分组。

**关键设计**：
- 路径解析：优先 `KNOWLEDGE_DATA_DIR` 环境变量，默认 `<project_root>/knowledge/processed/`
- text 截断：加载时 `text[:500]`，减少内存占用
- manifest 兼容：`manifest.get('total_books', manifest.get('books', 0))` 兼容新旧字段名
- 旧接口兼容：`result['bazi'] = by_system.get('bazi', [])` 保留顶层键

**输出结构**：
```python
{
    'items': List[Dict],          # 全量 passage（text 截断到 500 字）
    'by_system': Dict[str, List], # 按 system_type 分组
    'sources': {'total': int, 'books': int},
    'manifest': Dict,             # _manifest.json 原始内容
    'bazi': List,                 # 兼容旧接口
    'liuren': List,               # 兼容旧接口
}
```

### 3.2 main.py（4 个接口 + 检索逻辑）

**职责**：提供 4 个 HTTP 接口 + 关键词搜索 + 向量搜索 + 混合搜索。

**关键设计**：
- ChromaDB 绕过：因 ChromaDB 0.5.5 与 pydantic v1 不兼容，改用纯 numpy 内存向量检索
- numpy 兼容：Monkey-patch `np.float_` / `np.int_` / `np.uint`（numpy 2.0 移除）
- mmap 模式：`KNOWLEDGE_USE_MMAP=1` 时用 `np.load(mmap_mode='r')`，按需从磁盘读取
- 范数预计算：`_emb_norms` 全局变量，避免每次查询重算（mmap 模式分批计算）
- IDF 缓存：优先加载 `idf_cache.pkl`，不存在时 fit 并保存

**检索算法**：
- `keyword_match()`：基于关键词命中数 + 标签加分，归一化到 [0, 1]
- `_vector_search()`：TF-IDF 编码查询 → numpy cosine 相似度 → Top-K
- `hybrid_search()`：向量 Top-K ∪ 关键词 Top-K → 重排去重（vec_score * 0.7 + kw_score * 0.3）

### 3.3 knowledge_ingest.py（采集 + 切分 + 分类）

**职责**：从原始 .md 文件采集 passages，切分（≤400 字），分类（13 体系），写 jsonl。

**分类规则**（13 体系）：
| 分类 | 判定关键词 | 说明 |
|---|---|---|
| bazi | 八字 / 子平 / 四柱 / 三命 / 渊海 / 神峰 | 含 ziping 别名 |
| ziwei | 紫微 / 斗数 / 太微 | **已修复：不再误归 bazi** |
| qimen | 奇门 / 遁甲 | - |
| liuren | 六壬 / 大六壬 | - |
| liuyao | 六爻 / 周易预测 / 断卦 | - |
| meihua | 梅花易数 / 邵雍 | - |
| zhouyi | 周易 / 易经 / 卦象 / 爻辞 | - |
| fengshui | 风水 / 峦头 / 理气 / 玄空 | - |
| quming | 取名 / 起名 / 命名 / 康熙字典 | - |
| xiangshu | 相术 / 面相 / 手相 / 麻衣 | - |
| daoism | 道教 / 道德经 / 道家 | - |

**切分规则**：
- 硬切 400 字/passage（不再单 passage 60 万字）
- 支持 dict 根节点（不再只处理 list）

### 3.4 embed_classics.py（TF-IDF Embedder）

**职责**：实现 `TfidfCharBigramEmbedder`，生成 embeddings.npy。

**关键设计**：
- 算法：TF-IDF char-bigram（字符级 2-gram）
- 维度：1024 维
- IDF 缓存：`save_idf()` / `load_idf()` 持久化到 `idf_cache.pkl`
- 编码：`encode_one(query)` 单条查询编码

### 3.5 verify_knowledge_service.py（断言验证）

**职责**：5 项断言验证服务可用性。

**5 项断言**：
1. `/health` 返回 bookCount > 0
2. `/retrieve` routeType=bazi 返回 items 非空
3. `/embed_search` 返回 items 非空
4. `/hybrid_search` 返回 items 非空
5. 紫微分类正确（routeType=ziwei 不含八字书）

**通过条件**：全部 assert 通过 → `sys.exit(0)`；任一失败 → `sys.exit(1)`

## 4. 数据流说明

### 4.1 完整数据流

```
原始 .md 文件（knowledge/raw/）
    │
    ▼ knowledge_ingest.py
    │  ├─ 采集：遍历 .md 文件
    │  ├─ 切分：硬切 400 字/passage
    │  ├─ 分类：13 体系（detect_system_type）
    │  └─ 写出：classics_index.jsonl（每行 1 passage JSON）
    │
    ▼ embed_classics.py
    │  ├─ 加载：classics_index.jsonl
    │  ├─ fit：TfidfCharBigramEmbedder.fit(texts)
    │  ├─ 编码：embeddings = embedder.encode_batch(texts)
    │  ├─ 保存：embeddings.npy + idf_cache.pkl
    │  └─ 生成：_manifest.json（count/books/categories）
    │
    ▼ loader.py（启动时）
    │  ├─ 加载：classics_index.jsonl → items[]
    │  ├─ 分组：by_system dict
    │  └─ 加载：_manifest.json
    │
    ▼ main.py（运行时）
    │  ├─ /health：返回 manifest + items 统计
    │  ├─ /retrieve：keyword_match → by_system 过滤 → Top-K
    │  ├─ /embed_search：TF-IDF encode → numpy cosine → Top-K
    │  └─ /hybrid_search：向量 ∪ 关键词 → 重排去重
    │
    ▼ 后端 API 调用
       └─ LLM 引用 passages 生成五层输出
```

## 7. 检索能力说明

### 7.1 v2 当前能力

| 能力 | 算法 | 性能 | 质量 |
|---|---|---|---|
| 关键词检索 | `keyword_match()` | P95 ≤ 1s | 召回低，精确高 |
| 向量检索 | TF-IDF char-bigram + numpy cosine | P95 ≤ 1s | avg_p@10 = 0.917 |
| 混合检索 | 向量 ∪ 关键词 → 重排 | P95 ≤ 1s | 综合最优 |

**v2 评估结果**（`g6_0_evaluation.jsonl`）：
- avg_precision_at_10 = 0.917
- avg_mrr = 1.0
- pass_count = 11/12
- verdict = PASS（阈值 0.6）

### 7.2 v3 目标能力

| 能力 | 算法 | 目标 | 当前状态 |
|---|---|---|---|
| 语义向量 | BGE-large-zh-v1.5（1024 维） | avg_p@10 ≥ 0.95 | ❌ 未部署 |
| 语义向量 | BGE-small-zh-v1.5（512 维） | 评估 | 🟡 V3_PARITY |
| FTS5 混合 | FTS5 + v2 双路 | avg_p@10 ≥ 0.95 | 🟡 仅评估 |

**v3 评估结果**（`l8_v3_sampled_evaluation.jsonl`）：
- 模型：bge-small-zh-v1.5（512 维）**注：非计划的 bge-large**
- 采样：25,177 条（13 分类 × 2000/类）
- v3_sampled_avg_p@10 = 0.858
- v2_sampled_avg_p@10 = 0.817
- delta = +0.042（不显著）
- verdict = V3_PARITY（暂不替代 v2）

### 7.3 v2 → v3 旁路切换机制（G7/L9，未实施）

**计划机制**：
1. 环境变量 `KNOWLEDGE_INDEX_VERSION=v2`（当前）/ `v3`（切换后）
2. loader 根据 `KNOWLEDGE_INDEX_VERSION` 加载 `embeddings.npy` 或 `embeddings_v3.npy`
3. embed_classics 根据 `KNOWLEDGE_INDEX_VERSION` 选择 `TfidfCharBigramEmbedder` 或 `BGEEmbedder`
4. 灰度 24h 无回滚后正式切换

### 8.3 常见故障 5 类

| # | 故障 | 症状 | 排查方法 |
|---|---|---|---|
| 1 | loader 路径错 | `/health` bookCount=0 | 检查 `KNOWLEDGE_DATA_DIR` + `ls knowledge/processed/` |
