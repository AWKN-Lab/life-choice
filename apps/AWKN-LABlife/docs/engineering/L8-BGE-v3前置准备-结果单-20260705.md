# L8 前置准备结果单（BGE v3 vs TF-IDF v2 评估）

**日期**: 2026-07-05
**版本**: v1.0
**结论**: V3_PARITY（v3 与 v2 持平，略微优于 v2，但收益不显著）
**决策**: 暂不替代 v2，等服务器扩容后用 bge-large-zh-v1.5（1024维）全量评估

## 一、执行摘要

L8 目标：评估 BGE 语义 embedding（v3）是否优于当前 TF-IDF 字符级 Bigram（v2），作为下一版生产 embedding 候选。

原计划：下载 bge-large-zh-v1.5（1024维）全量编码 357359 条 passages，对比 v2 基线。

实际执行：
- **L8-a 降级**：本地沙箱无法访问 huggingface.co / hf-mirror.com / modelscope.cn / github.com（全部连接被拒绝），降级使用本地已有的 bge-small-zh-v1.5（512维）
- **L8-b 完成**：编写 embed_classics_v3.py（支持 memmap + 断点续传）
- **L8-c 调整**：全量编码 357359 条需 5+ 小时（CPU 21 passages/s），且 8000 条时内存崩溃。改为分层采样 25177 条（13分类每类 2000）
- **L8-d 完成**：在 25177 条相同样本上对比 v2 和 v3
- **L8-e 决策**：V3_PARITY，暂不替代 v2

## 二、L8-a 模型下载（降级 Plan B）

### 2.1 原计划
- 模型：BAAI/bge-large-zh-v1.5
- 维度：1024
- 大小：~1.3GB

### 2.2 实际执行
- 尝试 huggingface.co → `URLError [WinError 10061] 由于目标计算机积极拒绝`
- 尝试 hf-mirror.com → 同样拒绝
- 尝试 modelscope.cn → 同样拒绝
- 尝试 github.com / raw.githubusercontent.com → 同样拒绝
- **结论**：本地沙箱完全无法访问外部网络

### 2.3 降级方案
- 使用本地 HF cache 已有的 BAAI/bge-small-zh-v1.5
- 维度：512
- 加载耗时：30-45 秒
- 编码速度：CPU 21 passages/s（batch_size=64）

### 2.4 降级影响
- 维度从 1024 → 512，与 v2（1024）不兼容，无法直接替换
- 模型从 large → small，语义能力可能减弱
- 但仍是真实 BGE 语义模型，评估结果有参考价值

### 5.3 关键发现

1. **v3 在语义模糊查询上明显优于 v2**：
   - fengshui「风水峦头理气」: v3=0.6 vs v2=0.3 (+0.3) — BGE 能检索到「葬经」「神相铁关刀」中语义相关但关键词不完全匹配的内容
   - liuren「六壬天将贵人」: v3=1.0 vs v2=0.7 (+0.3)
   - ziwei「紫微斗数十四主星性格」: v3=0.9 vs v2=0.7 (+0.2)

2. **v3 更稳定**：pass 12/12，v2(采样) pass 10/12

3. **v3 唯一劣于 v2 的查询**：
   - liuyao「六爻断卦用神原神忌神」: v3=0.9 vs v2=1.0 (-0.1) — TF-IDF 对精确关键词匹配更强

4. **采样 vs 全量差异**：
   - v2(采样) avg_p@10=0.817 < v2(全量) avg_p@10=0.917
   - 采样评估偏低（样本小，部分相关结果未在采样中）
   - 但 v3 与 v2 在相同样本上对比，结论仍有效

## 六、L8-e 决策点

### 6.1 决策选项

| 选项 | 描述 | 优缺点 |
|------|------|--------|
| A | 放弃 v3，保留 v2，等服务器扩容后试 bge-large-zh-v1.5（1024维） | ✅ 维度兼容 ✅ large 模型更强 ❌ 需等扩容 |
| B | 用 v3-small（512维）替代 v2 | ✅ 语义模型更通用 ❌ 收益不明显 ❌ 需改服务端 loader ❌ 维度不兼容 |
| C | 暂不替代，等服务器扩容后用 bge-large-zh-v1.5 全量评估 | ✅ 最稳妥 ✅ 维度兼容 ✅ 保留 v2 生产稳定 |

### 6.2 决策结论：**选项 C**

**理由**：
1. v3-small（512维）与 v2（1024维）持平（delta=+0.042），收益不明显
2. 替换 v2 需修改服务端 loader.py 和检索逻辑，工作量大，收益小
3. bge-large-zh-v1.5（1024维）维度与 v2 兼容，且 large 模型语义能力更强，预计会有更明显提升
4. 服务器当前资源不足（2.9GB磁盘/483MB内存），无法部署 BGE 模型，需等扩容
