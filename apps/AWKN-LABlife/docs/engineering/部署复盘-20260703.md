## 二、本次发现的问题

### 问题1：Git remote URL 协议不一致

| 项 | 旧值 | 新值 |
|----|------|------|
| fetch URL | `ssh://git@ssh.github.com:443/AWKN-Lab/Mr.Mont.git` | ✅ 已正确 |
| push URL | `https://ghp_xxx@github.com/xiaxingxiaowei1983/Mr.Mont.git` | ⚠️ 个人token+旧账号 |
| push 机制 | 靠GitHub自动重定向到AWKN-Lab | ❌ 不稳定 |

**修复**：统一push URL为SSH协议
```bash
git remote set-url --push origin ssh://git@ssh.github.com:443/AWKN-Lab/Mr.Mont.git
```

**验证**：`ssh -T git@ssh.github.com -p 443` → `Hi AWKN-Lab! You've successfully authenticated`

### 问题2：服务器备份策略与用户期望不符

| 项 | 旧做法 | 新做法（用户要求） |
|----|--------|-------------------|
| 回滚基线 | 服务器cp -r全量备份 + Git commit | **仅Git commit作为回滚基线** |
| 服务器临时回滚 | dist.old + dist.bak-TS累积 | **仅保留dist.old做即时回滚** |
| 历史备份 | 服务器保留多个.bak-TS | **不在服务器累积历史备份** |

**用户原话**：`你不要在服务器上备份`

**调整**：服务器上只保留1份`dist.old`用于"刚部署就发现问题"的秒级回滚，历史回滚一律通过`git reset`回到指定commit后重新部署。

### 问题3：project-天火Life.md 部署参数过期

| 项 | 文档值 | 实际值 |
|----|--------|--------|
| 前端目录 | `/www/wwwroot/awkn-lab/life/` | `/www/wwwroot/awkn.cn/life/` |
| 后端端口 | `3002` | `30000` |
| API路由 | `/life/api/` → `127.0.0.1:3002` | `/life/api/` → `127.0.0.1:30000` |
| 备份策略 | cp -r + .bak-TS累积 | Git基线 + dist.old即时回滚 |

### 问题4：Deploy Key vs Actions Secret 概念混淆

| 项 | 类型 | 用途 | 当前状态 |
|----|------|------|---------|
| `mont`（SHA256指纹） | Deploy Key | SSH push认证 | Read/write，从未使用 |
| Actions Secret | 环境变量 | GitHub Actions自动化 | 当前流程不需要 |

**结论**：当前部署流程（本地push + SSH手动部署）不需要Actions Secret，Deploy Key足够。需要Actions Secret的唯一场景：未来启用GitHub Actions自动部署到服务器。

## 三、根因分析

### 根因1：Git remote 配置漂移
- **现象**：fetch和push协议不一致
- **根因**：早期为绕过SSH认证问题临时使用HTTPS+token，后续未清理
- **教训**：临时方案必须及时清理，否则会变成永久技术债

### 根因2：备份策略未对齐用户偏好
- **现象**：在服务器做cp -r全量备份
- **根因**：部署技能默认E-A10规则要求"部署前必须备份"，但未区分"服务器备份"和"Git基线备份"
- **教训**：备份策略应该优先Git版本管理，服务器只保留即时回滚用的dist.old

### 根因3：项目部署参数文档未同步
- **现象**：project-天火Life.md端口和目录过期
- **根因**：上一轮部署时端口从3002迁移到30000，目录从awkn-lab/迁移到awkn.cn/，但未回写技能文档
- **教训**：部署参数变更后必须立即回写project-*.md，否则下次部署会凭过期文档出错

## 四、新增经验条目（待写入experience-entries.md）

### E-A23：Git remote URL 协议统一（SSH优先）
- fetch和push URL必须统一协议和账号
- SSH优先于HTTPS+token（不依赖token过期）
- 禁止靠GitHub自动重定向作为长期方案

### E-A24：服务器备份策略调整（Git基线+dist.old）
- 回滚基线：Git commit（不是服务器cp -r）
- 服务器只保留1份dist.old做即时回滚
- 历史回滚：git reset → 重新部署
- 禁止在服务器累积.bak-TS历史备份

### E-A25：Deploy Key vs Actions Secret 区分
- Deploy Key：SSH push认证（当前流程足够）
- Actions Secret：GitHub Actions自动化（当前不需要）
- 概念混淆会导致误设secret或误删Deploy Key
