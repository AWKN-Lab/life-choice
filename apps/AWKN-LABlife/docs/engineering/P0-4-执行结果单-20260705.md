## 三、核心改动详解

### 3.1 LlmResponse + finishReason
```typescript
export interface LlmResponse {
  // ... existing fields
  // P0-4: 截断检测信号（向后兼容）
  // 取值: 'stop' | 'length' | 'content_filter' | 'tool_calls' | null
  finishReason?: string | null;
}
```

### 3.2 chat() 读取 finish_reason
- 非流式 chat() 现在从 `choices[0].finish_reason` 读取
- 流式 chatStream 原有逻辑保持不变（已实现）

### 3.3 maxTokens 提升
| 位置 | 原值 | 新值 |
|------|------|------|
| `generation-composer.service.ts` L134 | 1200 | 3000 |
| `generation-composer.service.ts` L170（重试） | 1200 | 3000 |
| 截断重试（新增） | — | 4000 |

### 3.4 截断检测 + 重试
```typescript
if (result.finishReason === 'length') {
  // 自动重试一次，用 4000 tokens
  const truncationRetry = await this.llmProviders.chatWithFallback(messages, {
    maxTokens: 4000,
    temperature: 0.7,
  });
  if (truncationRetry.finishReason !== 'length') {
    rawOutput = truncationRetry.content;
  }
}
```

**关键防护**：
- 重试仍截断：继续用原始输出，不阻断
- 重试异常：catch 后继续走质量门，不阻断

### 3.5 LayerRepairService 设计

**核心策略**：
1. 仅修复缺失 1-2 层（>2 层走原有兜底，避免浪费）
2. 单层针对性补全（每次补 1 层更稳定）
3. 用 `temperature=0.3` 保证风格稳定
4. 失败兜底：返回 existingLayers（不抛错）

**调用入口**：
```typescript
await layerRepair.repairMissingLayers(
  missingLayers,        // ['clause', 'nextAction']
  existingLayers,       // 已解析出的 Partial<FiveLayerOutput>
  question,             // 用户问题（用于构造 prompt）
)
```

### 3.6 质量门行为变更（向后兼容）

**老调用方（Throw 版）**：`evaluateFiveLayersStrict()` — 保留 P1-3 行为不变
**新调用方（修复版）**：`evaluateFiveLayers()` — 返回 repairable + missingLayers

**调用约定迁移**：
```typescript
// 老（P1-3）：evaluateFiveLayers 抛错 → catch 后走兜底
// 新（P0-4）：evaluateFiveLayers 返回 missingLayers → orchestrator 调修复器
```
