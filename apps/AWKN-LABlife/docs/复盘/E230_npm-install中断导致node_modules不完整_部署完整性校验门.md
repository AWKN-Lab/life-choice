# E230：npm install 中断导致 node_modules 不完整 → 部署完整性校验门

## 一句话

**npm install 执行失败时仅留下 package-lock.json 和部分 node_modules，不报错但运行时崩溃**。部署完整性校验门必须验证"声明的依赖 = 实际可加载的依赖"。

---

## A. 触发场景

### A.1 时间

- 2026-06-27 17:00-17:20（人生决策宗师 P1-B+P2-B 部署）

### A.2 现象

```
PM2 awkn-life-backend 启动崩溃
→ Error: Cannot find module 'gpt-tokenizer'
→ at token-counter.service.js:11
→ code: 'MODULE_NOT_FOUND'
→ restarts=293（持续崩溃-重启循环）
```

### A.3 根因（5 Why）

1. **Why 1** — 为什么崩溃？
   → token-counter.service.js require gpt-tokenizer MODULE_NOT_FOUND

2. **Why 2** — 为什么服务器缺包？
   → node_modules 不完整，缺 gpt-tokenizer 及其 97 个传递依赖

3. **Why 3** — 为什么 node_modules 不完整？
   → 之前 `npm install --legacy-peer-deps` 因 prisma generate 权限问题中途退出

4. **Why 4** — 为什么 prisma generate 失败？
   → `node_modules/.bin/prisma` 没有可执行权限（Permission denied）

5. **Why 5** — 为什么 prisma 不可执行？
   → 部署脚本 `deploy.sh` 未包含 `chmod +x node_modules/.bin/*` 步骤

### A.4 关键发现（事后复盘）

```bash
$ cat apps/api-server/package.json | grep gpt-tokenizer
"gpt-tokenizer": "^2.5.0",   # 声明存在

$ ls apps/api-server/node_modules/gpt-tokenizer
ls: cannot access 'node_modules/gpt-tokenizer': No such file or directory  # 实际缺失
```

**声明存在 ≠ 实际可加载** — 这是 npm install 中断场景的典型陷阱。

---

## B. 完整链路时序

```
本地（Windows）
  ↓ tar -czf 上传代码
  ↓ (含 package.json + package-lock.json + node_modules 缺失)
服务器（Linux）
  ↓ npm install --legacy-peer-deps
  ↓ ... prisma generate → Permission denied → 中断
  ↓ 部分 node_modules 写入
  ↓ （无报错退出码，部分包已写入）
  ↓ npm run build → tsc 通过（dist 生成）
  ↓ pm2 restart → Node.js 启动 → require('gpt-tokenizer') → MODULE_NOT_FOUND
  ↓ PM2 持续重启 → restarts=293
```

---

## C. 反模式 vs 正模式

### 反模式 ❌

1. ❌ **只验证 package.json 声明就认为依赖已就绪**
   ```bash
   test -f package.json && echo "deps OK"  # 错误
   ```

2. ❌ **npm install 退出码为 0 就认为成功**
   - 部分包已安装 → 部分 require 失败 → Node.js 运行时才发现
   - npm 不会"回滚"已写入的 node_modules

3. ❌ **部署脚本只关注 `npm install` 不关注 `prisma generate` 等可执行权限**

4. ❌ **首次崩溃后只补单包，不排查 node_modules 全量完整性**

### 正模式 ✅

1. ✅ **部署完整性校验门**（建议加入 deploy.sh）：
   ```bash
   # 校验 node_modules 完整性
   cd $PROJECT_DIR/apps/api-server
   node -e "
     const fs = require('fs');
     const pkg = require('./package.json');
     const deps = {...pkg.dependencies, ...pkg.devDependencies};
     let missing = [];
     for (const [name] of Object.entries(deps)) {
       const p = './node_modules/' + name + '/package.json';
       if (!fs.existsSync(p)) missing.push(name);
     }
     if (missing.length > 0) {
       console.error('❌ Missing node_modules:', missing);
       process.exit(1);
     }
     console.log('✅ All', Object.keys(deps).length, 'deps present');
   "
   ```

2. ✅ **强制 chmod 可执行位**（npm install 后）：
   ```bash
   chmod +x node_modules/.bin/* 2>/dev/null || true
   find node_modules -name '*.sh' -exec chmod +x {} \;
   ```

3. ✅ **Node.js 模块可加载性预检**（preflight-check.js 增强）：
   ```bash
   node -e "
     const pkg = require('./package.json');
     for (const [name] of Object.entries({...pkg.dependencies, ...pkg.devDependencies})) {
       try { require.resolve(name); } catch { throw new Error('Cannot resolve: ' + name); }
     }
   "
   ```

4. ✅ **PM2 启动失败判定**：
   - restarts > 5 且 status != online → 自动触发回滚

## D. 解决方案对比

| 方案 | 操作 | 耗时 | 适用场景 |
|------|------|------|----------|
| A | `npm install --legacy-peer-deps` 重装全部 | 3-5 min | 已知大量缺失 |
| B | 单包 `npm install gpt-tokenizer@^2.5.0 --legacy-peer-deps` | 30-60s | 已知 1 个缺失，但会自动补齐传递依赖 |
| C | 删除 node_modules 重装 | 5-10 min | 极端情况（npm cache 损坏） |
| D | 回滚到 backup point | 1-2 min | 紧急止损 |

**本次采用 B 方案**：单包安装自动补齐了 98 个依赖（npm 自动解析 package.json 找到所有声明依赖）。

## E. 实施建议（部署脚本升级）

### E.1 修改 deploy.sh

```bash
# 在 npm install 之后、pm2 restart 之前增加：
echo "[deploy] chmod node_modules/.bin/*"
chmod +x node_modules/.bin/* 2>/dev/null || true

echo "[deploy] verify node_modules integrity"
node -e "
  const fs = require('fs');
  const path = require('path');
  const pkg = require('./package.json');
  const all = {...pkg.dependencies, ...pkg.devDependencies};
  const missing = Object.keys(all).filter(name =>
    !fs.existsSync(path.join('./node_modules', name, 'package.json'))
  );
  if (missing.length) {
    console.error('❌ Missing:', missing.join(', '));
    process.exit(1);
  }
  console.log('✅ All', Object.keys(all).length, 'deps OK');
" || { echo "[deploy] FAILED: node_modules incomplete"; exit 1; }

echo "[deploy] preflight module resolvability"
node -e "
  const pkg = require('./package.json');
  for (const name of Object.keys({...pkg.dependencies, ...pkg.devDependencies})) {
    try { require.resolve(name); } catch (e) { throw new Error(name + ': ' + e.message); }
  }
" || { echo "[deploy] FAILED: module resolve"; exit 1; }
```

### E.2 修改 preflight-check.js

在现有 assets-manifest 检查后增加：
```javascript
// 验证关键模块可加载
const criticalModules = ['gpt-tokenizer', 'openai', '@nestjs/core', 'prisma'];
for (const mod of criticalModules) {
  try {
    require.resolve(mod);
  } catch (e) {
    throw new Error(`[preflight] CRITICAL: module '${mod}' not resolvable`);
  }
}
console.log('[preflight] OK all critical modules resolvable');
```

## G. 验收标准（升级版）

部署流水线新增 4 个门禁：

1. **G1 chmod 门**: `node_modules/.bin/*` 可执行
2. **G2 文件存在门**: 所有声明依赖的 `node_modules/<name>/package.json` 存在
3. **G3 解析门**: 所有声明依赖 `require.resolve()` 成功
4. **G4 加载门**: dist 启动后 `pm2 status = online` 且 `unstable_restarts = 0`

任一失败 → 阻断部署 + 触发回滚。

## J. 元反思

- 本次恢复仅耗时 1 分钟（npm 单包 + PM2 restart），但代价是服务 down ~20 分钟
- 教训：部署完整性校验门应在 deploy.sh 内置，而不是事后补救
- 如果再部署一次：先 chmod → 再 npm install → 再 node -e require.resolve 检查 → 最后 pm2 restart
