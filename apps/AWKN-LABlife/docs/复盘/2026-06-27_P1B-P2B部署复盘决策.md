## 候选方案

### 方案 A：单包 npm install + PM2 restart（采纳）

**操作**：
```bash
npm install gpt-tokenizer@^2.5.0 --legacy-peer-deps --no-audit --no-fund
pm2 restart ecosystem.config.js --env production
```

**优点**：
- 耗时最短（37s + 30s = ~1 min）
- 最小变更（不动其他已正确的包）
- npm 自动解析依赖补齐 98 个传递依赖
- 不引入新版本

**缺点**：
- 未从根本上修复 deploy.sh 缺 chmod 的问题（下次还会触发）

### 方案 B：删除 node_modules 完整重装

**操作**：
```bash
rm -rf node_modules
npm install --legacy-peer-deps
pm2 restart
```

**优点**：
- 干净状态，无残留
- 强制重装所有依赖

**缺点**：
- 耗时 5-10 分钟（业务 down 时间长）
- 引入 lockfile 漂移风险
- 占用大量磁盘 I/O

### 方案 C：回滚到备份点

**操作**：
```bash
bash /opt/awkn-life/scripts/rollback.sh
```

**优点**：
- 1-2 min 恢复
- 100% 稳定（恢复到已知良好的状态）

**缺点**：
- 失去 P1-B+P2-B 代码（业务倒退）
- 不解决根因

## 决策

**采纳方案 A**，理由：

1. **已知缺失模块**：pm2 logs 已明确指向 gpt-tokenizer
2. **本地 package.json 完整**：声明 98 个依赖都存在
3. **最小化变更**：不动其他已正确的依赖
4. **修复成本低**：1 分钟 vs 方案 B 的 5-10 分钟 vs 方案 C 的 1-2 分钟 + 业务倒退
5. **后续永久修复**：升级 deploy.sh（E230），下次部署不再触发

## 永久修复（写入 deploy.sh）

### F1 chmod 门（E230）

```bash
# 在 npm install 之后、pm2 restart 之前
chmod +x node_modules/.bin/* 2>/dev/null || true
find node_modules -name '*.sh' -exec chmod +x {} \;
```

### F2 完整性校验门（E230）

```bash
node -e "
  const fs = require('fs');
  const pkg = require('./package.json');
  const all = {...pkg.dependencies, ...pkg.devDependencies};
  const missing = Object.keys(all).filter(name =>
    !fs.existsSync('./node_modules/' + name + '/package.json')
  );
  if (missing.length) { console.error('Missing:', missing); process.exit(1); }
"
```

### F3 verify-deploy.sh 集成（E232）

```bash
# 在 pm2 restart 之后
bash scripts/verify-deploy.sh || {
  echo "DEPLOY FAILED, rolling back"
  bash scripts/rollback.sh
  exit 1
}
```

## 元反思

1. **部署脚本设计阶段未考虑跨平台复制场景**：本地编译 + 服务器 npm install 模式天然有完整性风险
2. **PM2 unstable_restarts 是最关键的静默崩溃信号**：必须监控
3. **单包 npm install 是 npm 的"黑科技"**：很多人不知道
4. **5 件套验证应在 deploy.sh 末尾自动执行**，而不是人工
