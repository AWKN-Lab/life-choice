# PRD：P1-B+P2-B（主链路 evidencePackage 接入 + AgentRun 埋点）

> 版本：v0.1（已上线）
> 上线日期：2026-06-27
> 上线结果：✅ PASS（部署后 5 件套验证全通过 + unstable_restarts=0）

---

## 一、一句话定位

> **面向张班珊主调度链路，在主链路全场景接入 evidencePackage 结构化输入，注入 AgentRun 埋点实现可观测性，让 LLM 调用具备"规则前置 + 知识检索 + 失败降级"的可观测能力。**

合成句式：
> 面向【张班珊调度器】，在【主链路 synthesizeThreeStage 阶段】，解决【LLM 输入无结构化证据 + 调用点无可观测性】，通过【evidencePackage 注入 + AgentRun 3 处埋点 + EVIDENCE_PACKAGE_ENABLED 灰度控制 + @Optional 失败降级】，让用户获得【可追溯的 LLM 输入 + 可量化的 Agent 调用指标】。

---

## 二、价值主张

- **用户为什么要用你而不是不用**：
  - 旧版：LLM 输入完全靠 prompt 拼接，无法追溯、无法量化、无法优化
  - 新版：每次 LLM 调用都有结构化 evidencePackage + AgentRun 记录，可追溯、可量化、可优化

- **用户为什么要用你而不是用竞品**：
  - 竞品（如简单 prompt 模板）：缺少规则前置和知识检索，容易出现幻觉
  - 本方案：8 条规则前置 + L2 知识检索 + evidence 评分，让 LLM 输出有据可依

---

## 三、最小闭环（3 步）

1. **Step1（用户问事）**：用户提交问题（如"我最近要不要换工作"）
2. **系统做什么**：
   - 张班珊调度器分类问题（婚姻/事业/财运/健康/时机/综合）
   - RuleMatcher 匹配 8 条规则（高/中/低 严重度）
   - EvidenceComposer 打包 evidencePackage（含 chartSnapshot + matchedRules + knowledgeFragments + ruleBasedScore）
   - LLM 调用（注入 evidencePackage 到 prompt）
   - AgentRunLogger 记录 3 处调用点（RuleMatcher / EvidenceComposer / LLM）
3. **用户得到什么结果**：得到结构化建议（含规则引用 + 知识引用 + 风险评分），且系统记录每次调用用于后续分析

## 八、技术冻结（Tech Freeze）

### 8.1 入口冻结

- 主链路入口：`POST /api/v1/consult/synthesize-three-stage`
- evidence 路由：`GET /api/v1/admin/consult-records/:id/evidence`（已注册，灰度关闭时返回 404/403）

### 8.2 数据格式冻结

```typescript
// evidencePackage 结构
interface EvidencePackage {
  chartSnapshot: { male: BaziFullResult; female?: BaziFullResult };
  matchedRules: { high: MatchedRule[]; medium: MatchedRule[]; low: MatchedRule[] };
  knowledgeFragments: KnowledgeFragment[];
  userContext: { background: string; concerns: string[] };
  ruleBasedScore: {
    evidenceCompleteness: number;  // 0-1
    decisionConfidence: number;    // 0-1
    riskLevel: 'low' | 'medium' | 'high';
    decisionBias: 'proceed' | 'observe' | 'stop' | 'defer';
  };
  meta: {
    versions: { prompt: string; rules: string; knowledge: string };
    createdAt: string;
  };
}
```

### 8.3 环境变量

- `EVIDENCE_PACKAGE_ENABLED`：默认 false，可选 true
  - false = evidencePackage 不构造，LLM 调用走原逻辑
  - true = evidencePackage 构造并注入 prompt
- 未设置 = 默认 false（fail-safe）

### 8.4 失败降级策略

- 注入失败 → evidencePackage = null，LLM 调用走原逻辑
- 埋点失败 → safeLogAgentRun try-catch 降级，不阻断主链路
- 任一服务缺失 → @Optional 注入为 undefined，相关功能跳过

## 九、风险与缓解

| 风险 | 严重度 | 缓解措施 |
|------|--------|----------|
| prompt 注入放大（evidencePackage 过长导致 LLM 上下文溢出） | medium | rule-based 评分 + meta.versions 追踪 + UC1 线上验证 |
| evidencePackage 构造耗时（每次 LLM 调用多 100-300ms） | low | try-catch 降级 + 异步化（v0.2） |
| AgentRun 存储膨胀 | low | 仅记录关键字段 + 30 天清理（v0.2） |
| 规则匹配误判（影响 LLM 输出） | medium | EVIDENCE_PACKAGE_ENABLED 灰度控制 + A/B 测试（v0.2） |
