## 一、Phase 2 目标与边界

### 目标
建立数据库层、积分扣减幂等、真实问事事务闭环，完成 V2 数据链路的持久化与权益控制。

### 本轮做
1. Prisma Schema 变更（KlineShareLink 新增 + CreditLedger 幂等键 + KlineOutcome 唯一约束 + ConsultRecord kline-v2 专用字段）
2. Migration 创建与 rollback.sql
3. 免费裁剪逻辑（generate 返回裁剪 ViewModel）
4. 会员解锁扣 3 积分（/membership/unlock）
5. 节点问事事务化重写（POST /kline-v2/nodes/:nodeId/ask）
6. 管理员资产接口（3 个 AdminGuard 端点）

### 本轮不做
- 前端整改（Phase 3）
- LLM 叙事接入（Phase 4）
- V1 数据迁移（保留只读兼容 14 天，不迁移）
- 模拟数据进入正式结果

### 约束
- V1 旧 API 保留只读兼容 14 天
- 模拟数据禁止进入正式结果
- LLM 只负责自然语言解释，不生成或修改分数、节点和日期
- 节点问事接口必须保证事务和幂等性，禁止返回虚构 consult-* ID

## 三、分步清单

### Step 2.1｜Prisma Schema 变更

- **动作**：完善模型关系、新增 KlineShareLink、CreditLedger 幂等键、ConsultRecord kline-v2 专用字段
- **修改文件**：`apps/api-server/prisma/schema.prisma`
- **diff 要点**：

#### 2.1.1 KlineSnapshot 关联 User 和 BaziProfile
```prisma
model KlineSnapshot {
  // 现有字段保持不变...
  userId    String
  profileId String?

  // 新增关系
  user    User    @relation(fields: [userId], references: [id], onDelete: Cascade)
  profile BaziProfile? @relation(fields: [profileId], references: [id], onDelete: SetNull)
  nodes   KlineNode[]

  // 现有索引保持不变
  @@index([userId, status])
  @@index([profileId])
}
```

#### 2.1.2 KlineNode 关联 ConsultRecord
```prisma
model KlineNode {
  // 现有字段保持不变...
  consultRecordId String?

  // 新增关系
  snapshot      KlineSnapshot   @relation(fields: [snapshotId], references: [id], onDelete: Cascade)
  consultRecord ConsultRecord?  @relation(fields: [consultRecordId], references: [id], onDelete: SetNull)
  outcomes      KlineOutcome[]

  // 现有索引保持不变
  @@index([snapshotId])
  @@index([nodeType])
}
```

#### 2.1.3 KlineOutcome 增加 @@unique
```prisma
model KlineOutcome {
  // 现有字段保持不变...

  // 新增关系
  node KlineNode @relation(fields: [nodeId], references: [id], onDelete: Cascade)
  user User      @relation(fields: [userId], references: [id], onDelete: Cascade)

  // 新增唯一约束：同一节点同一用户只能回写一次结果
  @@unique([nodeId, userId])
  @@index([nodeId])
  @@index([userId])
}
```

#### 2.1.4 新增 KlineShareLink 模型
```prisma
/// P2-1: K线分享链接 — 随机 token，不暴露 snapshotId
model KlineShareLink {
  id         String   @id @default(uuid())
  token      String   @unique // 随机 token，不暴露 snapshotId
  snapshotId String
  userId     String
  expiresAt  DateTime?
  revokedAt  DateTime?
  createdAt  DateTime @default(now())

  snapshot KlineSnapshot @relation(fields: [snapshotId], references: [id], onDelete: Cascade)
  user     User         @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([snapshotId])
}
```

#### 2.1.5 CreditLedger 增加 idempotencyKey

```prisma
model CreditLedger {
```

```sql
-- rollback.sql

-- 4. 删除 ConsultRecord kline-v2 专用字段

ALTER TABLE "ConsultRecord" DROP COLUMN IF EXISTS "nodeId";
ALTER TABLE "ConsultRecord" DROP COLUMN IF EXISTS "targetDate";

-- 5. 删除新增索引
DROP INDEX IF EXISTS "KlineShareLink_userId_idx";
DROP INDEX IF EXISTS "KlineShareLink_snapshotId_idx";
```

- **验收标准**：migration SQL 可读、rollback.sql 完整、本地 migrate 成功

### Step 2.5｜节点问事重写（核心）

- **动作**：`POST /kline-v2/nodes/:nodeId/ask` 事务化重写
- **前置依赖**：Step 2.1 完成（ConsultRecord kline-v2 字段）、Step 2.4 完成（积分扣减）
- **修改文件**：
  - `kline-v2.controller.ts`（ask 方法重写）
  - `consult/consult.service.ts`（新增 askKlineNode 方法）
- **diff 要点**：
  - 校验节点归属（nodeId 属于用户最新 snapshot）和快照状态（active）
  - 校验 `Idempotency-Key` header（必填）
  - 事务内操作顺序：
    1. 查询 CreditLedger 是否已有相同 idempotencyKey → 有则返回已有 recordId
    2. 创建 ConsultRecord（snapshotId/nodeId/targetDate 填充）
    3. 扣 1 积分 → 写 CreditLedger（idempotencyKey）
    4. 回写 KlineNode.consultRecordId
    5. 返回 ConsultRecord
  - 失败回滚：创建咨询失败不扣积分、扣积分失败不创建咨询
  - 重复请求：返回第一次 recordId
  - 禁止返回虚构 `consult-*` ID
- **验收标准**：真实 ConsultRecord + 事务 + 幂等
- **验证方法**：
```powershell
cd apps\AWKN-LABlife\awkn-life-backend\apps\api-server
..\..\node_modules\.bin\jest --testPathPattern="kline-tide" --grep="ask transaction|idempotency|consult record" --no-coverage
```
- **回滚方式**：`git checkout -- kline-v2.controller.ts consult/consult.service.ts`
- **风险标记**：高（事务 + 幂等 + 积分扣减）
- **Plan B**：失败信号=事务回滚错误 → 兜底方案=返回 500 + 错误日志 → 需保留证据=请求体+idempotencyKey+错误堆栈
