## 一、计划总览（Summary）

以"产品闭环上线"为总目标，Q3 开发计划统一收口到 4 条主线：**生产稳定与账号保真、三入口前台统一、数据资产与管理员后台、命运 K 线/潮汐价值化重构**。

### 执行原则（只有三条）

1. **后端数据库是唯一真源**，前端缓存只做体验优化。
2. **同一用户、同一事项、同一结果必须可追溯、可回看、可运营**。
3. **K 线与潮汐不是"图表展示功能"，而是面向用户决策的判断引擎与付费承接入口**。

### 四条主线

| 主线 | 阶段 | 目标 | 阻塞后续 |
|------|------|------|---------|
| 生产稳定与账号保真 | 阶段 1 | 部署保护、管理员恢复、路由稳定 | ✅ 是 |
| 数据资产与前台统一 | 阶段 2 | 三入口状态机、事项主键贯通、历史页改造 | ⚠️ 部分阻塞 |

## 二、执行原则与硬约束

### 硬约束（不可违反）

- **HC1**：后端数据库是唯一真源，前端缓存只做体验优化，不允许前端成为数据权威。
- **HC2**：同一用户、同一事项、同一结果必须可追溯、可回看、可运营，禁止新建匿名重复记录。
- **HC3**：K 线与潮汐是决策引擎，不是图表展示功能；必须输出"判断 + 依据 + 行动 + 窗口 + 代价"。
- **HC4**：生产环境禁止继续把 `prisma db push` 作为增量部署默认路径；已有库统一走 `prisma migrate deploy`。
- **HC5**：所有入口口径、数据格式、权限变更必须写入结果单并升版本，未写入的口头变更视为无效。
- **HC6**：SQLite 仍作为本期生产数据库，优先做保护与可回滚；数据库迁移不是本期阻塞项。
- **HC7**：管理员后台本期目标是"最小可运营视图"，不是完整 BI 系统。
- **HC8**：K 线与潮汐本期目标是"决策价值成型"，不是继续堆更多命理因子或更多图表组件。

### 执行顺序（硬规则）

- **OR1**：必须按阶段 1 → 阶段 4 顺序执行，不得跳步。
- **OR2**：任一阶段无结果单或结果单不完整，禁止进入下一阶段。
- **OR3**：阶段 1 通过前，禁止大规模开发。
- **OR4**：所有阶段全部 PASS 后，才允许进入工程落地复用。

## 三、阶段划分与主线

### 阶段 1：生产稳定与账号保真

**目标**：完成部署保护、管理员恢复、`/life` 路由稳定、登录权限保真、最小健康检查闭环。

**前置条件**：无（首要阶段）

**通过标准**：
- 部署链路改为"备份数据库 → 锁检查 → 安全迁移 → 管理员保底 → 健康检查 → 失败自动回滚"。
- 每次部署后强制校验管理员账号存在、密码可登录、`isAdmin` 状态正确。
- `/life` 子路径、静态资源、SPA 路由、健康检查、API 反代全部纳入部署后核验清单。
- 环境一致性审计完成，防止 `.env.example`、生产 `.env`、运行时配置漂移。

### 阶段 2：数据资产与前台统一

**目标**：完成三入口状态机统一、事项主键贯通、关键字段稳定写入、历史页改造。

**前置条件**：阶段 1 PASS

**通过标准**：
- 统一入口分发、壳层、阶段状态机、提交协议、结果承接与重试逻辑。
- `FrontdeskShell → FrontdeskChat → mode(question|naming|kline)` 作为唯一前台主结构。
- 统一 `analyze → clarify → result → followup` 提交流程，所有入口都返回同一类 `recordId/consultationId`。
- 缺基础资料时，不允许空页或死路，必须自动跳回资料补全，并保留当前事项上下文。
- 历史重开、结果回看、继续追问全部挂回原事项，不再新建匿名重复记录。

### 阶段 3：K 线/潮汐价值化与权益承接

**目标**：完成 K 线/潮汐后端真源收口、前台价值重构、积分/会员 gating、分享链与历史回看打通。

**前置条件**：阶段 2 PASS

**通过标准**：
- K 线后端作为唯一真源，前端本地重算仅保留为历史兼容与兜底层。
- K 线首屏固定输出：当前阶段、当前大运、趋势判断、支撑位、压力位、转向信号、最佳窗口、风险窗口、操盘证据层。
- 潮汐页重构为"状态判断页"而非空图页，必须输出时、位、心三维状态、阶段判断、短指令、窗口提示、行动建议。
- K 线与潮汐统一决策口径：都输出"判断是什么、依据是什么、该怎么做、什么时候做、代价是什么"。
- 付费分层围绕 K 线/潮汐统一：免费版看趋势与当前窗口，付费版看多维线、关键年份、深层解释、历史对比、高清分享资产。

### 阶段 4：管理员后台与经营闭环

**目标**：完成管理员最小后台、反馈/测试问题视图、用户资产视图、转化视图、数据清洗 SOP、回归验收。

**前置条件**：阶段 3 PASS

**通过标准**：
- 新增管理员最小后台视图：用户总览、事项总览、命盘与画像、转化与行为。
- 管理员可直接查看用户反馈、测试问题、最近咨询、命盘快照、追问链、积分/会员动作、分享/解锁记录。
- 增加匿名重复档案与孤儿会员数据治理任务：定义识别规则、清理策略、回归检查，保证清理后不破坏真实用户链路。

## 四、详细任务清单

### 阶段 1：P0 稳定性与账号保真（首要，阻塞后续）

#### P0-1：部署链路改造为安全迁移流程

**问题**：
- 当前部署链路缺少数据库备份和锁检查，`prisma db push` 作为默认路径风险高。
- 部署失败时无自动回滚机制。

**修复方案**：
```
Step 1: 编写部署脚本，流程改为：备份数据库 → 锁检查 → 安全迁移 → 管理员保底 → 健康检查 → 失败自动回滚
Step 2: 生产环境禁止 prisma db push，统一走 prisma migrate deploy
Step 3: 部署脚本增加失败检测点，任一步失败自动回滚到备份
Step 4: 部署后强制校验管理员账号存在、密码可登录、isAdmin 状态正确
```

**验收标准**：
- ✅ 部署脚本执行后，数据库备份文件存在且可恢复
- ✅ `prisma migrate deploy` 成功执行，无 schema 漂移
- ✅ 部署后管理员账号登录成功，`isAdmin` 状态正确
- ✅ 模拟部署失败时，自动回滚到备份版本，服务恢复

**回滚方式**：`ssh root@8.148.245.29 "cd /opt/hatwin && cp -r /opt/hatwin.bak-$(date +%Y%m%d)/* . && pm2 reload hatwin-backend"`

## 十、假设与约束

### 假设

- **A1**：本计划只整合当前仓库内可读工程文档、记忆目标与现有产品问题，不以缺失的外部整改 HTML 为准。
- **A2**：SQLite 仍作为本期生产数据库，优先做保护与可回滚；数据库迁移不是本期阻塞项。
- **A3**：管理员后台本期目标是"最小可运营视图"，不是完整 BI 系统。
- **A4**：K 线与潮汐本期目标是"决策价值成型"，不是继续堆更多命理因子或更多图表组件。
- **A5**：若后续要把"用户反馈/测试问题"独立成工单系统，可在管理员最小后台稳定后再拆，不在本期额外开新系统。

### 约束

- **C1**：所有入口口径必须写死，不口头改。
- **C2**：所有数据格式必须写死，变更必须升版本。
- **C3**：任何未写入结果单的入口、协议、字段、权限变更，均视为无效口头变更，不得执行。
- **C4**：环境变量权威来源唯一。
- **C5**：所有密钥不进前端、不进仓库。
- **C6**：发布前必须跑前置校验门与冒烟。
- **C7**：失败即止损，按定位路径或回滚。
- **C8**：数据/存储必须隔离。
- **C9**：真机/线上验证优先于模拟器判断。
