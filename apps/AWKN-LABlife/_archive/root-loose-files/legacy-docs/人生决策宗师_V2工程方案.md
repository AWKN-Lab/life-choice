# 人生决策宗师 V2 工程方案
## 基于现有架构的职责边界梳理与改进建议

**版本**: V2 | **日期**: 2026-04-14
**目标**: 明确"服务器做"与"API调用"的边界，对标现有架构，提出改进方案

---

## 一、核心原则（来自V1方案）

> 把"计算"从大模型手里拿回来，把"表达"交给大模型，只让大模型做它最擅长的人话理解与人话生成。

### 四不原则
1. **能规则化的，绝不交给大模型** - 意图初筛、会员状态、页面状态
2. **能算法化的，绝不交给大模型** - 真太阳时、八字排盘、六壬起课、神煞
3. **能预制的，绝不现场生成** - 文案模板、结果页模块、海报底图
4. **大模型只做四类事** - 自然语言理解、澄清追问、人话表达、多轮陪伴

## 三、职责边界：服务器做 vs API调用

### 3.1 服务器本地计算（确定性算法）

| 能力 | 模块 | 说明 | 是否调用外部API |
|------|------|------|-----------------|
| 真太阳时计算 | shared | 根据经纬度计算当地太阳时 | ❌ 纯算法 |
| 节气/月将计算 | shared | 基于天文学公式 | ❌ 纯算法 |
| 八字排盘 | ziping | 四柱+十神+纳音+长生 | ❌ 纯算法 |
| 大运流年 | ziping | 大运起运+流年分析 | ❌ 纯算法 |
| 大六壬起课 | liuren | 天地盘+四课+三传+课体 | ❌ 纯算法 |
| 神煞标注 | shared | 神煞基础标注（贵人/桃花等） | ❌ 纯算法 |
| 路由分流 | router | 基于规则的意图分类 | ❌ 纯算法 |
| 会员状态 | membership | 权益/期限/扣减 | ❌ 数据库 |
| 支付处理 | payment | 订单/回调 | ❌ 微信/支付宝SDK |
| 结果拼装 | consult | 结构化JSON装配 | ❌ 纯逻辑 |

### 3.2 必须调用LLM的能力

| 能力 | 触发场景 | 输入 | 输出 | 说明 |
|------|---------|------|------|------|
| 自然语言理解 | 用户问题模糊 | 压缩后的用户原话 | 意图类别 | 只能输入摘要，禁止塞整库 |
| 澄清追问 | 路由为clarify | 用户问题 | 一条澄清问题 | 单句，可直接显示 |
| 一句准话生成 | 算法完成后 | 结构化JSON | "XX日主，XX命局..." | 只翻译，不重算 |
| 多轮追问 | 用户继续问 | record_id+追问 | 顾问式展开 | 必须引用已有结果 |
| 情绪价值 | 结果输出 | 结构化结果 | 带情感的表达 | 不失准的前提下 |

### 3.3 可预制的能力（不调用LLM）

| 能力 | 内容 | 方式 |
|------|------|------|
| 结果页外壳 | 会员承接文案 | 模板预制 |
| 高频问题模板 | 合作/换工作/资产等问题 | 字段槽位 |
| 按钮文案 | 确定/取消/继续等 | 预制 |
| 海报底图 | 增长页素材 | CDN预制 |
| FAQ内容 | 常见问题解答 | 预制 |

## 四、数据流：完整链路追踪

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                              用户咨询完整链路                                  │
└──────────────────────────────────────────────────────────────────────────────┘

1. 用户输入问题
   ↓
2. 前端 → 后端 /api/consult/route (POST)
   └── 服务器做：router.service.ts 规则初筛
       ├── ziping (八字): 需要birth_date/time/place/gender
       ├── liuren (六壬): 需要ask_time/location
       └── clarify (澄清): 调用LLM生成澄清问题

3. 前端补信息页 → 后端 /api/consult/info (POST)
   └── 服务器做：
       ├── calc-engine 计算八字/六壬
       ├── 结构化结果 → llm-gateway
       └── LLM生成一句准话 + 风险块 + 行动块

4. 后端 → 前端 返回结果JSON
   └── calc_result: 四柱/十神/五行 ← 服务器算
       summary_line: 一句准话 ← LLM生成
       risk_block: 风险 ← LLM生成（算法提供tags）
       action_block: 行动 ← LLM生成（算法提供tags）
       window_block: 时间窗口 ← LLM生成（算法提供period）
       evidence_fold: 判断依据 ← 算法提供基础+LLM润色

5. 前端渲染结果页
   └── 显示：八字四柱 + 十神 + 一句准话 + 风险 + 行动 + 时间窗口

6. 用户保存 → 后端 /api/consult/save (POST)
   └── 服务器做：存储record + 会员权益扣减

7. 用户继续追问 → 后端 /api/consult/followup (POST)
   └── LLM生成：引用record_id的已算结果，展开顾问式回复
```

## 六、改进清单（按优先级）

### P0 - 必须修复

#### 1. 初步结论包含完整八字信息

**问题**：模板兜底的summaryLine只显示"身强/身弱"，没有四柱

**修复**：
```typescript
// ziping-agent.service.ts - analyzeDestinyTrend()
const baziInfo = `四柱：${chart.year.pillar}/${chart.month.pillar}/${chart.day.pillar}/${chart.hour.pillar}`;
summaryLine = `${baziInfo}，日主${chart.day.gan}身强，当前运势稳中有升。`;
```

**修复**：
```typescript
// ziping-agent.service.ts - LLM prompt
"summaryLine": "一句准话，将八字核心信息（四柱/日主/十神/五行强弱）融入定性结论，格式如：'日主甲木身强，食神当令，2026年Q2-Q3学业/事业突破'，控制在25字以内"
```
