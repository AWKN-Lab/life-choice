#### 2.3.1 多Provider架构

```typescript
// llm-gateway.service.ts

interface LLMProvider {
  name: string;
  timeout: number;
  priority: number;
  isAvailable: boolean;
}

class LLMGateway {
  private providers: LLMProvider[] = [
    { name: 'doubao', timeout: 180000, priority: 1, isAvailable: true },
    { name: 'minimax', timeout: 180000, priority: 2, isAvailable: true },
    { name: 'moonshot', timeout: 60000, priority: 3, isAvailable: false },
    { name: 'openai', timeout: 120000, priority: 4, isAvailable: true },
  ];

  async generate(prompt: string, context: object): Promise<string> {
    // 按优先级尝试每个Provider
    for (const provider of this.providers) {
      if (!provider.isAvailable) continue;
      
      try {
        const result = await this.callProvider(provider, prompt, context);
        return result;
      } catch (error) {
        console.error(`${provider.name} failed:`, error);
        continue; // 尝试下一个Provider
      }
    }
    
    // 所有Provider都失败，返回模板兜底
    return this.fallbackResponse(context);
  }

  private async callProvider(
    provider: LLMProvider,
    prompt: string,
    context: object
  ): Promise<string> {
    const response = await fetch(provider.endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        model: provider.model,
        messages: this.buildMessages(prompt, context),
        timeout: provider.timeout,
      }),
    });
    
    if (!response.ok) throw new Error(`${provider.name} returned ${response.status}`);
    return response.text();
  }

  private fallbackResponse(context: object): string {
    // 模板兜底逻辑
    return `根据您提供的信息，当前运势处于${context.strength}状态，建议${context.action}。`;
  }
}

// 真太阳时转换
function convertToTrueSolarTime(
  nominalTime: number,  // 北京时间小时
  latitude: number,
  longitude: number
): number {
  // 真太阳时 = 北京时间 + (当地经度 - 120°) × 4分钟
  // + 时差修正(每年变化，范围 -2.5h ~ +2.5h)
  const eastOffset = (longitude - 120) * 4;  // 分钟
  const timeDifference = getTimeEquation(new Date()); // 获取时差
  const trueSolarMinutes = nominalTime * 60 + eastOffset + timeDifference;
  
  return Math.floor(trueSolarMinutes / 60);  // 返回小时
}

// 日柱计算(重要: 需要精确算法)
function getDayPillar(birthDate: Date, hour: number): string {
  // 使用甲子日起算
  const baseDate = new Date('1984-01-01'); // 甲子日
  const dayDiff = Math.floor((birthDate - baseDate) / (24 * 60 * 60 * 1000));
  const dayCycle = dayDiff % 60;
  
  // 天干表: 甲乙丙丁戊己庚辛壬癸
  const gan = ['甲', '乙', '丙', '丁', '戊', '己', '庚', '辛', '壬', '癸'];

// 步骤1: 求月将
function getYueJiang(month: number): string {
  // 月将表(从天盘起)
  const yueJiangMap: Record<number, string> = {
    1: '亥',  // 雨水后
    2: '戌',  // 春分后

    5: '未',  // 夏至后
    6: '午',  // 大暑后

    10: '寅', // 小雪后
    11: '丑', // 冬至后

// 步骤2: 排天地盘
function getTianPanDiPan(yueJiang: string, askTime: Date): {tianPan: string[], diPan: string[]} {
  const ganList = ['甲', '乙', '丙', '丁', '戊', '己', '庚', '辛', '壬', '癸'];
  const zhiList = ['子', '丑', '寅', '卯', '辰', '巳', '午', '未', '申', '酉', '戌', '亥'];
  
  // 地盘固定(永远是子丑寅卯辰巳午未申酉戌亥)
  const diPan = [...zhiList];
  
  // 天盘根据月将旋转
  const yueJiangIndex = zhiList.indexOf(yueJiang);
  const tianPan = [];
  for (let i = 0; i < 12; i++) {
    const index = (i + yueJiangIndex) % 12;
    tianPan.push(zhiList[index]);
  }
  
  return { tianPan, diPan };
}

## 新增经验条目

### EXP-028: 算法确定性+LLM不确定性分工模式

**场景**: 需要在确定性与灵活性之间取得平衡的复杂任务

**核心做法**:
```
确定性 → 算法/规则 (服务器本地计算)
        - 数据计算、结构判断、状态管理
        - 不依赖外部API，结果可复现

不确定性 → LLM (外部API调用)
        - 自然语言理解、内容生成、创意发挥
        - 可能有变化，但质量更高

分工原则:
1. 能规则化的不交给LLM
2. 能算法化的不交给LLM
3. LLM只做它最擅长的事
```

**适用边界**:
- 适用: 复杂决策、内容生成、创意任务
- 不适用: 简单查询、纯计算任务

### EXP-029: 多Provider Fallback增强

**场景**: API调用可能失败的场景

**核心做法**:
```typescript
const providers = [
  { name: 'doubao', timeout: 180000, priority: 1 },
  { name: 'minimax', timeout: 180000, priority: 2 },
  { name: 'openai', timeout: 120000, priority: 3 },
];

// 失败自动切换，无需人工干预
// 所有Provider失败则模板兜底
```

**适用边界**:
- 适用: 外部API调用场景
- 不适用: 本地计算任务
```

## 新增章节: 第11章 - 多Provider API调用规范

### 11.1 多Provider Fallback模式

**核心原则**:
- 按优先级尝试每个Provider
- 失败自动切换下一个
- 所有失败则模板兜底

**示例配置**:
```typescript
const config = {
  providers: [
    { name: 'primary', timeout: 180000, priority: 1 },
    { name: 'backup1', timeout: 180000, priority: 2 },
    { name: 'backup2', timeout: 120000, priority: 3 },
  ],
  fallback: 'template'
};
```

### 11.2 前后端数据契约设计

**核心原则**:
- 字段命名统一规范
- 类型定义完整准确
- 降级响应有兜底

**契约模板**:
```typescript
interface Response<T> {
  success: boolean;
  data?: T;
  error?: {
    code: string;
    message: string;
  };
  fallback?: T;  // 降级时的兜底数据
}
```

### 11.3 规则+AI混合决策

**核心原则**:
- 规则引擎处理确定性
- AI处理不确定性
- 规则优先，AI降级

**示例**:
```typescript
function process(input: Input): Result {
  // Step 1: 规则引擎初筛
  const ruleResult = ruleEngine.process(input);
  if (ruleResult.canHandle) {
    return ruleResult.result;
  }
  
  // Step 2: AI处理复杂场景
  const aiResult = await llmGateway.generate(input);
  return aiResult;
}

## 八、复盘总结

### 8.1 项目成功因素

| 因素 | 说明 | 可复用性 |
|------|------|---------|
| **算法+LLM混合架构** | 确定性算法保证准确，LLM提升体验 | ⭐⭐⭐⭐⭐ |
| **多Provider Fallback** | 不依赖单一Provider，保证可用性 | ⭐⭐⭐⭐⭐ |
| **MVP快速迭代** | 先上线再优化，快速验证 | ⭐⭐⭐⭐ |
| **命理专业积累** | 深度融合传统命理与现代技术 | ⭐⭐⭐⭐ |
| **用户需求驱动** | 真实咨询场景驱动功能开发 | ⭐⭐⭐ |

### 8.2 项目不足之处

| 不足 | 说明 | 改进方向 |
|------|------|---------|
| **测试覆盖不足** | 算法缺乏单元测试 | 建立测试体系 |
| **监控告警缺失** | 无法及时发现问题 | 增加监控 |
| **Prompt分散管理** | 难以维护和优化 | 建立Registry |
| **文档不同步** | 代码变更后文档未更新 | 建立机制 |

### 8.3 关键教训

```
【教训1】LLM Provider不能依赖单一来源
→ 任何外部依赖都需要Fallback机制

【教训2】算法结果必须完整返回前端
→ 数据契约一旦确定，不能轻易变更

【教训3】代码变更必须同步文档
→ 建立文档与代码的同步机制

【教训4】测试覆盖率是质量保障
→ 核心算法必须有单测保护

【教训5】用户代码不能随意回退
→ git操作必须谨慎，尤其是restore/reset
```

### 8.4 方法论总结

```
项目成功 = 算法确定性 × LLM灵活性 × 架构稳定性

算法确定性: 减少不确定性，保证核心准确
LLM灵活性: 提升用户体验，增加智能感
架构稳定性: 支持扩展，保证可用性

三者缺一不可，形成铁三角。
```
