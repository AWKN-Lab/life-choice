## 一、V1 目标回顾

V1 核心目标：从"能演示"升级到"能稳定让用户完成一次有效体验"。

V1 必须完成的 6 条线（路线图 Ch5.2）：
- A. 命运K线：入口清晰、流程短、结果稳定、付费差异明确、可分享
- B. 问事：对话内完成首问/补充/追问/深推、历史可回看
- C. 取名：统一对话前台、命理依据清晰、付费承接
- D. 稳定性：子站稳定、权限积分逻辑稳定、404/400/403 收口、部署回滚有文档
- E. LLM 质量：去模板残渣、知识库接入调用链
- F. 数据资产：用户数据进后台、历史可回看

## 三、问题清单

### 问题 1：知识库生产部署链路断裂（P0 级）
- **现象**：P0-P2 建好 137337 条向量知识库，但服务器（PM2+Nginx）未启动 knowledge-service，生产环境不可用
- **根因**：原部署计划假设 Docker，实际服务器无 Docker；ecosystem.config.js 只有 backend 一个进程
- **影响**：知识库投入生产价值为零，LLM 调用链无法接入向量检索
- **处理**：P3 工程已规划（方案 A：保持镜像层级），待执行

### 问题 2：对话前台迁移契约冲突（P1 级）
- **现象**：ConsultPage 与 FrontdeskChat 存在 API 路径、跳转目标、鉴权策略、路由契约 5 处冲突
- **根因**：两条链路独立开发，未对齐契约
- **影响**：问事/取名对话闭环不稳定
- **处理**：ENGINEERING-2周闭环攻坚 P2 已规划，待执行

### 问题 3：治理体系自验失效（P1 级）
- **现象**：知识库治理验收报告声称 100% PASS，实际 TC-2.4 _index.md 不存在（误报）
- **根因**：AI 自写-自执行-自验收-自闭环，审查环节被跳过（重演 H-002）
- **影响**：治理体系可信度受损，递归空转
- **处理**：P0 已修复 3 处断裂带；P2 将建立独立审查闸门

### 问题 4：文档归档索引 1 月未更新（P2 级）
- **现象**：归档索引最后更新 2026-05-28，6 月新增文档均未归档
- **根因**：归档动作无自动化触发，依赖人工记忆
- **影响**：文档检索困难，历史可追溯性下降

## 四、经验沉淀（E 编号候选）

### E142 候选：知识库建设必须先验证部署环境
- **场景**：P0-P2 花大量精力建知识库（26568→137337 条），但生产环境无 Docker，部署链路断裂
- **教训**：工程启动前必须先验证部署环境（SSH 探测服务器实际能力），不能假设技术栈
- **规则**：任何"生产可用"目标的项目，第一步是 SSH 探测服务器，第二步才是开发

### E143 候选：AI 自验 PASS 不可信
- **场景**：验收报告声称 TC-2.4 _index.md 已创建，实际文件不存在
- **教训**：AI 作为执行者+验收者时，会不自觉地"美化"结果
- **规则**：所有验收必须 Glob/LS/Read 交叉验证产出物真实存在，不信任"自验 PASS"

### E144 候选：路径推算依赖 __file__ 层级的代码不可移植
- **场景**：main.py 的 _PROJECT_ROOT 基于 __file__ 向上 4 级 dirname 推算，部署路径层级不同会导致路径错误
- **教训**：路径推算不应依赖文件层级深度，应优先用环境变量或配置文件
- **规则**：任何基于 __file__ 的路径推算，必须提供环境变量覆盖入口
