## 5. A｜Act 改进行动

### 5.1 修正目标
- 建立操作前"安全检查"机制
- 对不可逆操作强制用户确认

### 5.2 10条强制规则

```
【高风险操作 - 必须用户确认】
□ 1. git restore / git checkout / git reset → 必须用户确认
□ 2. 删除文件 / 清空大段代码 → 必须用户确认
□ 3. 从外部项目复制代码 → 必须用户确认来源和版本

【编辑前 - 必须执行】
□ 4. 先 git status && git diff → 查看当前状态
□ 5. 先 cp xxx xxx.bak.manual → 备份当前版本
□ 6. 先 Read 完整文件结构 → 确认修改位置

【操作中 - 必须遵守】
□ 7. 分步执行，每步验证后再继续
□ 8. 用户说"删除XX" → 必须确认"删除哪些代码、哪几行"
□ 9. 不确认用户意图时 → 宁可问清楚也不擅自决定
□ 10. 产生错误后 → 先备份当前状态再尝试修复
```

### 5.3 风险与预案

| 风险 | 触发条件 | 应对 |
|------|---------|------|
| 再次产生孤立代码 | Edit替换位置不准确 | 先Read完整文件，标记准确位置 |
| 再次丢失用户代码 | 未确认就执行restore | 强制弹窗确认，或先git stash |
| 复制错误版本 | 未确认来源 | 复制前必须用户确认 |
