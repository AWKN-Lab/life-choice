# 分支保护规则

> 适用范围：本仓库 `main` 分支及发布分支（如 `release/*`）。
> 目的：通过 GitHub 分支保护规则，强制核心目录 PR 必须经 owner 审核且 CI 全绿后方可合并，防止误推与未审核代码进入主干。
> 配套文件：`.github/CODEOWNERS`、`.github/pull_request_template.md`、`.github/workflows/ci.yml`。

---

## 一、为什么需要分支保护

未启用分支保护时，任何有写权限的协作者都可以：

- 直接向 `main` 推送提交（绕过 PR 与审核）
- 在 CI 未通过时合并 PR
- 在 owner 未审核时合并涉及核心模块的 PR

启用分支保护后，上述行为将被 GitHub 拒绝，确保：

1. 所有变更必须通过 Pull Request
2. 所有 PR 必须至少 1 个 approval
3. 涉及核心目录的 PR 必须由 CODEOWNERS 指定的 owner 审核
4. 所有 CI 检查（lint / typecheck / test / security）必须通过

---

## 二、启用步骤（GitHub 仓库设置）

### 2.1 进入分支保护设置

1. 打开仓库页面，点击 **Settings**。
2. 左侧菜单选择 **Branches**。
3. 在 *Branch protection rules* 区域点击 **Add rule**（或编辑已有规则）。

### 2.2 配置 main 分支保护规则

*Branch name pattern* 填入：`main`

勾选以下三项强制规则：

#### 规则 1：Require pull request reviews before merging

- 勾选 **Require a pull request before merging**
- *Required approving reviews* 设置为至少 `1`（核心模块建议 `2`）
- 勾选 **Require review from Code Owners**（强制 CODEOWNERS 审核）
  - 启用后，PR 修改的文件若命中 `.github/CODEOWNERS` 中的规则，对应 owner 将被自动加为 required reviewer，必须由其 Approve 才能合并
- 可选：勾选 **Dismiss stale pull request approvals when new commits are pushed**（新提交撤销旧 approval，强制重新审核）
- 可选：勾选 **Require review from Code Owners** 下的 *Require approval of the most recent push*（最新推送必须被审核）

#### 规则 2：Require status checks to pass before merging

- 勾选 **Require status checks to pass before merging**
- 勾选 **Require branches to be up to date before merging**（合并前必须与目标分支同步）
- 在 *Search for status checks* 中添加以下必过项：
  - `lint`（代码规范检查）
  - `typecheck`（TypeScript 类型检查）
  - `test`（单元测试）
  - `security`（安全扫描，若 CI 中配置）
- 若某项检查在 CI 中尚未配置，先添加已配置的项，后续逐步补齐

#### 规则 3：Require conversation resolution before merging

- 勾选 **Require conversation resolution before merging**
- 启用后，PR 中所有 review 评论必须标记为 *Resolved* 才能合并

### 2.3 可选强化项（推荐）

- **Do not allow bypassing the above settings**：管理员也不绕过分支保护（强烈推荐，防止特权误操作）
- **Restrict who can push to matching branches**：限制可推送人员
- **Require linear history**：要求线性历史，禁止 merge commit（配合 *Squash and merge* 使用）
- **Require signed commits**：要求 GPG 签名提交

### 2.4 发布分支保护（可选）

若使用 `release/*` 发布分支，重复 2.2 步骤，*Branch name pattern* 填入 `release/*`，规则与 `main` 一致或更严格。

### 2.5 保存

点击 **Create**（新建规则）或 **Save changes**（编辑已有规则）。

## 三、CODEOWNERS 与分支保护的协同

分支保护中的 *Require review from Code Owners* 是 CODEOWNERS 生效的前提：

| 配置项 | 作用 |
| --- | --- |
| `.github/CODEOWNERS` | 定义"哪些路径由谁负责" |
| 分支保护 - *Require review from Code Owners* | 强制"命中路径的 PR 必须由对应 owner 审核" |

两者缺一不可：

- 只有 CODEOWNERS、未启用分支保护：owner 会被自动加为 reviewer，但 PR 可在 owner 未审核时被合并（无强制力）
- 只有分支保护、无 CODEOWNERS：所有 PR 需 1 个 approval，但无法按模块指定必须由谁审核

本仓库的 owner 分配见 `.github/CODEOWNERS` 文件，模块与 owner 对应关系概览：

| 模块 | 路径 | Owner |
| --- | --- | --- |

| 后端 - consult | `/apps/AWKN-LABlife/awkn-life-backend/apps/api-server/src/consult/` | `@backend-lead @consult-owner` |
| 后端 - auth | `/apps/AWKN-LABlife/awkn-life-backend/apps/api-server/src/auth/` | `@backend-lead` |

## 四、验证分支保护已生效

启用后，可通过以下方式验证：

1. **直推验证**：尝试直接 `git push origin main`，应被拒绝并提示需通过 PR。
2. **PR 审核验证**：发起一个修改 `/apps/AWKN-LABlife/app/src/` 下文件的 PR，检查 `@frontend-lead` 是否被自动加为 required reviewer；在其 Approve 前合并按钮应不可用。
3. **CI 阻断验证**：发起一个 CI 未通过的 PR，合并按钮应不可用并提示 status check 未通过。
4. **CODEOWNERS 审核**：发起一个修改 `/.env.prod.example` 的 PR，检查 `@cto-user` 与 `@devops-lead` 是否均被加为 required reviewer。

## 五、回滚

- 分支保护规则可在 **Settings → Branches** 中点击 **Delete** 删除，或取消勾选对应选项禁用。
- 删除/禁用分支保护属于高风险操作，需经 `@cto-user` 确认，并在操作前后记录变更。
- 紧急情况下需临时绕过保护（如线上故障修复），建议通过 *hotfix* 分支走快通道 PR 审核，而非禁用分支保护。
