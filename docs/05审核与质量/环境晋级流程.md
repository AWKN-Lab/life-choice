# 环境晋级流程（Staging → Production）

> 适用范围：人生决策宗师后端服务（awkn-life-backend）
> 关联：`.github/workflows/ci.yml` 的 `staging-deploy` 与 `deploy` job

## 1. 环境定义

| 环境 | 用途 | 触发方式 | 数据库 |
|------|------|----------|--------|
| dev | 本地开发 | `npm run dev` | SQLite (dev.db) |
| staging | 预发布验收 | main 分支推送自动部署 | SQLite (staging.db) |
| prod | 生产 | **手动触发**（见下文） | SQLite (prod.db) / PostgreSQL |

## 2. Staging 自动部署

- **触发**：推送到 `main` 分支
- **执行 job**：`staging-deploy`（ci.yml）
- **部署位置**：staging 服务器（与 prod 隔离）
- **验收标准**：
  - CI 全部通过（lint + typecheck + test + build）
  - `/health` 返回 200
  - `/health/ready` 返回 200（DB + LLM + JWT 均就绪）
  - 冒烟测试通过

## 3. Staging → Prod 晋级流程（手动触发）

### 3.1 晋级前置条件（必须全部满足）

- [ ] staging 部署成功且稳定运行 ≥ 30 分钟
- [ ] staging 冒烟测试通过
- [ ] `/health/ready` 持续返回 200
- [ ] 无 P0/P1 级别未修复 bug
- [ ] 数据库备份已执行（`bash scripts/backup-db.sh`）

### 3.2 触发 Prod 部署

Prod 部署**不自动触发**，必须手动执行以下任一方式：

**方式 A：GitHub Actions 手动触发（推荐）**

```bash
# 通过 GitHub CLI 触发 deploy workflow
gh workflow run deploy.yml -f confirm=true
```

**方式 B：SSH 手动部署**

```bash
ssh -i ~/.ssh/aliyun-awkn root@8.148.245.29
cd /opt/awkn-life
git pull origin main
cd apps/AWKN-LABlife
bash deploy.sh
```

### 3.3 Prod 部署后验收

- [ ] `/health` 返回 200
- [ ] `/health/ready` 返回 200
- [ ] `/health/db` 返回真实 DB 状态 + responseTimeMs
- [ ] 冒烟测试通过（`bash scripts/smoke-test.sh`）
- [ ] 关键链路手动验证（登录 → 咨询 → 结果返回）

### 3.4 失败回滚

如 Prod 部署后验收失败，立即回滚：

```bash
bash /opt/awkn-life/scripts/rollback.sh
```

回滚脚本会从最近备份点恢复代码 + DB + .env.prod，并重启服务。
回滚日志：`/var/log/awkn-rollback.log`

## 4. 禁止事项

- ❌ 禁止跳过 staging 直接部署 prod
- ❌ 禁止在 staging 验收未通过时晋级 prod
- ❌ 禁止无备份直接部署 prod
- ❌ 禁止在 prod 直接调试代码（必须回 dev/staging 修复）
