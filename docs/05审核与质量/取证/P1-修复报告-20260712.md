### 3.2 memory-forget.service.ts 三个方法恢复

**applyDecay（衰减）**：
- 查找 `lastAccessedAt < 30天前` + `weight > MIN_WEIGHT_TO_DECAY(0.2)` 的记忆
- 逐条 `update weight *= 0.8`（不低于 0.2）
- 使用 findMany + 循环 update（需要读取当前 weight 做乘法）

**archiveStale（归档）**：
- `updateMany` 将 `lastAccessedAt < 90天前` 的记忆 `weight = 0.1`
- 使用 updateMany 批量更新

**markAccessed（标记访问）**：
- `updateMany` 将指定 id 的记忆 `lastAccessedAt = now`
- 参数 memoryIds 是 UserMemory.id 列表（primary key）

**注意**：cleanExpired 方法**保持 no-op**（P0-1 安全止损未恢复），因为涉及删除整行 UserMemory 的风险，PRD 说要改为"只清空 P2-1 扩展字段"，不属于本轮 P1 范围。

## 七、跳过问题的详细说明

### 7.1 配置错位修复（DATABASE_URL）

**原问题**：.env 的 `DATABASE_URL="file:./prisma/dev.db"` 是相对路径，Prisma CLI 在不同 cwd 下解析不同。

**跳过理由**：
- bootstrap-production.js L156-164 已强制修正 DATABASE_URL 为绝对路径 `file:/opt/awkn-life/awkn-life-backend/apps/api-server/prisma/dev.db`
- 运行时 Prisma Client 连接正确的 DB
- .env 的相对路径在 `apps/api-server/` 目录下执行 prisma CLI 时解析正确
- 4 个 DB 文件已清理为 1 个（批次 2），不再有混淆风险

### 7.2 P2 对话契约差异 3

**原问题**：ConsultPage 的 liuren/ziping 路由使用 V1 旧架构（直接跳转结果页），需迁移到 V2 新架构（FrontdeskChat 对话引导）。定义详见 `P2-对话前台契约差异分析与修复计划-20260711.md` §3 差异 3。

**延期理由**（2026-07-12 更正）：
- 差异 3 有明确定义（改 ConsultPage.tsx L102-176），此前报告写"无具体定义"为错误表述，现更正
- 项目已有 Vitest + Testing Library + test:run + typecheck，但缺 ConsultPage/FrontdeskChat 的流程测试
- 直接在无测试覆盖下改生产入口路径风险高（用户流程变更 + 回归风险）
- 准入条件：补两个流程测试（六壬补问时间 + 八字档案检查）+ 人工验收
- 决策：延期至 V2 P1 实施，作为 V2 P1 的硬门禁

### 7.3 移除 bootstrap DB 路径修正

**原问题**：bootstrap-production.js 的强制修正逻辑"治标不治本"。

**跳过理由**：
- 强制修正是防御性编程，确保生产环境始终指向正确的 DB
- 即使 .env 配置被误改，bootstrap 仍能兜底
- 移除后，如果 .env 配置被误改，生产会连错 DB
- P2 优先级低，风险大于收益

### 7.4 端口配置统一

**原问题**：.env PORT=30001，实际监听 30000。

**跳过理由**：
- .env PORT=30001 是开发环境配置
- .env.prod PORT=30000 是生产环境配置
- bootstrap-production.js 用 .env.prod 强制覆盖 .env，生产实际监听 30000 是正确的
- .env / .env.prod 分离是正确的环境隔离实践
- "端口配置统一"是误判，实际配置是正确的
