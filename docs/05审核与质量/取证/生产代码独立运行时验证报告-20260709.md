## 9. 问题清单

### P0-001: 用户浏览器加载 PWA 缓存的旧版前端代码
- **级别**: P0
- **现象**: 浏览器请求 `ResultAdvancedTools-mLk_mzFy.js`，服务器实际为 `ResultAdvancedTools-DXJzUrxz.js`
- **证据**: 
  - 服务器 `cat index.html` → `index-DMvw80dh.js`
  - 用户控制台 → `index-BjkUmOis.js`
  - vite.config.ts 配置了 VitePWA + workbox globPatterns 缓存 JS
- **根因**: PWA Service Worker 缓存了旧版 JS，`registerType: 'autoUpdate'` 未强制刷新
- **影响**: 用户使用旧版前端，包含已修复的 bug（map undefined）
- **建议处理**: 
  1. 用户清除浏览器缓存 / Site Data（含 Service Worker）
  2. 或更新 Service Worker 版本号触发强制更新
  3. 检查 VitePWA `autoUpdate` 配置是否生效
- **是否阻塞上线**: 是（用户体验受损）

### P0-002: 本地代码领先 origin/main 36 个提交未推送
- **级别**: P0
- **现象**: `git status` 显示 "Your branch is ahead of 'origin/main' by 36 commits"
- **证据**: `git log -5 --oneline` 显示本地 HEAD 38e75ca2，origin/main 落后 36 个
- **根因**: 36 个提交未推送到 GitHub 远程仓库
- **影响**: 
  - 生产无法通过 git pull 获取修复
  - 团队无法协作
  - 代码丢失风险
- **建议处理**: 立即 `git push origin main` 推送 36 个提交
- **是否阻塞上线**: 是（代码不可追溯）

### P0-003: Cloudflare CDN 外部访问异常
- **级别**: P0
- **现象**: `curl https://awkn.cn/life/` 超时返回 000（21s），但 `ping` 通、TCP 443 可连
- **证据**: 
  - nslookup awkn.cn → 104.21.31.213 (Cloudflare)
  - Test-NetConnection awkn.cn:443 → TcpTestSucceeded: True
  - curl --max-time 15 → TIME_TOTAL: 21s, HTTP_CODE: 000
  - 服务器内部 https://127.0.0.1/life/ → 200
- **根因**: Cloudflare 的 SSL/防火墙/Bot 防护可能拦截了非浏览器 curl 请求；或 Cloudflare → 源站回源超时
- **影响**: 无法从外部验证 WebSocket；用户可能遇到间歇性访问问题
- **建议处理**: 
  1. 检查 Cloudflare Dashboard 的 SSL/TLS 模式（应为 Full）
  2. 检查 Cloudflare WebSocket 是否启用（Network → WebSockets）
  3. 检查 Cloudflare 防火墙规则是否拦截了 socket.io 路径
  4. 检查 Cloudflare → 源站的回源超时设置
- **是否阻塞上线**: 需进一步确认

### P0-004: ResultAdvancedTools 组件 map undefined 运行时错误
- **级别**: P0
- **现象**: `TypeError: Cannot read properties of undefined (reading 'map') at hn (ResultAdvancedTools-mLk_mzFy.js:2:2047)`
- **证据**: 用户浏览器控制台日志 + ErrorBoundary 捕获
- **根因**: 旧版 ResultAdvancedTools 组件中某个子组件（BaZiDetail/AnalysisResult/KLineShareCard）调用 `.map` 时数据为 undefined
- **影响**: 结果页高级工具区崩溃，ErrorBoundary 兜底
- **建议处理**: 
  1. **短期**: 用户清除浏览器缓存加载新版（DXJzUrxz.js 可能已修复）
  2. **长期**: 审查新版 ResultAdvancedTools 源码确认 .map 调用有空值保护
  3. 检查 BaZiDetail、AnalysisResult 组件中的 .map 调用
- **是否阻塞上线**: 是（核心功能崩溃）

### P1-001: 后端 socket.io namespace 配置不匹配
- **级别**: P1
- **现象**: 
  - gateway 配置 `namespace: '/ws'`
  - `curl /ws/?EIO=4&transport=polling` 返回 404
  - `curl /socket.io/?EIO=4&transport=polling` 返回 200
- **证据**: 
  - websocket.gateway.ts 第50行: `namespace: '/ws'`
  - SSH curl 测试: `/ws/` → 404, `/socket.io/` → 200
  - 前端 websocket.ts: `io(url, { path: ... })` 未指定 namespace
- **根因**: gateway 的 namespace 配置可能未生效（main.ts 缺少 IoAdapter），实际运行在默认 namespace `/`
- **影响**: 前端连默认 namespace 能建立连接，但 gateway 的事件处理器可能未正确注册
- **建议处理**: 
  1. 统一 namespace：前端加 `namespace: '/ws'` 或后端去掉 namespace 配置
  2. main.ts 显式配置 `app.useWebSocketAdapter(new IoAdapter(app))`
- **是否阻塞上线**: 否（polling 能连，但事件路由可能有隐患）

### P1-002: main.ts 缺少 IoAdapter 显式配置
- **级别**: P1
- **现象**: `grep -c "IoAdapter|useWebSocketAdapter" dist/main.js` 返回 0
- **证据**: SSH grep 生产 dist/main.js
- **根因**: main.ts 未显式 `app.useWebSocketAdapter(new IoAdapter(app))`
- **影响**: socket.io 服务依赖 NestJS 默认行为，配置不可控
- **建议处理**: main.ts 添加 `import { IoAdapter } from '@nestjs/platform-socket.io'; app.useWebSocketAdapter(new IoAdapter(app));`
- **是否阻塞上线**: 否（当前能运行，但不可控）

### P2-001: 生产 Git 仓库与本地完全分叉（前序报告遗留）
- **级别**: P2
- **现象**: 生产 commit 4bbcd7c (master) 本地不存在
- **证据**: 前序报告 + 本次 `git log` 确认未变
- **建议处理**: 生产仓库添加 remote 或统一用 dist 上传部署

### P2-002: 生产 src 不完整（前序报告遗留）
- **级别**: P2
- **现象**: 生产 src 缺 47 个模块，无法独立 build
- **建议处理**: 后续部署统一用"本地 build dist → 上传"
