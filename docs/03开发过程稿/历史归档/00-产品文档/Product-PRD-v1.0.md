## 1. 产品定位

**一句话定义**：AI命理咨询全栈应用，基于八字/六壬算法与大模型推理，为用户在人生关键决策节点提供命理参考与理性分析。

**核心价值主张**：融合传统命理智慧与现代AI技术，让"算法确定性"保障排盘准确，"LLM灵活性"提升解读体验。

**目标用户**：
- 在职业、感情、投资等关键节点需要决策参考的成年人
- 对传统命理文化有认知基础的用户
- 希望获得"一句准话"式明确建议的用户

### 2.2 四步决策框架

```
理解需求 → 识别风险 → 生成方案 → 评估决策
```

| 步骤 | 输入 | 处理 | 输出 |
|------|------|------|------|
| 理解需求 | 用户问题 + 出生/问事信息 | 路由分流（八字/六壬/取名） | 咨询类型 + 缺失信息 |
| 识别风险 | 算法计算结果 | 五行生克分析 + 课体判断 | 风险提示列表 |
| 生成方案 | 算法结果 + 风险 + 用户画像 | LLM生成解读 | 一句准话 + 行动建议 |
| 评估决策 | 完整解读结果 | VFM评估矩阵 | 决策参考 + 时间窗口 |

### 4.3 LLM Provider架构

| 优先级 | Provider | Timeout | 状态 |
|--------|----------|---------|------|
| 1 | 豆包（Doubao） | 180s | ✅ 优先 |
| 2 | MiniMax | 180s | ✅ 备用 |
| 3 | Moonshot | 60s | ❌ 账户封禁 |
| 4 | OpenAI | 120s | ✅ 兜底 |

```typescript
class LLMGateway {
  private providers: LLMProvider[] = [
    { name: 'doubao', timeout: 180000, priority: 1, isAvailable: true },
    { name: 'minimax', timeout: 180000, priority: 2, isAvailable: true },
    { name: 'moonshot', timeout: 60000, priority: 3, isAvailable: false },
    { name: 'openai', timeout: 120000, priority: 4, isAvailable: true },
  ];

  async generate(prompt: string, context: object): Promise<string> {
    for (const provider of this.providers) {
      if (!provider.isAvailable) continue;
      try {
        return await this.callProvider(provider, prompt, context);
      } catch (error) {
        continue;
      }
    }
    return this.fallbackResponse(context);
  }
}
```

## 6. 算法核心

### 6.1 八字排盘算法

**输入参数**：出生日期、出生时间、出生地点（经纬度）、性别

**计算流程**：
1. 真太阳时转换（北京时间 + 经度偏移 + 时差修正）
2. 排四柱（年柱/月柱/日柱/时柱）
3. 计算十神关系
4. 五行统计与旺衰判断
5. 纳音五行
6. 神煞标注
7. 大运流年推算

### 6.2 六壬起课算法

**输入参数**：问事时间、问事地点

**计算流程**：
1. 真太阳时转换
2. 求月将（按节气）
3. 排天地盘
4. 发用四课
5. 贼克法取三传
6. 判断课体
7. 神煞标注

### 三入口产品设计（v1.1）

**设计理念**：将原有的单一对话入口拆分为三大产品线，降低认知门槛，提升转化率。

| 入口 | 名称 | 定位 | 目标用户 |
|------|------|------|----------|
| 命运K线 | 命运K线 | 八字深度分析 + 四线算法 | 有耐心、愿深度了解命盘的核心用户 |
| 取名 | 取名大师 | 宝宝取名 / 成人改名 / 起字号 | 实用场景驱动的新用户 |
| 问事 | 问事解惑 | 快速占卜 / 重大决策分析 | 低频、即时需求用户 |

**三入口差异化**：
- **K线**：重算法（四线：天运/地运/人运/时运），重结果展示
- **取名**：重交互（多轮筛选），重实用输出（名字候选列表）
- **问事**：重速度（输入→意图识别→结论），重场景覆盖

### Frontdesk 通用对话前台（v1.1）

**问题**：取名和问事前台的对话交互 90% 相同，但之前是两套独立代码。

**方案**：构建通用 FrontdeskChat 组件，通过 `mode` prop 切换行为。

| mode | 对话步骤 | 配置色系 | 快捷选项 |
|------|----------|----------|----------|
| `naming` | 对话 → 表单详情 → 出生信息 | 蓝色（blue-400） | 宝宝取名 / 成人改名 / 起字号 |
| `question` | 输入 → 意图识别 → 路由 | 紫色（purple-400） | 事业 / 财运 / 健康 / 婚姻 |

**渲染模式**：
- `renderAs="modal"`：首页弹窗（从 EntryGrid 点击触发）
- `renderAs="page"`：独立页面（直接路由 /naming、/question）

### 免费预览机制（v1.2）

**问题**：K线需要出生信息 + 高认知门槛 → 新用户流失率高。

**方案**：未登录用户可查看 K线预览版（简化分析），点击"查看四线"触发登录。

**流程**：
```
访问首页 → 点击命运K线 → KlineIntroPage（免费预览）
  → 预览 K线趋势图 → 点击"查看详细四线" → AuthModal（登录/注册）
  → 登录成功 → ResultPage（完整四线数据）
```

**数据存储**：ConsultPreview 表，24h 过期，IP+UA hash 匿名标识。
