# 天阶功法工作流 SOP

> **状态**: REFERENCE | **权威替代**: — | **最后核验**: 2026-06-05

---

## 1. 核心原则

### 1.1 One Bite At A Time

把大任务拆成最小可验收单元。饭要一口口吃，代码要一行行写。

**三不原则**：
- 不做"顺便"的事——每个改动只解决一个问题
- 不留"待优化"的口子——要么做完，要么不做
- 不跳过验收——没有验收的代码等于没写

### 1.2 颗粒度标尺

| 维度 | 标准 | 判定方式 |
|------|------|---------|
| 一次专注可完成 | 单次改动不超过 1 个文件或 1 个函数 | 改动前明确边界 |
| 10 分钟内可验证 | 改完即可跑测试或手动验证 | 改完立即验证 |
| 改动半径可控 | 不产生跨模块连锁修改 | 改动后无新增编译错误 |

**超标处理**：若任一维度超标，必须先拆分再动手。

## 2. 八阶段执行脊

完整工作流按以下 8 个阶段顺序执行，每阶段必须通过验收才能进入下一阶段。

```
Critical → Trace → Die → Fix → Verify → Evolve → Document → Close
 先止血    追踪     死点   最小修复  验证修复  进化升级   经验沉淀   分支收尾
```

### 2.1 Critical — 先止血、先定位

| 件 | 内容 |
|----|------|
| **动作** | 确认问题现象，判断是否阻断性故障；阻断则立即止血（回滚/降级/熔断） |
| **产出** | 问题描述 + 严重等级（P0/P1/P2/P3）+ 止血措施（如已执行） |
| **验收标准** | 现象可复现或已止血；问题范围已圈定 |
| **验证方法** | 复现步骤可稳定触发；止血后用户侧恢复正常 |
| **回滚方式** | 止血操作本身可逆（如 feature flag 关闭、版本回退） |
| **风险标记** | P0 止血可能引入新问题 → 止血后必须 Verify |

**严重等级定义**：

| 等级 | 定义 | 响应时间 | 示例 |
|------|------|---------|------|
| P0 | 服务不可用/数据丢失 | ≤15min | 支付失败、八字排盘全挂 |
| P1 | 核心功能受损 | ≤1h | 咨询结果为空、登录失败 |
| P2 | 非核心功能异常 | ≤4h | 海报生成失败、运势页样式错乱 |
| P3 | 体验优化/小问题 | ≤24h | 文案错误、动画不流畅 |

### 2.2 Trace — 数据流追踪

| 件 | 内容 |
|----|------|
| **动作** | 从用户输入到最终输出，逐层追踪数据流；标注每层输入/输出/转换逻辑 |
| **产出** | 数据流图（文本或图表）+ 异常节点标注 |
| **验收标准** | 数据流完整覆盖问题路径；异常节点已定位 |
| **验证方法** | 在异常节点处插入日志，确认数据与预期不符 |
| **回滚方式** | 移除调试日志（不提交调试代码） |
| **风险标记** | 数据流跨 3 个以上模块时，追踪可能遗漏中间态 |

**追踪模板**：

```
[用户输入] → [前端组件] → [API请求] → [Controller] → [Service] → [Agent/CalcEngine] → [LLM/DB] → [返回]
     ↑                                                              ↓
   预期值                                                        实际值
```

### 2.3 Die — 死点分析

| 件 | 内容 |
|----|------|
| **动作** | 在异常节点处定位根因；区分代码 Bug / 配置错误 / 数据问题 / 第三方故障 |
| **产出** | 根因分析报告（1-3 句话概括）+ 证据链 |
| **验收标准** | 根因唯一且可解释；修改根因可消除问题 |
| **验证方法** | 构造最小复现用例，确认修改根因后问题消失 |
| **回滚方式** | 无代码改动，无需回滚 |
| **风险标记** | 多根因并存时，优先修影响面最大的 |

**根因分类**：

| 类型 | 特征 | 典型示例 |
|------|------|---------|
| 代码 Bug | 逻辑错误、边界遗漏 | 八字排盘闰月处理遗漏 |
| 配置错误 | 环境变量、feature flag | LLM Provider API Key 过期 |
| 数据问题 | 脏数据、缺失数据 | 知识库 sourceId 缺失 |
| 第三方故障 | API 超时、服务降级 | MiniMax TTS 异步任务失败 |

### 2.4 Fix — 最小修复

| 件 | 内容 |
|----|------|
| **动作** | 只改根因，不做额外优化；改动量 ≤ 10 行为佳 |
| **产出** | 修复代码 + 对应测试用例 |
| **验收标准** | 修复代码只解决当前问题；不引入新问题；有测试覆盖 |
| **验证方法** | `npm run typecheck` 零错误 + `npm run test` 全通过 |
| **回滚方式** | `git revert` 单次提交 |
| **风险标记** | 修复涉及共享模块时，需检查下游影响 |

**最小修复原则**：

- [ ] 改动只针对根因，不夹带优化
- [ ] 改动行数 ≤ 10 行（超过需说明理由）
- [ ] 新增测试用例覆盖修复点
- [ ] 无硬编码、无 TODO/FIXME

### 2.5 Verify — 验证修复

| 件 | 内容 |
|----|------|
| **动作** | 运行完整验证链：类型检查 → 单元测试 → 集成测试 → 手动验证 |
| **产出** | 验证结果记录（通过/失败 + 截图/日志） |
| **验收标准** | 全部验证项通过；原问题不再复现 |
| **验证方法** | 按验证链逐项执行 |
| **回滚方式** | 验证失败则回滚修复，回到 Fix 阶段 |
| **风险标记** | 手动验证需覆盖边界场景，不能只验 happy path |

**验证链**：

| 步骤 | 命令/操作 | 通过标准 |
|------|----------|---------|
| 1. 类型检查 | `npm run typecheck` | 零错误 |
| 2. 代码规范 | `npm run lint` | 零错误 |
| 3. 单元测试 | `npm run test` | 全部通过 |
| 4. 集成验证 | 启动服务手动测试 | 核心流程无异常 |
| 5. 回归验证 | 确认相关功能未受影响 | 无新增 Bug |

### 2.6 Evolve — 进化升级

| 件 | 内容 |
|----|------|
| **动作** | 评估修复是否暴露架构问题；是否需要加固、重构或增加防护 |
| **产出** | 进化方案（如需）+ 优先级标注 |
| **验收标准** | 进化方案可独立验收；不阻塞当前修复上线 |
| **验证方法** | 进化方案单独走 Fix → Verify 流程 |
| **回滚方式** | 进化改动独立提交，可单独回滚 |
| **风险标记** | 进化改动不得与修复改动混在同一提交 |

**进化判断矩阵**：

| 条件 | 动作 |
|------|------|
| 同类问题第 2 次出现 | 加防护代码 + 补测试 |
| 同类问题第 3 次出现 | 重构模块 + 写入记忆系统 |
| 涉及跨模块影响 | 提升为架构优化任务，排入迭代 |

### 2.7 Document — 经验沉淀

| 件 | 内容 |
|----|------|
| **动作** | 将问题、根因、修复方案、经验教训写入记忆系统 |
| **产出** | 记忆系统条目（L1/L2/L3 对应层级） |
| **验收标准** | 条目可被后续会话检索到；内容完整可复用 |
| **验证方法** | 新会话中搜索关键词可命中该条目 |
| **回滚方式** | 删除错误条目 |
| **风险标记** | 不写等于白做 |

**记忆系统写入层级**：

| 层级 | 写入条件 | 示例 |
|------|---------|------|
| L0 工作记忆 | 当前任务进行中 | 今日修复进度 |
| L1 项目经验 | 项目内可复用经验 | 八字排盘闰月处理 SOP |
| L2 行为偏好 | 跨项目通用偏好 | 第三方 API 接入先建兼容矩阵 |
| L3 元规则 | 方法论级规则 | One Bite At A Time |

### 2.8 Close — 分支收尾

| 件 | 内容 |
|----|------|
| **动作** | 合并分支、清理临时资源、更新任务状态 |
| **产出** | 合并提交 + 任务状态更新 |
| **验收标准** | 分支已合并；临时资源已清理；任务状态已更新 |
| **验证方法** | 主分支 `npm run typecheck` + `npm run test` 全通过 |
| **回滚方式** | `git revert` 合并提交 |
| **风险标记** | 合并前必须 Verify 通过 |

**收尾检查清单**：

- [ ] `npm run typecheck` 零错误
- [ ] `npm run lint` 零错误
- [ ] `npm run test` 全部通过
- [ ] 无孤立 TODO/FIXME
- [ ] 经验已写入记忆系统
- [ ] 分支已合并到主分支
- [ ] 临时文件/调试代码已清理

## 3. 完成标准（全局门禁）

以下所有项必须通过，任务才算完成：

| # | 检查项 | 命令/操作 | 通过标准 |
|---|--------|----------|---------|
| 1 | 类型检查 | `npm run typecheck` | 零错误 |
| 2 | 代码规范 | `npm run lint` | 零错误 |
| 3 | 单元测试 | `npm run test` | 全部通过 |
| 4 | 孤立标记 | 全局搜索 TODO/FIXME | 无新增孤立项 |
| 5 | 经验沉淀 | 记忆系统写入 | 已写入对应层级 |

## 4. 流程速查表

| 阶段 | 核心动作 | 关键产出 | 不可跳过 |
|------|---------|---------|---------|
| Critical | 止血 + 定级 | 问题描述 + 严重等级 | ✅ |
| Trace | 数据流追踪 | 数据流图 + 异常节点 | ✅ |
| Die | 根因分析 | 根因 + 证据链 | ✅ |
| Fix | 最小修复 | 修复代码 + 测试 | ✅ |
| Verify | 验证修复 | 验证结果记录 | ✅ |
| Evolve | 进化评估 | 进化方案（如需） | 可跳过（无架构问题时） |
| Document | 经验沉淀 | 记忆系统条目 | ✅ |
| Close | 分支收尾 | 合并提交 + 状态更新 | ✅ |

## 5. 常见反模式（禁止）

| 反模式 | 危害 | 正确做法 |
|--------|------|---------|
| 跳过 Trace 直接 Fix | 修错地方，问题反复出现 | 先追踪再定位 |
| Fix 夹带优化 | 改动范围失控，引入新 Bug | 修复和优化分开提交 |
| 跳过 Verify 直接上线 | 修复不完整或引入回归 | 必须走完验证链 |
| 不写 Document | 同类问题重复踩坑 | 经验必须写入记忆系统 |
| 一次修多个问题 | 无法定位哪个修复有效 | One Bite At A Time |
| 颗粒度超标不拆分 | 改动半径失控 | 超标先拆分再动手 |
