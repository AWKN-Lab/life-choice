# LLM 输出风格修复计划

> 版本：v1 | 日期：2026-05-15 | 问题：输出风格偏学术报告，与参考案例差距大

---

## A. 问题诊断

### 参考案例风格特征（案例.txt / 子平a案例.txt / 命理案例.txt）

| 特征 | 参考案例示例 | 说明 |
|------|-------------|------|
| **结论先行** | "偏能赚钱，但不是轻松钱" | 开篇一句话定性，有记忆点 |
| **自然叙述** | "这课按广州真太阳时校正后..." | 讲故事，不堆章节标题 |
| **术语紧跟白话** | "重审课——要反复谈、反复改" | 每个术语后必须跟白话翻译 |
| **分段清晰** | 【判断依据】【当前风险】【建议动作】【时间窗口】【补充说明】 | 用方括号分段，每段不超过5条 |
| **风险具体到场景** | "账上热闹，净利不厚" | 不是"小心谨慎"，而是"流水容易先出来，真利润未必同步" |
| **建议可执行** | "先用1-2个主力SKU + 1个平台小规模试跑" | 带数字、带动作、带条件 |
| **时间窗口具体** | "5月上旬到6月上旬" | 不用干支年份，用现代日历表达 |
| **结尾金句** | "落一句最实在的话：这项目能做..." | 以人性化总结收尾 |
| **该做/不该做对仗** | "现在该做什么" + "现在不要做什么" | 对仗式建议 |

### 当前输出症状（以用户提供的"正印格带伤官"为例）

| 症状 | 表现 | 根因 |
|------|------|------|
| ❌ 无结论先行 | 开篇就是"深入推演分析"标题 | System prompt 未强制要求开篇一句话定性 |
| ❌ 学术章节标题 | "格局定性""古籍依据""事业断事" | 输出格式模板偏学术 |
| ❌ 术语无白话 | "正印格带伤官"无解释 | 缺少"术语→白话"的强制规则 |
| ❌ 时间窗口用干支 | "2027丁未年" | 未要求转换为现代日历 |
| ❌ 缺少结尾金句 | 无收尾 | 输出 Schema 缺少 closingLine 字段 |
| ❌ 缺少对仗建议 | 只有"行动方向"一条 | 缺少"该做/不该做"格式模板 |

### 根因定位

1. **liuren-analysis-prompt.md 已有好规则（结论先行、术语翻译、建议具体化），但只作用于六壬，子平 Agent 未同步**
2. **liuren-system-prompt.md 第89行 "用小红书风格或清晰分块风格呈现" 太模糊，LLM 无法执行**
3. **所有 prompt 缺少 few-shot 示例直接嵌入**——LLM 看不到"长什么样才算合格"
4. **输出 Schema 缺少 closingLine 字段**——LLM 不会主动写"落一句最实在的话"
5. **子平 Agent（ziping-system-prompt.md）整体风格偏 JSON 字段堆砌**，缺少自然叙述层

## B. 修复范围

### 本轮做（5 项）

1. **建立统一的"输出风格铁律"文档** — `shared/prompts/output-style-rules.md`
   - 结论先行模板
   - 术语→白话翻译规则
   - 分段格式规范（【】方括号分段）
   - 该做/不该做对仗模板
   - 结尾金句模板
   - 时间窗口表达规范（现代日历优先，干支可附后）

2. **重写子平（八字）Agent Prompt** — `ziping-system-prompt.md`
   - 删除学术章节标题模板
   - 注入参考案例风格要求
   - 嵌入 1 个完整 few-shot 示例（从命理案例.txt 提取）
   - 增加 closingLine 输出字段
   - 强制"术语→白话"规则

3. **增强六壬 Agent Prompt** — `liuren-analysis-prompt.md` + `liuren-system-prompt.md`
   - 替换第89行模糊的"小红书风格"为具体分段格式
   - 嵌入 1 个完整 few-shot 示例（从案例.txt 提取）
   - 增加 closingLine 输出字段
   - 强化"该做/不该做"对仗模板

4. **同步子平 Agent Service** — `ziping-agent.service.ts`
   - 加载新 prompt
   - Schema 增加 closingLine 字段
   - 确保 parseJsonResponse 能解析新字段

5. **同步六壬 Agent Service** — `liuren-agent.service.ts`
   - Schema 增加 closingLine 字段
   - 确保 analyze() 和 generateAnalysis() 返回 closingLine

### 本轮不做（5 项）

1. 不修改其他术数 Agent（奇门/六爻/紫微/取名）
2. 不修改前端展示逻辑
3. 不修改数据库 Schema
4. 不修改算法引擎计算逻辑
5. 不做大规模代码重构

## C. 分步清单

### Step 1｜建立统一输出风格铁律文档

**文件**：`shared/prompts/output-style-rules.md`（新建）

**内容模板**：

```markdown
# 输出风格铁律（所有术数 Agent 共享）

## 1. 结论先行
- 开篇第一句必须是一句话定性，有记忆点
- 格式：**加粗**的一句话，不超过30字
- 示例：
  ✅ "偏能赚钱，但不是轻松钱"
  ✅ "有财机，但不能贪快"
  ✅ "事多阻力，宜缓不宜急"
  ❌ "深入推演分析"（这是标题，不是结论）
  ❌ "正印格带伤官"（这是术语，不是结论）

## 2. 术语紧跟白话
- 每个术数术语后，必须紧跟一句白话解释
- 格式：术语——白话解释
- 示例：
  ✅ "重审课——这不是'一拍即合就顺跑'的象，而是要反复谈、反复改、边做边修正"
  ✅ "正印格——你天生有贵人运，但容易被现实利益动摇底线"
  ❌ "正印格带伤官，主聪明有才但易情绪化"（缺少白话转译）

## 3. 分段格式
- 用【】方括号作为段标题，不要用学术章节标题
- 固定分段：
  【结论】（一句话定性）
  【判断依据】（推导过程，3-5条）
  【当前风险】（具体场景，3-5条）
  【建议动作】（该做什么 / 不要做什么，对仗式）
  【时间窗口】（现代日历表达）
  【落一句最实在的话】（结尾金句）

## 4. 风险必须具体到场景
- ❌ "注意安全"
- ✅ "开车、出行、机械工具也要稳一点，巳申动，容易因急躁出小磕碰"
- ❌ "合作有风险"
- ✅ "合作方反复改条件、客户压价、家里人对钱的安排有意见"

## 5. 建议必须可执行
- ❌ "宜稳守"
- ✅ "先用1-2个主力SKU + 1个平台/1条渠道小规模试跑"
- ❌ "注意健康"
- ✅ "少熬夜、少酒局、少暴饮暴食。5月21日小满之后火气更盛"

## 6. 时间窗口用现代日历
- 优先用现代日历表达（月/日范围），干支可附后
- 示例：
  ✅ "5月上旬到6月上旬：最适合试跑、定模型"
  ✅ "5月1日-5月5日：收尾期，不要急着开新局"
  ❌ "2027丁未年"（只有干支，用户看不懂）

## 7. 结尾金句
- 每个回答必须以"落一句最实在的话"收尾
- 30字以内，像朋友直接说
- 示例：
  ✅ "这项目能做，也有钱路；但长期要做成事业，靠的是她自己控盘"
  ✅ "你只要不贪、不担保、不重仓，这个月反而能见到一笔钱"
```

**验收**：文件包含7条规则，每条含正反示例

```markdown
### 三、输出示例（必须模仿此风格）

【结论】
**偏能赚钱，但不是轻松钱。**

【判断依据】
- 这课按广州真太阳时校正后，折真太阳时约11:34，属午时；当日仍在春分—清明之间，用戌将。日干支为丙午日。
- 四课为巳上酉、酉上丑、午上戌、戌上寅。课中有一下贼上，属重审课——这不是"一拍即合就顺跑"的象，而是要反复谈、反复改、边做边修正。
- 三传为酉→丑→巳。这三支正好能成巳酉丑金局，而丙火日所克者为金，金就是财——所以这项目不是空谈，确有赚钱条件。
- 但初传酉发用，又带"财先现、利先动"的象，前段最容易出现的是：看起来有单、有流量、有收入，但净利被抽佣、投流、账期、合规成本吃掉。

【当前风险】
- 账上热闹，净利不厚：流水容易先出来，真利润未必同步。
- 合作边界不清：谁控货、谁投流、谁拿渠道、谁担售后与合规，后面会扯。

【建议动作】
现在该做什么：
- 先用1-2个主力SKU + 1个平台/1条渠道小规模试跑
- 先锁四件事：供货价、分润、投流预算、回款周期
现在不要做什么：
- 不要一开始就把这段合作定义成"长期绑定"
- 不要只看GMV、出单量，不看毛利和回款

【时间窗口】
- 5月上旬到6月上旬：最适合试跑、定模型、看第一轮真实利润
- 9月上旬到10月上旬：更容易看到"钱感"和放量机会

【落一句最实在的话】
**这项目能做，也有钱路；但长期要做成事业，靠的是自己控盘，不是一直靠别人。**
```

## G. 风险与回滚

- **风险**：Prompt 重写后 LLM 可能不遵守新格式 → **Plan B**：保留旧 prompt 文件备份，通过环境变量切换
- **风险**：closingLine 字段新增后前端未适配 → 前端不展示 closingLine 也不影响现有功能
- **回滚方式**：Git revert 6 个文件的修改，恢复原 prompt 文件
