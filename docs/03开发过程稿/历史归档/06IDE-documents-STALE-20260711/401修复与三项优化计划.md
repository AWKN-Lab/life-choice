# 401修复与三项优化计划

## 目标一句话
修复 401 Unauthorized 生产 bug + 三项用户体验优化（深入推演超时退积分、K线图死叉→下行、醒神早贴自然语言化）

## 本轮范围

### 本轮做（4项）
1. **深入推演超时退积分**：LLM 推演超时时自动退还已扣积分
2. **人生K线图死叉→下行**：中英文翻译文本替换
3. **醒神早贴自然语言化**：算法兜底输出的自然度优化
4. **深入推演生成失败退积分**：非超时的 LLM 失败也退还积分

### 本轮不做
- 不重构积分扣除时序（积分仍先扣后退，风险可控）
- 不修改 LLM System Prompt（醒神早贴 LLM 路径不做改动）
- 不修改前端渲染逻辑（只改后端数据输出和翻译文本）
- 不增加新的超时重试机制
- 不涉及金叉标签修改

## 约束与假设
- 后端 NestJS + Prisma + TypeScript
- 前端 React + Zustand + i18n
- 积分扣除在 `membership.service.ts:consumeAdminCredit()`
- 积分退还通过 `creditLedger` 表记录，`reason: 'refund_timeout'`
- 死叉标签在 `LifeKLineChart.tsx` 通过 `t('lifeKLine.crossDown')` 渲染

---

## B. 选定拆解视角
- **刀法选择**：模块边界（积分模块 / K线模块 / 醒神早贴模块，三个独立改动，互不干扰）
- 为什么选它：三个问题是三个独立模块，可以并行修复，不需要按数据流顺序

## C. 最小闭环（MVP-0）
- **积分退还 MVP-0**：在 `generateBreakthroughContent()` 超时 catch 中调用退还方法 → 写入 `creditLedger` → 前端仍显示 `noCharge: true`
- **死叉→下行 MVP-0**：改 2 个翻译文件，1 处代码标签名
- **醒神早贴自然语言 MVP-0**：优化 `buildAlgorithmicMorningFallback()` 的 overview 拼接逻辑 + 十神效果表模板

## D. 分步清单

---

### Step 1｜深入推演超时自动退积分

- **动作**：在 `consult.service.ts` 的 `generateBreakthroughContent()` 超时 catch 块中注入 `MembershipService`，调用退还积分方法
- **产出**：
  - 修改 `consult.service.ts`：注入 `MembershipService`，超时时调用 `refundCredit()`
  - 新增 `membership.service.ts`：`refundCredit(userId, moduleId, recordId, reason)` 方法
- **验收标准**：
  - 深入推演 LLM 超时后，`creditLedger` 表出现一条 `reason: 'refund_breakthrough_timeout'` 的记录
  - 用户积分余额恢复到扣减前的值
  - 非超时失败（如 LLM 返回异常 JSON）同样退还积分
- **验证方法**：
  - 模拟 LLM 超时 → 查看 `creditLedger` 表是否有退还记录
  - 查看用户 `creditBalance` 是否恢复
- **回滚方式**：删除 `refundCredit` 调用行，重新部署即可
- **风险标记**：中（涉及积分流水表写入）
- **Plan B**：如果 `MembershipService` 注入有问题，退化为在 consult.service 中直接写 Prisma 操作

---

### Step 2｜K线图"死叉"改为"下行"

- **动作**：修改中英文翻译文件中的 `crossDown` 键值，以及 `LifeKLineChart.tsx` 中的金叉/死叉映射逻辑
- **产出**：
  - 修改 `zh-CN/translation.json` L997：`"crossDown": "死叉"` → `"crossDown": "下行"`
  - 修改 `en/translation.json` L1141：`"crossDown": "Cross down"` → `"crossDown": "Downward"`
  - 修改 `LifeKLineChart.tsx` L498-505：金叉颜色仍为红色 `#ef4444`，下行颜色改为绿色 `#10b981`（保持不变，只改文字）
- **验收标准**：
  - K线图上交叉点标签显示"下行"而非"死叉"
  - 英文环境下显示"Downward"
  - 金叉标签不受影响
- **验证方法**：
  - 打开 K线图页面 → 确认交叉点标签文字为"下行"/"金叉"
  - 切换英文 → 确认显示"Downward"/"Golden cross"
- **回滚方式**：还原翻译文件中两个 key 的值为原始文本
- **风险标记**：低

---

### Step 3｜醒神早贴算法兜底自然语言化

- **动作**：优化 `buildAlgorithmicMorningFallback()` 中的输出文本，让算法兜底更自然
- **产出**：
  - 修改 `consult.service.ts` L1963-1974：`SHISHEN_EFFECT_MAP` 中的 tip/avoid 文本优化
  - 修改 `consult.service.ts` L1978-1995：`overview` 拼接逻辑改为更自然的叙事句式
  - 修改 `consult.service.ts` L1997-2003：`daily_tips` / `stop_doing` / `warnings` 文本优化
- **验收标准**：
  - 算法兜底输出的 overview 不再是指令式拼接（如"日主甲（木），今日丙午，食神当值..."），而是自然的叙事句
  - 每条 daily_tip 包含具体的可行动建议
  - stop_doing 每条都有明确的"为什么不要"
  - 文本读起来接近 LLM 生成的风格
- **验证方法**：
  - 模拟 LLM 不可用 → 查看 `buildAlgorithmicMorningFallback` 的输出
  - 逐字段对比新旧文本的自然度
- **回滚方式**：还原 `consult.service.ts` 中修改的文本模板
- **风险标记**：低

---

### Step 4｜验证所有改动（构建 + 回归）

- **动作**：构建前端 + 后端 TypeScript 编译检查
- **验收标准**：无编译错误，无类型错误
- **验证方法**：`npm run build` / `tsc --noEmit`
- **回滚方式**：git revert

## F. 最终验收（DoD）

### 用户可见体验
1. 深入推演超时后积分自动退还，不会白白扣分
2. K线图上不再出现"死叉"，改为"下行"
3. 醒神早贴在 LLM 不可用时也能输出自然流畅的文本

### 系统可观测性
1. `creditLedger` 表出现 `reason: 'refund_breakthrough_timeout'` 记录
2. 日志中出现 `[ConsultService]深入推演超时，已退还积分` 日志

### 稳定性
1. 后端 TypeScript 编译通过
2. 前端构建通过
3. 积分退还逻辑在异常场景下不抛错

### 回归清单
1. 深入推演正常生成 → 积分正常扣除
2. 深入推演超时 → 积分退还
3. 醒神早贴正常生成 → LLM 路径不受影响
4. 醒神早贴 LLM 不可用 → 算法兜底输出自然
5. K线图金叉标签正常显示
6. K线图下行标签正常显示
7. 英文环境翻译正常
