## 1. 变更背景

### 问题
生产日志出现两个 WARN（非阻塞）：
```
[LiurenAgent] 加载课体知识库失败 — 知识库文件缺失
⚠️ LLM 未配置，使用模板兜底逻辑 — .env 中 LLM API Key 可能需要更新
```

### 根因分析

PM2 启动服务时，`ecosystem.config.js` 中的环境变量优先级高于 `.env`，且 `pm2 save` 固化了旧的 dump。

旧配置：
```js
// ecosystem.config.js（修改前）
env: {
  DEFAULT_LLM_PROVIDER: "doubao",   // ← doubao 没有配 API key
  DOUBAO_API_KEY: ...,              // ← SENSENOVA 的 key 填在了 doubao 字段下
  DOUBAO_BASE_URL: "https://ark.cn-beijing.volces.com/api/v3",
}
```

系统实际走的是 `doubao`，而 doubao API key 为空，所有 Agent 进入"LLM 未配置"兜底逻辑。

### 修复方案
将 `ecosystem.config.js` 的 `env` 块重写，以 deepseek 为主 provider，minimax 为备。

## 2. 修改内容

### 2.1 ecosystem.config.js

文件路径：`/opt/awkn-life/awkn-life-backend/ecosystem.config.js`

**修改前**：doubao 无 key，所有 Agent 走兜底模板

**修改后**：
```js

  NODE_ENV: "production",
  PORT: 3002,
  DEEPSEEK_API_KEY: "sk-xxx",
  DEEPSEEK_BASE_URL: "https://api.deepseek.com",
  DEEPSEEK_MODEL: "deepseek-v4-flash",
  MINIMAX_API_KEY: "sk-xxx",
  MINIMAX_BASE_URL: "https://api.minimaxi.com/v1",
  MINIMAX_MODEL: "MiniMax-M2.7",
  DEFAULT_LLM_PROVIDER: "deepseek",
},
```

备份文件：`/opt/awkn-life/awkn-life-backend/ecosystem.config.js.bak`

### 2.2 PM2 操作

```bash
pm2 delete awkn-life-backend
cd /opt/awkn-life/awkn-life-backend
pm2 start ecosystem.config.js
pm2 save
```

删除旧实例再重建，是为了清除 PM2 dump 中的旧缓存，防止 `pm2 restart` 回滚到旧配置。

### 2.3 .env 清理

删除了以下过期的 SENSENOVA 配置行：
```
SENSENOVA_API_KEY=...
SENSENOVA_BASE_URL=...
SENSENOVA_MODEL=...
```

（不影响功能，SENSENOVA 未被设为 default provider）

### 未完全解决

#### WARN 1：LLM 未配置（Agent 层）
症状：日志显示 `default: deepseek` 且 `deepseek: true`，但各 Agent 仍报 `⚠️ LLM 未配置，使用模板兜底逻辑`。

根因判断：各 Agent 服务内部独立注入了 `LlmProvidersService` 实例，与 `LlmProvidersService` 初始化日志中的实例不共用。Agent 内部的 `isConfigured()` 调用链中可能存在路径差异（process.env 未正确读取，或实例注入方式不同）。

**下一步**：需读各 Agent 服务源码定位 `isConfigured()` 的实际调用路径，确认 env 注入时机。

#### WARN 2：课体知识库文件缺失
```
[LiurenAgent] 加载课体知识库失败 — 知识库文件缺失
```
与 LLM 配置无关，独立问题。需确认知识库文件在服务器上的正确路径。

## 4. LlmProvidersService 代码快照

文件：`apps/api-server/src/llm-providers/llm-providers.service.ts`

关键逻辑（constructor）：
```typescript
// 从 process.env 读取各 provider 的 key
this.providers.deepseek.apiKey = process.env.DEEPSEEK_API_KEY || volcengineKey;
this.providers.deepseek.baseUrl = process.env.DEEPSEEK_BASE_URL || ...;
this.providers.deepseek.model = process.env.DEEPSEEK_MODEL || 'deepseek-chat';
this.providers.minimax.apiKey = process.env.MINIMAX_API_KEY || ...;
this.providers.minimax.baseUrl = process.env.MINIMAX_BASE_URL || ...;
this.providers.minimax.model = process.env.MINIMAX_MODEL || 'MiniMax-M2.7';

// DEFAULT_LLM_PROVIDER 只认这五个
const envProvider = process.env.DEFAULT_LLM_PROVIDER;
this.defaultProvider = (['minimax','doubao','deepseek','sensenova','deepseek-direct'].includes(envProvider))
  ? envProvider : 'sensenova';
```

`isConfigured()` 逻辑（line 341-349）：
```typescript
isConfigured(): boolean {
  return !!(
    this.providers['deepseek-direct'].apiKey ||
    this.providers.sensenova.apiKey ||
    this.providers.doubao.apiKey ||
    this.providers.minimax.apiKey ||
    this.providers.deepseek.apiKey
  );
}
```
