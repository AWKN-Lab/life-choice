## 1. JWT 认证策略

### 文件路径

```
awkn-life-backend/apps/api-server/src/auth/strategies/jwt.strategy.ts
```

### 架构说明

基于 `@nestjs/passport` + `passport-jwt` 实现的 JWT 验证策略，挂载于 Passport 默认策略。

### 核心逻辑

```typescript
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(private readonly prisma: PrismaService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: process.env.JWT_SECRET,
    });
  }

  async validate(payload: JwtPayload) {
    const user = await this.prisma.user.findUnique({
      where: { id: payload.sub },
    });
    if (!user) throw new UnauthorizedException('用户不存在');
    return { id: user.id, email: user.email };
  }
}
```

### Payload 结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `sub` | `string` | 用户 ID（主键） |
| `iat` | `number?` | 签发时间 |
| `exp` | `number?` | 过期时间 |

### 配置参数

| 参数 | 环境变量 | 默认值 | 说明 |
|------|----------|--------|------|
| Secret | `JWT_SECRET` | — | **必填**，JWT 签名密钥 |
| ExpiresIn | `JWT_EXPIRES_IN` | `15m` | Access Token 有效期 |

### Token 提取方式

从 HTTP 请求头 `Authorization: Bearer <token>` 中提取。

## 2. Auth Guard

### 2.1 JwtAuthGuard

**文件路径**: `src/auth/guards/jwt-auth.guard.ts`

通用 JWT 认证守卫，继承 `@nestjs/passport` 的 `AuthGuard('jwt')`，用于保护需要登录才能访问的路由。

```typescript
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  canActivate(context: ExecutionContext) {
    return super.canActivate(context);
  }
}
```

**使用方式**: 在 Controller 方法上添加 `@UseGuards(JwtAuthGuard)` 装饰器。

### 2.2 AdminGuard

**文件路径**: `src/auth/guards/admin.guard.ts`

管理员权限守卫，实现 `CanActivate` 接口，在 JWT 验证通过后进一步检查用户是否为管理员。

```typescript
@Injectable()
export class AdminGuard implements CanActivate {
  constructor(private readonly prisma: PrismaService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const user = request.user;
    if (!user || !user.id) throw new ForbiddenException('需要登录才能访问');

    const dbUser = await this.prisma.user.findUnique({
      where: { id: user.id },
      select: { isAdmin: true },
    });
    if (!dbUser || !dbUser.isAdmin) throw new ForbiddenException('需要管理员权限才能访问');

    return true;
  }
}
```

### Guard 链路

```
请求 → JwtAuthGuard（验证Token有效性）→ AdminGuard（验证管理员权限）→ Controller
```

## 3. 用户注册/登录流程

### 文件路径

| 文件 | 路径 |
|------|------|
| AuthController | `src/auth/auth.controller.ts` |
| AuthService | `src/auth/auth.service.ts` |
| DTO | `src/auth/dto/index.ts` |

### API 端点

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| `POST` | `/auth/register` | 无 | 邮箱注册 |
| `POST` | `/auth/login` | 无 | 邮箱密码登录 |
| `POST` | `/auth/wx-login` | 无 | 微信登录 |
| `POST` | `/auth/refresh` | 无 | 刷新 Token |
| `POST` | `/auth/logout` | JWT | 登出 |

### 注册流程

```
客户端提交 RegisterDto → 检查邮箱/手机是否已存在
  → 已存在: 抛出 ConflictException
  → 不存在: bcrypt.hash(password, 10) → 创建 User 记录 → 生成双 Token → 返回
```

### 登录流程

```
客户端提交 LoginDto → 查找用户 → bcrypt.compare 验证密码
  → 失败: 抛出 UnauthorizedException
  → 成功: 生成双 Token → 合并匿名会话数据(如有) → 返回
```

### Token 双签机制

| Token 类型 | 有效期 | 存储位置 | 用途 |
|------------|--------|----------|------|
| Access Token | 15 分钟 | 客户端内存 | API 请求认证 |
| Refresh Token | 7 天 | 数据库 Session 表 | 无感刷新 Access Token |

每次生成 Token 时附加 `nonce`（时间戳+随机数）确保唯一性，Refresh Token 存入 `Session` 表并设置过期时间。

### 微信登录

通过 `wxOpenId` 查找或创建用户，支持 `sessionId` 参数合并匿名会话数据。

```typescript
interface AuthState {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  error: string | null;

  login: (email: string, password: string) => Promise<boolean>;
  register: (name: string, email: string, password: string, phone?: string) => Promise<boolean>;
  logout: () => Promise<void>;
  clearError: () => void;

}
```

### 核心特性

| 特性 | 实现方式 |
|------|----------|
| 持久化 | `zustand/middleware` 的 `persist`，存储键名 `auth-storage` |
| Hydration | `hasHydrated` 标志 + `onRehydrateStorage` 回调 |
| Mock 模式 | `VITE_USE_MOCK=true` 时使用本地模拟数据 |
| 管理员识别 | `ADMIN_ACCOUNTS` 列表自动识别管理员账号 |
| Token 一致性 | Hydration 后检查 `getAuthToken()`，无 Token 则清除认证状态 |

### 管理员积分体系

管理员用户使用积分制代替会员制：

- 每次解锁模块消耗积分（默认 1 积分/模块）
- 积分不足时自动充值 50 积分
- 所有积分变动记录到 `CreditLedger` 表
- 支持积分退还（如超时退款）

### 订单创建流程

```
CreateOrderDto → 创建 Order 记录(status=pending)
  → Stripe: 创建 Checkout Session → 返回支付链接
  → 微信: 生成支付 URL → 返回支付链接
  → 支付宝: 生成支付 URL → 返回支付链接
```

### Webhook 处理

Stripe Webhook 验证签名后处理事件：

| 事件 | 处理 |
|------|------|
| `checkout.session.completed` | 更新订单状态为 `paid` |
| `payment_intent.payment_failed` | 更新订单状态为 `failed` |

### 订单状态流转

```
pending → paid → refunded
         ↓
       failed
```
