# 咨询与算法引擎模块

## 模块总览

咨询与算法引擎是系统的核心计算层，负责问题路由分流、传统命理算法计算、结果拼装与追问处理。

| 子模块 | 后端路径 | 职责 |
|--------|----------|------|
| Consult 服务 | `src/consult/` | 问题路由、结果拼装、追问处理 |
| CalcEngine 模块 | `src/calc-engine/` | 八字/六壬/取名算法计算 |
| Knowledge Base | `src/knowledge-base/` | 算法知识库与计算器 |
| 算法数据文件 | `src/calc-engine/data/` | 静态命理数据 |

### 1.1 路由分流（RouterService）

**文件路径**: `src/consult/router.service.ts`

RouterService 是咨询入口的第一层决策，根据用户问题关键词计算各路由得分，选择最合适的分析方式。

#### 路由类型

| routeType | 说明 | 必填字段 |
|-----------|------|----------|
| `liuren` | 大六壬断事 | `askTime`, `askLocation` |
| `ziping` | 子平八字命理 | `birthDate`, `birthTime`, `birthPlace`, `gender` |
| `qimen` | 奇门遁甲 | `askTime` |
| `liuyao` | 六爻卜卦 | `askTime`, `hexagramCode`, `changingLines` |
| `ziwei` | 紫微斗数 | `birthDate`, `birthTime`, `gender` |
| `quming` | 取名 | `birthDate`, `birthTime`, `gender` |
| `clarify` | 追问澄清 | — |

#### 关键词分类与路由逻辑

| 关键词类别 | 示例 | 路由倾向 |
|------------|------|----------|
| event | 能不能、签约、投资、分手 | → `liuren` |
| trend | 今年运势、事业运、节律 | → `ziping` |
| vague | 迷茫、不知道、很焦虑 | → `clarify` |
| qimen | 奇门、遁甲、方位、择日 | → `qimen` |
| liuyao | 六爻、摇卦、起卦、卜卦 | → `liuyao` |
| ziwei | 紫微、斗数、命盘 | → `ziwei` |
| quming | 取名、起名、改名 | → `quming` |

#### 路由优先级

```
1. vague 得分 > 0.3 且为最高 → clarify（追问）
2. quming 得分 > 0 → quming（取名优先级最高）
3. liuyao > qimen 且 > event → liuyao
4. qimen > event → qimen
5. event >= trend → liuren
6. ziwei > 0 且 > trend*0.5 → ziwei
7. 默认 → ziping
```

#### 路由决策结构

```typescript
interface RouteDecision {
  routeType: 'liuren' | 'ziping' | 'clarify' | 'quming' | 'qimen' | 'liuyao' | 'ziwei';
  needClarify: boolean;
  requiredFields: string[];
  clarifyingQuestion?: string;
  nextStep: 'submit_info' | 'clarify';
}
```

### 1.2 结果拼装

ConsultService 协调 CalcEngine 和 LlmGateway 完成完整咨询流程：

```
用户问题 → RouterService.route() → 路由决策
  → CalcEngineService.calculate() → 算法计算结果
  → LlmGatewayService.generate() → LLM 语义分析
  → 结果拼装 + Paywall 模块标记 → 返回
```

### 1.3 追问处理

当路由结果为 `clarify` 时，系统生成追问引导用户明确问题方向：

- "您是想了解一件具体的事情，还是想看整体的运势趋势？"
- "如果是具体事，是关于哪个方面的？"

### 2.1 CalcEngineService

CalcEngineService 是算法计算的统一入口，根据 `routeType` 分发到对应的计算逻辑。

#### 输入结构

```typescript
interface CalcInput {
  routeType: 'liuren' | 'ziping' | 'quming' | 'qimen' | 'liuyao' | 'ziwei';
  question: string;
  askTime?: string;
  askLocation?: string;
  birthDate?: string;
  birthTime?: string;
  birthPlace?: string;
  gender?: string;
  timeUnknown?: boolean;
  hexagramCode?: string;
  surname?: string;
  givenName?: string;
  parentWish?: string;
  avoidChars?: string[];
}
```

#### 输出结构

```typescript
interface CalcResult {
  routeType: string;
  calcData: LiurenResult | any;
  summary_core: string;
  risk_tags: string[];
  action_tags: string[];
  time_window: string[];
  evidence_tags: string[];
}
```

#### 计算分发逻辑

| routeType | 调用方法 | 核心依赖 |
|-----------|----------|----------|
| `liuren` | `calculateLiuren()` | 本地六壬算法 |
| `ziping` | `calculateZiping()` | `BaziCalculatorWrapper` + `ZiweiAgentService` |
| `quming` | `calculateQuming()` | `calculateZiping()` + `NamingCalculator` |
| `qimen` | `calculateQimen()` | `QimenAgentService.paipan()` |
| `liuyao` | `calculateLiuyao()` | `LiuyaoAgentService.paipan()` |
| `ziwei` | `calculateZiwei()` | `ZiweiAgentService.paipan()` |

#### 子平八字计算特色

`calculateZiping()` 在计算八字的同时，会同步排紫微斗数盘，将紫微命盘摘要（`ziweiSummary`）嵌入到计算结果中，实现"八字+紫微"双盘联动。

### 资产字段体系

为解决用户行为追踪和画像构建问题，ConsultRecord 新增 6 个资产字段：

| 字段 | 类型 | 蛇形别名 | 说明 | 写入时机 |
|------|------|----------|------|----------|
| `sourceEntry` | String? | `source_entry` | 来源入口（kline/naming/question） | 前端写入 sessionStorage → API 写入 DB |
| `namingType` | String? | `naming_type` | 取名类型（宝宝取名/改名/起字号） | 取名流程提交时 |
| `namingPreferences` | String? | `naming_preferences` | 取名偏好（JSON 字符串） | 取名流程提交时 |
| `questionIntent` | String? | `question_intent` | 问事意图分类 | 问事流程提交时 |
| `unlockStatus` | String? | `unlock_status` | 解锁状态（preview/unlocked_full/unlocked_partial） | 创建记录时 + 解锁后更新 |
| `shareGenerated` | Boolean? | `share_generated` | 是否已生成分享卡片 | 分享卡片生成后 |

**数据流转链路**：
```
前端入口 → sessionStorage（snake_case）
  → API 请求 → DTO（camelCase + snake_case 双接收）
  → consult.service 创建记录时写入 DB
  → membership 解锁时更新 unlockStatus
```

**DTO 双驼峰设计**：ConsultAnalyzeDto 同时支持 camelCase 和 snake_case 字段名，确保前后端兼容：

```typescript
@IsOptional() @IsString()
sourceEntry?: string;
@IsOptional() @IsString()
source_entry?: string;
```

### 多引擎路由决策

Orchestrator 的 IntentRouterService 负责首次请求的引擎路由：

```
用户输入 → IntentRouter 分析意图
  ├── 六壬 → LiurenEngine
  ├── 子平八字 → ZipingEngine  
  ├── 奇门 → QimenEngine
  └── 六爻 → LiuyaoEngine
```

路由后的后续请求由各引擎内部处理，consult.service 通过 `inferSourceEntry()` 推断来源入口。

### ConsultPreview 免费预览机制

K线入口支持未登录免费预览：

| 字段 | 说明 |
|------|------|
| `ipIdentifier` | 匿名用户标识（未登录时用 IP+UA hash） |
| `previewData` | 缓存的预览结果 JSON |
| `previewType` | 预览类型（kline） |
| `expiresAt` | 过期时间（24h） |

**流程**：
1. 未登录用户访问 K线 → 创建 ConsultPreview 记录
2. 后端生成简化版分析结果（不含四线详细数据）
3. 前端 KlineIntroPage 展示预览 → 点击"查看四线"触发登录弹窗
