## C. 关键发现（4 条）

### C.1 LLM 风险等级系统性偏保守

**现象**：5 条预期 high/low 的 case，LLM 全部输出 medium：
- 预期 high → 输出 medium：gc-001/005/007（共 3 条，全部含"子午冲"或"伤官见官"高危信号）
- 预期 low → 输出 medium：gc-009/011（共 2 条，分别为大运转吉 + 立春 case）

**根因**：
1. LLM 对"羊刃+子午冲"等高危信号识别不够敏感，倾向给中间值
2. LLM 对"大运转水运夫星显"等吉象也不愿直接判 low，保持保守
3. 现有 prompt 没有强制"高危信号→high、无风险信号→low"的硬规则

**影响**：v2.0 严格判定下，5 条 case 因此 FAIL；v2.1 案例水准判定下不影响通过率，但需在 v0.2 prompt 中加强

**改进方向**（v0.2 候选）：
- 在 prompt-layers Layer 4 增加"风险等级判定规则"：含子午冲/伤官见官/羊刃激活→high；大运转吉+无明显冲克→low
- 或在 score-engine 增加风险等级计算规则，从 LLM 自评改为规则强制

### C.2 LLM 自评分集中在 55~70 区间，与 score-engine 规则算分有差异

**现象**：
- LLM 自评分：55(×4) / 65(×4) / 70(×2) / 55超区间(×1)，集中度极高
- score-engine 案例基准：61（用规则算分）

**根因**（已在 MVP-0 记录中确认）：
- LLM 评"风险程度"——看到水旺+子午冲+羊刃就给 55
- score-engine 评"格局完整度"——按 5 维度规则算 61
- 两者度量不同，是本质差异不是错误

**影响**：仅 gc-001 因 LLM 给 55（低于区间下限 60）严格判 FAIL；其他 10 条 LLM 自评分都在预期区间内

### C.3 LLM 倾向用正面建议而非"不"红线

**现象**：11 条 case 中，仅 gc-001 严格命中 1 条 expectedRedLine（"不共同贷款"），其他 10 条红线命中 0/2 ~ 0/3

**根因**：
1. LLM 倾向用"建议"、"尝试"、"行动"等正面表达
2. expectedRedLines 是从案例.docx 提取的硬红线（"不冲动领证"等），LLM 给的红线是命理逻辑衍生（"不在情绪激动时讨论敏感话题"等），内容合理但措辞不对齐

**影响**：v2.1 案例水准判定下，"给出了合理红线列表"即算通过；v0.2 可考虑在 prompt 中加入"红线必须以'不'开头"的硬约束

### C.4 calc-engine 真实排盘是"强工程"的关键装甲片

**现象**：
- gc-001/002/004/006/007/008/010（7 条 case 用同一 birthInfo 1989-08-20 06:00 male）：全部正确排出 壬子日柱 + 子午冲 + 丙午流年
- gc-005/009（2 条 case 用 1993-07-24 12:00 female）：正确排出 丙午日柱
- gc-011（立春 case 2024-02-04 17:00 male）：正确排出 戊戌日柱 + 甲辰年柱（确认立春 16:27 后进入甲辰年）

**根因**：MVP-0 修复时已确认——不接入 calc-engine 让 LLM 自己排盘会出错（日柱辛卯 vs 正确壬子），接入 calc-engine 后排盘 100% 正确

**影响**：11/11 case 排盘事实正确，验证了"弱 LLM + 强工程"命题的核心假设——把排盘事实从 LLM 中剥离，让 LLM 只做解读+表达
