# 人生决策宗师 v2 工程执行计划 — 三战线编排

> 版本：v2.0
> 日期：2026-06-14
> 状态：执行中
> 产品：张半山 · 命理咨询 AI
> 三大入口：问事 / 命运K线 / 取名

---

## 一、北极星指标

**问事深度推演完成率**

定义：用户进来 → 完成一次完整推演 → 愿意追问 → 付费升级

为什么是这个：
- 问事是核心入口，K线和取名是衍生
- 完成率低 = 产品没价值感，其他都是空谈
- 追问意愿 = 专家感的直接证据
- 付费 = 闭环验证

---

## 二、三战线总览

| 战线 | 北极星 | 时间 | 核心逻辑 |
|------|--------|------|---------|
| **P0 生产稳定** | 部署不炸、数据不丢、链路不断 | 立即 → 持续 | 没有稳定，一切白做 |
| **P1 收入主链路** | 问事完成率 + K线传播率 + 取名转化率 | Week 1-8 | 用户进来 → 觉得值 → 付费 |
| **P2 能力增强** | 记忆/回访/角色/IP | Week 8+ | 锦上添花，不抢主线 |

### 战线依赖关系

```
P0 ──→ P1（P0 未完成，P1 不可启动）
P1-1 ──→ P1-2 ──→ P1-3 ──→ P1-4（问事链路串行依赖）
P1-5 ──→ P1-6（质量基线先于付费感）
P1-7 ──→ P1-8 ──→ P1-9（K线链路串行依赖）
P1-10 ──→ P1-11 ──→ P1-12（取名链路串行依赖）
P1 全部通过 ──→ P2 启动
```

### 执行节奏

```
Week 1-2:  P0 生产稳定（全部完成）+ P1-1 L2 Pipeline 串联
Week 3-4:  P1-2 5层输出 + P1-3 身份注入 + P1-4 追问不断链
Week 5-6:  P1-5 LLM质量基线 + P1-6 付费升级 + P1-7~9 K线链路
Week 7-8:  P1-10~12 取名链路 + 转化漏斗埋点 + 3个真实用户验证
Week 8:    🔑 闭环验证：问事完成率 ≥ 60% + 首个付费用户
           → 通过 → 启动 P2
           → 不通过 → 回到 P1 迭代
```

## 四、P1 收入主链路

> 北极星：问事完成率 + K线传播率 + 取名转化率
> 原则：用户进来 → 觉得值 → 付费
> 时间：Week 1-8

### P1-1 L2 Pipeline 串联（5 天）

> 依赖：P0 全部完成
> 目标：用户输入 → L1 快速输出 → L2 深度推演 → 完整呈现

| 子任务 | 验收标准 | 耗时 | 状态 |
|--------|---------|------|------|
| L2 触发逻辑 | L1 输出后自动触发 L2，无需用户手动 | 1 天 | ☐ |
| L2 队列与状态 | L2 推演中显示进度，完成后通知 | 1 天 | ☐ |
| L2 输出合并 | L1 + L2 输出合并为完整推演结果 | 1 天 | ☐ |
| L2 超时与降级 | L2 超时 60s → 降级为 L1 结果 + 提示"深度推演中" | 1 天 | ☐ |
| 端到端验证 | 从输入到完整输出跑通 10 次 | 1 天 | ☐ |

**每日拆解：**

- Day 1：L2 触发逻辑 — L1 返回后自动调用 L2 endpoint，前端显示"正在深度推演"
- Day 2：L2 队列 — 后端用内存队列管理 L2 任务，前端轮询状态
- Day 3：输出合并 — 定义 L1+L2 合并 schema，前端渲染完整结果
- Day 4：超时降级 — L2 超时后返回 L1 结果 + 后台继续推演，完成后推送
- Day 5：端到端 — 10 次完整流程验证，记录每次耗时和成功率

**Week 2 检查点：L2 Pipeline 是否跑通？**
- 通 → 继续 P1-2
- 不通 → Plan B：L2 改为异步 + WebSocket 推送（+2 天）

### P1-2 5 层输出强制（3 天）

> 依赖：P1-1 完成
> 目标：每次推演必须输出 5 层，不允许缺层

| 层级 | 内容 | 缺失后果 |
|------|------|---------|
| L2-1 事实层 | 八字排盘 + 大运流年 | 无基础，后续无意义 |
| L2-2 解读层 | 格局 + 用神 + 旺衰 | 用户看不懂排盘 |
| L2-3 推演层 | 3 条推演路径 + 概率 | 没有推演 = 不是产品 |
| L2-4 建议层 | 每条路径对应行动建议 | 有分析无行动 = 废话 |
| L2-5 点睛层 | 一句话金句 + 追问引导 | 无记忆点，无追问动力 |

**每日拆解：**

- Day 1：定义 5 层输出 JSON schema，后端强制校验
- Day 2：prompt 工程确保 LLM 输出 5 层，缺层自动补全
- Day 3：前端 5 层渲染 + 缺层降级显示

### P1-3 身份 Prompt 注入（1 天）

> 依赖：P1-2 完成
> 目标：张半山身份感贯穿全流程

- [ ] 定义张半山身份 prompt 模板（姓名、风格、口头禅、禁忌）
- [ ] 注入到 L1/L2 所有 prompt 的 system message
- [ ] 验证：3 个用户盲测"像不像同一个大师"

### P1-4 追问不断链（3 天）

> 依赖：P1-3 完成
> 目标：推演结果 → 用户追问 → 上下文延续

| 子任务 | 验收标准 | 耗时 | 状态 |
|--------|---------|------|------|
| 追问上下文保持 | 追问时携带前文推演结果 | 1 天 | ☐ |
| 追问路由 | 追问走 L1 快速响应，不重新走 L2 | 0.5 天 | ☐ |
| 追问引导 | L2-5 点睛层自然引出追问 | 0.5 天 | ☐ |
| 追问付费墙 | 第 3 次追问触发付费提示 | 1 天 | ☐ |

### P1-5 LLM 质量基线（2 天）

> 依赖：P1-4 完成
> 目标：建立输出质量底线，低于基线自动重试

- [ ] 定义质量评分维度：完整性、准确性、一致性、身份感
- [ ] 实现 LLM 输出自检（prompt 内自评 + 重试）
- [ ] 建立质量日志，记录每次输出的评分
- [ ] 基线指标：完整性 ≥ 90%，身份感 ≥ 80%

### P1-6 付费升级感（2 天）

> 依赖：P1-5 完成
> 目标：免费用户觉得值 → 付费后觉得更值

- [ ] 免费版：L1 完整 + L2 前 2 层
- [ ] 付费版：L2 完整 5 层 + 追问无限 + 取名折扣
- [ ] 付费提示时机：追问第 3 次 / L2-3 层截断处 / 取名结果页
- [ ] 付费页面：3 档定价 + 对比表

### P1-7 K线 route_type 修复（0.5 天）

> 依赖：P0 完成
> 目标：K线入口正确路由到命运 K 线功能

- [ ] 修复 route_type 字段，确保 K 线入口走 K 线 pipeline
- [ ] 验证：从首页点 K 线 → 正确进入 K 线流程

### P1-8 K线分享卡片（2 天）

> 依赖：P1-7 完成
> 目标：K线结果可分享，分享卡片有传播力

- [ ] 设计分享卡片（命运 K 线图 + 一句话金句 + 二维码）
- [ ] 实现卡片生成（服务端渲染图片）
- [ ] 分享链路：微信分享 / 保存图片 / 复制链接
- [ ] 分享追踪：UTM 参数 + 来源标记

### P1-9 K线付费升级感（1 天）

> 依赖：P1-8 完成
> 目标：K线免费看概览 → 付费看详细

- [ ] 免费：K线概览图 + 3 个关键节点
- [ ] 付费：完整 K 线 + 每个节点详细解读 + 行动建议
- [ ] 付费提示：K线详情截断处

### P1-10 取名统一入口（0.5 天）

> 依赖：P0 完成
> 目标：取名从独立入口进入，不再混在问事里

- [ ] 首页增加取名入口
- [ ] 取名入口走独立 pipeline（不经过问事 L1/L2）
- [ ] 取名结果页与问事结果页视觉统一

### P1-11 取名全程对话化（2 天）

> 依赖：P1-10 完成
> 目标：取名不是填表，是对话

- [ ] 取名流程改为多轮对话（姓 → 性别 → 期望 → 风格 → 结果）
- [ ] 每轮对话有张半山的身份感输出
- [ ] 取名结果：3 个候选名 + 每个名的解读

### P1-12 取名 PDF 导出（0.5 天）

> 依赖：P1-11 完成
> 目标：取名结果可导出为 PDF

- [ ] PDF 模板：姓名解读 + 八字配合 + 五行分析
- [ ] 服务端生成 PDF + 下载链接
- [ ] 付费功能：免费用户预览，付费用户下载

### P1 转化漏斗埋点

> 贯穿 P1 全过程，每个任务完成后补充对应埋点

| 漏斗环节 | 埋点事件 | 目标 | 状态 |
|---------|---------|------|------|
| 首页 → 问事入口 | `funnel_home_to_ask` | ≥ 30% | ☐ |
| 问事入口 → 完成推演 | `funnel_ask_to_complete` | ≥ 60% | ☐ |
| 完成推演 → 追问 1 次 | `funnel_complete_to_followup` | ≥ 40% | ☐ |
| 追问 → 付费升级 | `funnel_followup_to_pay` | ≥ 5% | ☐ |
| 首页 → K线入口 | `funnel_home_to_kline` | ≥ 25% | ☐ |
| K线结果 → 分享 | `funnel_kline_to_share` | ≥ 10% | ☐ |

## 六、关键决策点

| 时点 | 检查点 | 决策 | 负责人 |
|------|--------|------|--------|
| **Week 2** | L2 Pipeline 串联是否跑通 | 不通 → Plan B（异步 + WebSocket） | 技术 |

### Week 8 闭环验证（硬门槛）

```
问事完成率 ≥ 60% ──→ 通过
                    └──→ 不通过 → 回 P1 迭代

首个付费用户 ──────→ 通过
                    └──→ 不通过 → 回 P1 迭代

两项都通过 ────────→ 启动 P2
任一不通过 ────────→ 回 P1 迭代（最多 2 轮，第 3 轮考虑转向）
```

## 七、风险与缓解

| 风险 | 概率 | 影响 | 缓解 | 触发条件 |
|------|------|------|------|---------|
| L2 推演耗时过长（>60s） | 高 | 用户流失 | 超时降级 + 后台继续 + 完成推送 | P1-1 验证时 |
| LLM 输出质量不稳定 | 高 | 用户不信任 | 自检 + 重试 + 人工抽检 | P1-5 基线测试时 |
| 付费意愿低于预期 | 中 | 商业模型不成立 | 调整免费/付费边界 + 增值服务 | Week 8 |
| K线分享率低于 5% | 中 | 获客成本高 | 优化卡片 + 增加社交货币感 | Week 6 |
| 取名转化率低于预期 | 中 | 收入缺口 | 取名与问事联动推荐 | Week 7 |
| C6 token 成本超标 | 中 | 利润被吃 | prompt 精简 + 缓存 + 换模型 | 每月 14 号 |
| 微信审核风险 | 低 | 上线延迟 | 提前准备审核材料 + 合规自查 | 提交审核前 |
