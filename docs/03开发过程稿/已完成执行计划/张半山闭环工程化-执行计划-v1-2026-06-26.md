## 一、5 件套（目标/产出/验收/验证/回滚）

### 目标
把"张半山智能体中枢 + 判例转换层"工程化为完整闭环，让弱 LLM（Kimi/MiniMax/GLM）通过 4 层架构兜底，稳定输出案例.docx 水准（10/10 能力）的判断报告。

### 产出
- 3 处主链代码修改（orchestrator 接入 + 判例注入 + 三法融合）
- 1 份数据扩展（bazi-classics.json 10→30 条 + translationTemplate）
- 1 套可证伪输出模板（分值/观察期/红线/三窗口）
- 1 套端到端回归测试（11 条 golden case）

### 验收（DoD）
- 弱 LLM 跑同一八字，输出含"夫妻宫正冲"而非原文古文
- 11 条 golden case 连续 3 次回归通过 ≥8 条
- 每个判断点可点击看 EvidencePacket + 古籍原文
- 跨会话用户更新资料能无缝衔接

### 验证
- `npx tsc --noEmit` 编译通过
- `npm test -- --testPathPattern=orchestrator` 64 个测试不挂
- `npm test -- --testPathPattern=generation-composer` 新增 spec 通过
- 端到端跑 1 次案例八字，输出含 translationTemplate.core

### 回滚
- 每步独立 git commit，失败时 `git checkout <commit>` 还原
- 数据扩展（Step 2）纯 JSON，可独立回滚
- 代码修改（Step 1/3/4）按模块独立 commit
