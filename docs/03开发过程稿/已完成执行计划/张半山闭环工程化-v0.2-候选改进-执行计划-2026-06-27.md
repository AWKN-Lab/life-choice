## A. 目标与边界

- **目标一句话**：通过 prompt 硬约束 + score-engine 规则强制，修复 LLM 输出"风险全 medium / 红线不用'不' / 分值集中 55/65/70"三个系统性问题
- **本轮做（3 项改动 + 1 项验证）**：
  1. Step 1: prompt-layers Layer 2 风险等级判定规则加强 + score-engine 规则强制覆盖
  2. Step 2: prompt-layers Layer 2 红线硬约束（必须以"不"开头）
  3. Step 3: prompt-layers Layer 2 分值参考基准注入 + 反集中约束
  4. Step 4: 重跑 gc-001/005/011 验证三项改动效果
- **本轮不做（4 项）**：
  1. 不重写 score-engine 打分规则（仅加 riskLevel 强制覆盖函数）
  2. 不改 prompt-layers 整体结构（仅 Layer 2 可证伪段局部加强）
  3. 不接入新的 LLM provider（doubao/kimi 仍欠费）
  4. 不做可证伪 5 段接入 generation-composer 主链（P2-3，v0.3+ 候选）
- **约束与假设（5 项）**：
  1. 不破坏现有主链（generation-composer + orchestrator）
  2. 每步必须可独立 git commit + 回滚
  3. 改动仅限 prompt-layers.ts + score-engine.ts（Layer 2 可证伪段 + riskLevel 函数）
  4. 验证用 minimax + deepseek-direct 各跑 gc-001/005/011（共 6 次）
  5. 验收标准：风险等级匹配率 ≥ 50%（6 次中 ≥ 3 次匹配预期）+ 红线"不"开头率 ≥ 80% + 分值离散度提升

## B. 选定拆解视角

- **刀法选择**：按数据流（输入 → 处理 → 输出 → 验证）
- **为什么选它**：
  1. prompt-layers 是处理层，LLM 输出是输出层，6 次重跑是验证层
  2. 数据流视角能清晰定位"约束是否生效"
  3. 每步改动后立即跑 1 次验证，10 分钟内可判定
