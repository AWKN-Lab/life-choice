## 一、RACI 定义

| 缩写 | 含义 | 角色数量建议 |
|------|------|------------|
| **R**esponsible | 执行者（实际干活） | 1~2 人 |
| **A**ccountable | 最终负责人（拍板/担责） | 唯一 1 人 |
| **C**onsulted | 需要咨询的人（双向沟通） | 0~3 人 |
| **I**nformed | 需要被告知的人（单向通知） | 多人 |

## 五、关键依赖关系

### 强依赖（必须串行）

```
P1-1 (头像) ──→ P1-2 (仪式动画)  // 头像是仪式动画的视觉元素
P1-4 (算法话术) ──→ P2-1 (蛐蛐提醒)  // 话术层是蛐蛐的载体
P2-2 (代价确认环) ──→ P3-1 (回访系统)  // 代价确认是回访触发条件
P4-1 (SSE) ──→ P4-2 (状态机) ──→ P4-3 (UI)  // 标准架构依赖链
```

### 并行通道

| 通道 | 可并行任务 | 理由 |
|------|----------|------|
| **前端通道 A** | P1-2、P2-2、P4-3 | 都是前端 UI 改造 |
| **前端通道 B** | P1-3、P1-4、P3-2 | 都是文案/前端轻改 |
| **后端通道 A** | P2-1、P3-1、P4-1 | 都是后端核心服务 |
| **后端通道 B** | P2-3、P3-2、P3-3、P4-2 | 都是后端扩展功能 |

### 跨通道阻塞

- P1-2（前端）需要 BE-1 配合提供 WS 进度事件 → 后端通道 A 必须先到位
- P3-1（回访系统）需要 OPS 提供定时任务基础设施 → 需提前 3 天确认
- P4-3（前端 UI）需要 P4-2 的 API 设计文档 → 文档先行 1 天

## 七、里程碑 Definition of Done

### P1 阶段 DOR（Definition of Ready）

- ✅ 14 任务 DOD 文档完成（M1 产出）
- ✅ P1 任务对应的设计稿/文案确认
- ✅ RACI 表全员对齐（本文档）

### P1 阶段 DOD（Definition of Done）

- ✅ P1-1/2/3/4 全部上线
- ✅ 4 项均通过对应 DOD 验收标准（M1）
- ✅ 灰度发布至 100%（M6 Feature Flag）
- ✅ 至少 100 个真实用户咨询走完完整流程
- ✅ 用户访谈 ≥10 人，验证"活人感"假设

### P2 阶段 DOD

- ✅ P2-1 蛐蛐渲染成功率 ≥95%
- ✅ P2-2 代价确认环降级路径被验证 ≥5 次
- ✅ P2-3 高风险场景脚本化回复 100% 覆盖设计清单
- ✅ 退款率较 P1 阶段下降 ≥20%

### P3 阶段 DOD

- ✅ P3-1 回访触发率 ≥30%（7 天后主动回访的用户占比）
- ✅ P3-2 记忆锚点召回准确率 ≥70%（人工抽样）
- ✅ P3-3 4 类用户分布合理（每类 ≥15%）
- ✅ 隐私合规审计通过（M3）

### P4 阶段 DOD

- ✅ SSE 连接稳定性 ≥99.5%（断线率 < 0.5%）
- ✅ 6 态状态机单元测试覆盖率 ≥90%
- ✅ 多轮对话 UI 用户满意度 ≥4/5
- ✅ SKILL 升级后，张半山口吻一致性人工 review ≥90%

## 八、变更管理

本表生效后，任何任务分配调整须满足：

1. **变更前**：在周会明确新 R/A/C/I
2. **变更后**：更新本表 + 同步给全员
3. **影响评估**：若涉及关键路径任务（P4 系列），必须 CEO 批准
