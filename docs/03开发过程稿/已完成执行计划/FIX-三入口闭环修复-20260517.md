## 2. 修复 B-01：取名 ResultPage 处理逻辑

### 2.1 问题根因

**路由类型不匹配**：
- `NamingFrontdesk.tsx` 第 62 行发送：`route_type: 'naming'`
- `ResultPage.tsx` 第 1047 行期望：`result.route_type === 'quming'`

导致 ResultPage 的 quming 分支不触发，取名结果无法展示。

### 2.2 修复方案

**步骤1**：✅ 已修改 `NamingFrontdesk.tsx` 第175行
```tsx
// 修改前
route_type: 'naming',

// 修改后
route_type: 'quming',
```

**步骤2**：同时修改第 170 行 question 构造逻辑，确保和 quming 路由期望的字段一致：
- 当前：`question: "我想为${surname || '宝宝'}取个好名字..."` 会作为 `data.question` 传给 ResultPage
- ResultPage 第 434-442 行期望 `data.birth_date`, `data.birth_hour`, `data.gender`, `data.naming_type`, `data.surname`

**关键文件**：
- `app/src/pages/NamingFrontdesk.tsx` — 第 174-189 行
- `app/src/pages/ResultPage.tsx` — 第 434-443 行（consultData 保存）、第 1047-1130 行（quming 渲染）

**验证方式**：
1. 启动前端 `npm run dev`
2. 从首页 → 取名 → 填写信息 → 提交
3. 验证结果页正确展示名字候选列表（InitialQumingAlgorithmPanel + RenameComparison 等），无白屏

## 3. 修复 A-01：命运K线四线数据为空

### 3.1 问题根因

`ResultPage.tsx` 第 2337-2454 行传入 `bundle.aspects` 的数据：

```tsx
career: { points: [], primarySignal: {...}, oneLiner: '', actionAdvice: '' },
wealth: { points: [], primarySignal: {...}, oneLiner: '', actionAdvice: '' },
relationship: { points: [], primarySignal: {...}, oneLiner: '', actionAdvice: '' },
```

`moduleContent.aspects?.career/wealth/relationship?.points` 全部为空。

根因：V2 四线派生逻辑未实现，backend 未返回 `aspects` 数据。

### 3.2 修复方案

**方案A（推荐）**：前端实现派生逻辑
1. 在 `app/src/lib/destinyKline/deriveDestinyKline.ts` 实现四线派生函数
2. 基于 `moduleContent.chartData`（overall 数据）和八字十神信息，派生 career/wealth/relationship 的 K 线数据点
3. 在 ResultPage 渲染 bundle 前，调用派生函数填充 aspects

**方案B**：后端实现
1. 后端 `calc_result.module_content.aspects` 包含完整的 career/wealth/relationship 数据
2. 前端只负责展示（当前 ResultPage 已经正确展示 structure，只是 data 为空）

**关键文件**：
- `app/src/lib/destinyKline/deriveDestinyKline.ts` — 待创建
- `app/src/pages/ResultPage.tsx` — 2337-2454 行 bundle 构造
- `app/src/types/lifekline.ts` — KLinePoint 类型

**验证方式**：
1. 启动前端和后端
2. 进入命运K线完整流程（需要年度会员）
3. 切换到「事业/财运/情感」tab，验证有数据且图表正常显示
