## A. 目标与边界

- **目标一句话**：用 11 条 golden case 验证"弱 LLM + 强工程"能稳定输出案例水准，并清理文档分值不一致问题
- **本轮做（4 项）**：
  1. Step 6 端到端 11 条 golden case 回归测试
  2. P2-1 文档分值与实际统一（66→61）
  3. P2-2 弱 LLM 输出 13 段完整性验证
  4. 复盘 + 状态写回执行计划 v1.1
- **本轮不做（4 项）**：
  1. P2-3 可证伪 5 段接入 generation-composer 主链（v0.2 候选）
  2. 重写 score-engine 打分规则（仅微调，不大改）
  3. 改 prompt-layers Layer 2 输出段数（保持 13 段，仅验证完整性）
  4. 接入新的命理算法（如紫微排盘重写）
- **约束与假设（6 项）**：
  1. 不破坏现有主链（generation-composer + orchestrator）
  2. 每步必须可独立 git commit + 回滚
  3. 弱 LLM 环境：Kimi / MiniMax / GLM（非 Claude/GPT-4）
  4. 端到端测试依赖真实 LLM 调用，有成本（控制在 50 次以内）
  5. 案例.docx 婚姻咨询为基准（66/100 区间，实际 61）
  6. golden case 半自动：人工跑一次记结果，不接 CI

---

## B. 选定拆解视角

- **刀法选择**：按数据流（输入 → 处理 → 输出 → 验证）
- **为什么选它**：
  1. golden case 是输入，LLM 是处理，13 段输出是输出，分值/完整性校验是验证
  2. 数据流视角能清晰定位"哪一段断了"（是 LLM 截断 / prompt 不清 / 校验过严）
  3. 端到端测试天然按数据流推进

## C. 最小闭环（MVP-0）

- **MVP-0 定义**：用 1 条 golden case（案例.docx 婚姻咨询）跑通"输入八字 → orchestrator 主链 → generation-composer 输出 → 校验 13 段完整性 + 分值区间"
- **MVP-0 的"临时项"清单**：
  - 临时：只验证 1 条 case，不跑 11 条
  - 临时：只验证完整性，不验证内容质量
  - 临时：不接 CI，手动跑
  - 移除条件：MVP-0 跑通后，扩展到 11 条 + 加内容质量校验

#### Step 3 卡点根因（2026-06-27 记录）

首次 MVP-0 跑 gc-001 + minimax，结果：
- ✅ 14 段完整（5层+4段三段式+5段可证伪）
- ✅ 分值 65（在区间 60-70）
- ❌ 关键词命中 1/7（仅"夫妻宫"命中，"子午冲"/"壬子"/"丙午"/"水火"/"规则"/"三个月"未命中）
- ❌ 风险等级 medium ≠ 预期 high

**根因定位**：mvp0-runner.ts 第 122 行只把出生信息作为文本传入 agentSummary，没有调用 calc-engine 做真实排盘。LLM 自己排盘错误（日柱辛卯），实际正确日柱为 **壬子**（用 BaziCalculatorWrapper 算法手算验证：1989-08-20 06:00，JDN=2447759，dayIdx=48 → 壬子）。

排盘错误导致 LLM 把"卯酉冲"当成主信号，未识别"子午冲"+"申子辰三合水局"+"丙午流年冲子"等关键信号，进而关键词全未命中、风险等级降为 medium。

#### Step 3.1｜接入 calc-engine 真实排盘（修复子步骤）

- **动作**：在 mvp0-runner.ts 中实例化 BaziCalculatorWrapper（纯计算类，无 NestJS DI 依赖），调 calculate() 算出真实排盘结果（四柱、五行、大运、刑冲合害、神煞），格式化为 agentSummary 文本传入 buildSystemPromptFromLayers
- **产出**：mvp0-runner.ts 修改 + 1 份 MVP-0 结果记录
- **验收标准**：
  - 通过：14 段完整 + 分值在区间 + 关键词命中 ≥2 + 风险等级 high
  - 失败：与原卡点相同
- **验证方法**：重跑 `npx ts-node mvp0-runner.ts gc-001 minimax`，读输出确认排盘为壬子日柱 + 关键词命中数
- **回滚方式**：`git checkout -- mvp0-runner.ts` 还原（不影响主链代码）
- **风险标记**：低（仅修改测试 runner，不触碰主链）
- **Plan B**：
  - 失败信号：排盘仍是辛卯 / 关键词仍 <2
  - 兜底方案：检查 BaziInput.month 是否需要 -1（JS month 0-11 vs 自然月 1-12）；若仍失败，回退到"只验格式不验内容"的弱验收
  - 保留证据：排盘结果 JSON + LLM 原始输出
