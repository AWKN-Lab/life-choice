# 输出格式迁移方案 V1.0

> 创建时间：2026-05-29
> 关联文档：spec.md（批判性分析 §1.5 50+ 字段断崖降级）、张半山-输出格式规范.md、张半山-SKILL.md
> 决策依据：GatewayOutput 50+ 字段逐项消费端分析

---

## 一、核心决策

**三段式输出为新增通道（通道 A），不替换现有 GatewayOutput（通道 B）。**

理由：
1. GatewayOutput 的 50+ 字段被 6+ 消费端使用，任何一个字段缺失都会导致功能断裂
2. 三段式是张半山人格化输出的载体，与结构化算法数据是互补关系，不是替代关系
3. 风险最小化：新增字段不会破坏现有功能

---

## 二、GatewayOutput 消费端全景

基于 [llm-gateway.service.ts](file:///C:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/AWKN-LABlife/awkn-life-backend/apps/api-server/src/llm-gateway/llm-gateway.service.ts#L36-L134) GatewayOutput 接口，逐字段分析消费端：

### 2.1 按消费模块分类

| 消费端 | 依赖字段 | 缺失影响 |
|--------|---------|---------|
| **ResultPage（核心结果页）** | `summary_line`, `summary_body`, `risks`, `actions`, `time_window`, `evidence_fold` | 页面主体内容丢失 |
| **命运K线** | `monthlyFortune`, `futureYearsRhythm`, `bestMonths`, `worstMonths`, `timeRhythm`, `daYunTheme`, `keyYearPhenomenon` | K线图表无数据 |
| **付费墙** | `paywall_modules` | 无法控制解锁逻辑 |
| **模块化分析** | `modules` (career/wealth/relationship/health), `modulesRating` | 四模块雷达图空白 |
| **决策审计** | `decisionAudit`, `mvpPlan`, `stopDoingList` | 审计面板空白 |
| **六壬专项** | `coreReasoning`, `keySignals`, `timeWindows`, `action_strategy`, `evidence_tags`, `课体`, `三传`, `counterpart_portrait`, `three_layer_advice`, `phased_calendar`, `scripts` | 六壬分析专项不可用 |
| **子平专项** | `character_portrait`, `patternType`, `strengthLevel`, `paiPanVerification`, `mingjuGuJia`, `classicAnalysis`, `label`, `ranking` | 子平分析专项不可用 |
| **取名专项** | `bazi`, `wuxing_analysis`, `xi_yong_shen`, `name_suggestions` | 取名功能完全失效 |
| **伴侣画像** | `partnerPortrait` | 感情分析缺失 |
| **守护指引** | `guardianGuidance` | 亲子/教育场景缺失 |
| **前端路由** | `route_type`, `record_id` | 前端无法确定渲染哪个模板 |

### 2.2 结论

**50+ 字段中没有任何一个是可以丢弃的。** 每个字段都有明确的消费端。三段式输出必须作为**追加字段**，而非替换字段。

## 三、双轨输出数据流

```
用户提问 → Orchestrator → LlmGatewayService.generate()
                              │
                              ├── [通道 B] 现有 6 Agent → GatewayOutput（50+ 字段）
                              │   不变，原样返回
                              │
                              └── [通道 A] 张半山调度 → 三段式输出（新增）
                                  追加到 GatewayOutput 的顶层字段
```

### 3.1 GatewayOutput 新增字段

```typescript
export interface GatewayOutput {
  // === 现有字段保持不变 ===
  summary_line: string;
  summary_body: string;
  // ... 其余 50+ 字段不变 ...

  // === 新增：张半山三段式输出（通道 A）===
  zhangbanshan_output?: ZhangbanshanOutput;
}

export interface ZhangbanshanOutput {
  judgment: string;           // 【我的判断】≤40 字
  cost: string;               // 【代价】≤100 字，以「这意味着……」开头
  reasoning_trace: string;    // 【推理轨迹】≤120 字，前端折叠
  primary_agent: string;      // 主调 Agent 名称
  secondary_agent?: string;   // 佐调 Agent 名称（可选）
  schedule_reason: string;    // 调度理由
  agent_consistency?: 'consistent' | 'undetermined' | 'conflicting';  // Agent 一致性
  arbitration_note?: string;  // 仲裁说明（仅 conflicting 时有值）
}
```

### 3.2 前端消费方式

```
┌─────────────────────────────────────────────┐
│          ResultPage（主结果页）               │
│                                              │
│  ┌──────────────────────────────────────┐   │
│  │  张半山总评（通道 A）                  │   │
│  │  zhangbanshan_output.judgment         │   │
│  │  zhangbanshan_output.cost             │   │
│  │  [展开推理轨迹 ▼]                     │   │
│  └──────────────────────────────────────┘   │
│                                              │
│  ┌──────────────────────────────────────┐   │
│  │  详细算法数据（通道 B，不变）           │   │
│  │  summary_body / risks / actions ...   │   │
│  │  命运K线 / 付费墙 / 模块分析 ...       │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

前端渲染逻辑（伪代码）：
```typescript
// ResultPage.tsx
if (result.zhangbanshan_output) {
  // 通道 A 存在 → 渲染张半山三段式
  renderZhangbanshanBlock(result.zhangbanshan_output);
  // 通道 B 仍然渲染（折叠或次要位置）
  renderAlgorithmDetails(result);
} else {
  // 通道 A 不存在 → 仅渲染通道 B（向后兼容）
  renderAlgorithmDetails(result);
}
```

### 3.3 向后兼容

- 老版本前端：`zhangbanshan_output` 为 `undefined`，前端忽略该字段，功能不受影响
- 新版本前端：检测 `zhangbanshan_output` 存在时优先展示三段式，否则 fallback 到现有渲染
- API 签名不变：`POST /consult/analyze` 和 `GET /consult/result/:recordId` 返回体仅新增字段

## 五、Agent 输出新增字段（confidence）

6 个 Agent prompt 追加 confidence 字段后，Agent 返回体变化：

### 5.1 Agent 输出扩展

```typescript
// 现有 Agent 输出（以 liuyao 为例）
interface LiuyaoOutput {
  summaryLine: string;
  summaryBody: string;
  risks: string[];
  actions: string[];
  timeWindow: string;
  evidenceFold: string;
  // ... existing fields ...
}

// 新增字段
interface LiuyaoOutputV2 extends LiuyaoOutput {
  confidence: '高' | '中' | '低';
  uncertainty_factors: string[];  // 最多 3 条
}
```

### 5.2 字段在 Gateway 中的传递

LlmGatewayService 的 `handle*()` 方法将 Agent 返回的 confidence 透传到 GatewayOutput：

```typescript
// llm-gateway.service.ts - handleLiuyao() 改造
return {
  summary_line: liuyaoResult.summaryLine,
  // ... existing fields ...
  
  // 新增：透传 confidence
  agent_confidence: liuyaoResult.confidence,
  agent_uncertainty_factors: liuyaoResult.uncertainty_factors,
};
```

### 5.3 confidence 字段消费方

| 消费方 | 用途 |
|--------|------|
| 张半山调度层 | 仲裁时对比多 Agent confidence |
| 张半山三段式 | 推理轨迹中引用「{Agent}的把握是{confidence}」 |
| 前端（可选） | 在算法详情区展示置信度标签 |

---

## 六、不做什么

- 不删除 GatewayOutput 任何现有字段
- 不改变现有 API 响应格式（仅追加）
- 不改变 consultRecord 数据库 schema（JSON 字段天然兼容）
- 不在 Phase B 就要求前端全部适配三段式（渐进增强）
