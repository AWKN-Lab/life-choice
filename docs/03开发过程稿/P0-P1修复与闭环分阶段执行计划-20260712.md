## A. 目标与边界

### 目标一句话（用户视角）

把"页面表现得像成熟产品但数据可信度/选择资产/商业验证没跟上"的项目，推进到"4 个 P0 全修 + git HEAD 可代表代码事实 + P01/P03 最小闭环 + CEO 看板可算 12 指标"，为 D+30 真实用户验证做准备。

### 本轮做（3-5 条）

1. 修复 4 个 P0（K线 /seed guard、取名 DTO 契约、静默伪默认、Math.random 评分）
2. 提交纪律收口（40 commits push + 125 files 分批 commit）
3. P01 K线数据契约（source/dataVersion/generatedAt）
4. P03 取名三表（NamingProject/NamingCandidate/NamingIteration）
5. CEO 12 指标看板 + 文档索引 6 列收口

### 本轮不做（3-5 条）

1. 不做 0-100 岁长期曲线实现（仅 PRD 裁决，留给 v0.2）
2. 不做品牌取名完整闭环（仅移除 Math.random + 加"待核验"提示，标实验能力）
3. 不做 Cloudflare WebSocket/SSL（P0-003 待用户操作，不在本计划）
4. 不做 Service Worker 缓存清理（P0-001 待用户硬刷新，不在本计划）
5. 不做 D+30 用户测试执行（仅准备计划与样本路径）

### 约束与假设（≤10）

1. 生产 Linux 服务器路径 `/opt/awkn-life/awkn-life-backend`，本地 Windows 开发
2. 生产 DB 是 SQLite WAL，`apps/api-server/prisma/dev.db`（1.1M, 18 User）
3. 生产跑 dist 产物，不是 git HEAD；本计划修复后必须重新构建 + scp 部署
4. 部署类操作（pm2 restart / scp / ssh 写服务器）按 L1 需确认
5. 不连生产 DB 写操作；schema 变更先本地验证再服务器 ALTER TABLE
6. 用户已授权"@天火 修复后续所有问题"（P1 报告 §0），本计划沿用此授权
7. 不做 git reset --hard / git clean -fd / rm -rf 等破坏性操作
8. 每个Phase结束写回本文件"复盘记录"段
9. 风险触发时暂停，不绕过 SAFETY GATE
10. typecheck/lint/test 全绿才是 Phase 通过的硬门禁
