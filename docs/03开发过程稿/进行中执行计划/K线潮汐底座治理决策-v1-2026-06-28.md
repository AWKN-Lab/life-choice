## 一、背景与问题

### 1.1 为什么停任务 2

大宗师.docx 已经开始"任务 2 开发"：新增 `getCurrentStage`、`get12DimStatus`，准备把 K线/潮汐注入问事、ResultPage、支付深推。

但《潮汐取证报告》静态取证证明：

- K线/潮汐底座还没到可以直接进 PRD / 进问事 / 进支付的状态
- "代码存在但不工作"：孤立 service 未被注册
- "两套平行 K线逻辑"：字段/算法/入口/调用方完全不同
- "接口实测未执行"：运行时真相未知
- 权威性等级：弱
- 可靠性等级：C

继续往前开发等于：在一个不稳定、不统一、不可验证的仪表盘上继续加功能。这会越做越乱。

### 1.2 当前真实现状一句话

K线不是"没有"，但不是稳定产品能力；12 维是真实存在，但解释权威不足；最大问题是两套 K线逻辑并存。

### 1.3 治理目标

只解决 4 个硬问题：

1. 两套 K线逻辑谁是 v0.1 权威源？
2. 孤立文件 `kline-decision.service.ts` / `tide-judgment.service.ts` 如何处理？
3. `/kline` `/tide` `/kline-tide/*` 接口是否真实稳定？
4. K线/潮汐结果如何具备版本号、输入快照、来源说明？

## 三、v0.1 权威源推荐

### 3.1 推荐

**推荐方案 A `src/kline-tide/kline-tide.service.ts` 作为 v0.1 唯一权威源。**

### 3.2 推荐理由

1. **前端 `/kline` `/tide` 页面已经在用方案 A**：useTidePackage hook 调用 `GET /kline-tide/package`，KlineChart 消费 `ParsedKlineBar` 字段（[KlinePage 行 168-170](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/pages/KlinePage.tsx#L168-L170) + [KlineChart 行 81-127](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/components/kline/KlineChart.tsx#L81-L127)）
2. **方案 A 与 12 维 StateSnapshot 同源**：都使用 Prisma + userId 体系，可形成"K线 + 潮汐"统一仪表盘（[schema.prisma KlineBar 行 734-760](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/awkn-life-backend/apps/api-server/prisma/schema.prisma#L734-L760) + [StateSnapshot 行 764-800](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/awkn-life-backend/apps/api-server/prisma/schema.prisma#L764-L800)）
3. **方案 A 有持久化**：可追溯、可复盘、可加版本号（[行 1417](file:///c:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/awkn-life-backend/apps/api-server/src/kline-tide/kline-tide.service.ts#L1417)）
4. **方案 A 有 REST 端点**：可独立测试、可独立验收、可被前端独立调用
5. **方案 B 无 DB 持久化、无独立端点**：每次内存生成，无法追溯历史，无法与 12 维 StateSnapshot 形成统一仪表盘

### 3.3 推荐方案的代价

| 代价 | 处理方式 |
|---|---|
| 方案 A 当前是"骨架 + mock"，权威性弱 | 见第六节最小修复清单，必须先治理再承诺 |
| 方案 A 的 4 因子算法比方案 B 的 15 因子粗糙 | v0.1 先用 4 因子，v0.2 评估是否吸收方案 B 的命理因子 |

### 3.4 方案 B 的处置

**不删除，但降级为"咨询链路内部辅助计算"，禁止作为 K线仪表盘的数据源。**

- 保留 `consult/generators/kline.generator.ts` 文件
- 保留 `consult.service.ts` 对它的调用（咨询结果页内部使用）
