# 人生决策宗师目录治理基线

> 日期：2026-07-11
> 范围：当前仓库
> 原则：保护开发现场、先治理入口、分批迁移、全程可回滚

## 一、当前判断

仓库已经具备完整产品、工程、知识库和部署体系，目录层仍保留多轮开发、恢复、设计和跨项目协作痕迹。

主要问题：

1. 根目录混有工程入口、临时文件、压缩包、PPT、跨项目资产和恢复工具。
2. `knowledge/` 约 11GB，原始资料、主索引、恢复数据库、备份与处理产物边界模糊。
3. `_recovered_assets/` 约 2.4GB，`dangling-probe-analysis/` 约 912MB，属于阶段性恢复资产。
4. `docs/` 已建立分类体系，仍有旧目录、重复入口和多版本并存。
5. Git 工作区存在多批尚未提交的代码、测试、知识数据和文档改动。

本轮采用软重构：建立唯一入口、目录契约、审计脚本、清理清单和 Git 忽略边界。现有业务代码与数据保持原位。

## 五、迁移批次

### Batch 0｜治理层

- 新增 `START-HERE.md`。
- 新增 `docs/00项目治理/`。
- 新增只读工作区审计脚本。
- 增补 Git 忽略规则。
- 更新仓库地图、入门文档和根目录命令。

### Batch 1｜根目录低风险项

处理对象：跨项目 PPT 与设计目录、构建压缩包、日志、测试输出、临时文件和一次性生成脚本。

### Batch 2｜运行时与备份隔离

处理对象：运行日志、后端备份、服务器备份、Chroma 备份和恢复分析产物。

### Batch 3｜知识库职责收口

- `knowledge/processed/` 作为当前生产索引与产物区。
- `knowledge/knowledge_base/metaphysics.db` 作为只读冷备。
- `knowledge/knowledge-base/` 中的可复用脚本后续归入 `scripts/knowledge/`。
- 路径调整前先生成引用报告和兼容方案。

### Batch 4｜旧项目归位

评审 `ziwei-doushu/`、`人生决策智能体/`、`人生决策宗师-体验升级/` 和前端更新包。每个目录标记为 ACTIVE、REFERENCE、ARCHIVED 或 EXTERNAL。

### Batch 5｜脚本治理

每个脚本明确输入、输出、影响范围、回滚方式和所属分类。高风险脚本增加 `--dry-run` 与路径校验。

## 六、目录契约

### 根目录

只允许项目入口、全仓规则、Monorepo 配置和一级领域目录。PPT、DOCX、ZIP、数据库、日志、临时脚本和一次性报告不得长期停留在根目录。

### Git

- 一个提交服务一个工程目标。
- 构建产物、日志、数据库、备份和恢复资产不进入 Git。
- 目录迁移与功能修改分开提交。
- 迁移前记录旧路径，迁移后更新引用与索引。

### 文档

- `docs/文档索引.md` 负责全量导航。
- ACTIVE 文档明确版本和更新时间。
- 历史材料进入 `03开发过程稿/`。
- 工程事实以源码、数据库、进程和接口验证为准。

### 知识资产

原始资料、处理产物、生产运行时、冷备数据库和资产台账分区管理。每个生产索引保留来源链、生成脚本、版本和验证报告。

## 七、验收标准

1. 根目录没有跨项目交付物、构建包、日志和临时文件。
2. `npm run audit:workspace` 不报告高风险根目录项。
3. 生产代码只从 `apps/AWKN-LABlife/` 启动。
4. 当前产品与工程事实各有一个唯一入口。
5. `knowledge/` 每个一级目录拥有明确职责。
6. Git 工作区中每项变更都能解释来源、目标和验收方式。
7. 迁移动作均有回滚路径。

## 八、本轮边界

本轮没有移动现有业务代码和知识数据。当前工作区存在大量未提交改动，同时知识数据库存在广泛路径引用。物理迁移应在独立批次中执行并逐项验收。
