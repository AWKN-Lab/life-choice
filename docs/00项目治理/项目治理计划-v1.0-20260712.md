## 一、治理结论

当前项目已经具备完整产品雏形、生产代码、知识服务、工程文档和多条产品闭环能力。工作区同时积累了大量功能开发、知识数据、文档迁移和工程治理改动，提交边界与生产边界需要集中收口。

本轮治理完成三项结果：

1. **恢复工程可控性**：每一项改动都有批次、目标、验证命令、回滚方式和责任边界。
2. **恢复发布安全性**：Schema、锁文件、构建资产、知识索引和生产配置进入强制闸门。
3. **建立长期运行机制**：新需求、新代码、新文档和 AI 生成内容按统一规则进入项目。

治理期间允许继续开发。所有开发必须进入明确批次，禁止跨批次混合提交。当前后端存在 5 个硬阻断项，在清零前禁止生产发布。

## 四、治理原则

1. **一批一目标**：一次提交、一次评审、一次发布只服务一个清晰目标。
2. **生产事实优先**：生产代码、生产数据库、生产进程和实际接口状态拥有最高工程优先级。
3. **证据进入结论**：测试结果、命令输出、Blob 哈希、数据库取证和发布记录进入治理文档。
4. **高风险独立处理**：Schema、迁移、锁文件、依赖版本、构建链和资产清单单独成批。
5. **全程可回滚**：涉及删除、移动、数据库和部署的动作必须先写恢复路径。
6. **共享文件整体收口**：状态机、总路由、多语言文件、总索引等共享热点按完整功能链提交。
7. **文档服务执行**：文档要提供路径、状态、动作、验收和责任边界。
8. **自动审计先行**：可以交给脚本判断的内容，不依赖人工记忆。
9. **根目录保持克制**：根目录只承载工程入口、规则、配置和一级领域目录。
10. **历史资料保留来源链**：历史过程进入归档区，ACTIVE 主线保持清晰。

- 未核验的批量删除。
- 功能开发与目录迁移混合提交。
- Schema 与锁文件夹带进入普通功能提交。
- 自动格式化覆盖全部仓库。

## 十、文档治理

### 文档状态

| 状态 | 使用规则 |
|---|---|
| ACTIVE | 当前执行和决策依据 |
| PROPOSED | 待评审方案，禁止直接视为生产规则 |
| REFERENCE | 参考资料，不能覆盖当前基线 |
| DEPRECATED | 已停止使用，保留历史链接 |

### 文档层级

1. `START-HERE.md`：项目入口。

5. 模块文档：API、数据库、部署、测试。
6. 质量报告：验收与取证。
7. 历史归档：过程和旧方案。

### 更新规则

- 代码实现完成后更新工程文档。
- 生产部署完成后更新生产状态。
- 方案讨论阶段使用 `PROPOSED`。
- 旧文档迁移后更新索引和旧路径引用。
- 同一主题保留一个 ACTIVE 主入口。

## 十二、发布治理

### 发布前闸门

```bash
npm run audit:batches
npm run audit:backend
npm run audit:workspace
npm run typecheck
npm run test
npm run build
```

发布前必须确认：

- 后端 BLOCK = 0。
- 当前发布批次边界明确。
- 数据库备份完成。
- 迁移在副本验证通过。
- 构建资产校验通过。
- 环境变量清单完整。
- 冒烟测试通过。
- 回滚版本和命令已记录。

### 发布后验证

- 健康接口连续通过。
- 核心问事、取名、K 线、用户资产入口可用。
- 日志无新增高频异常。
- 数据库迁移状态同步。
- 前端错误采集正常。
- 经营指标能够记录新版本数据。

### 回滚触发

满足任一条件立即回滚：

- 核心接口不可用。
- Prisma 字段或表错误持续出现。
- 必需知识资产缺失。
- 用户咨询记录无法落库。
- 新版本错误率超过发布前基线。
- 数据迁移出现不可解释差异。

## 十三、AI 协作治理

所有 AI 编程助手进入项目后按以下顺序读取：

1. `START-HERE.md`
2. `docs/00项目治理/项目治理计划-v1.0-20260712.md`
3. `docs/00项目治理/提交批次计划-20260711.md`
4. `docs/文档索引.md`
5. 当前模块 PRD
6. 当前生产工程基线
7. 目标源码与测试

AI 开始修改前必须输出：

- 当前批次。
- 目标文件。
- 计划修改范围。
- 禁止触碰范围。
- 验证方法。

AI 完成修改后必须输出：

- 实际修改文件。
- 测试结果。
- 剩余风险。
- 文档同步情况。
- 回滚方式。

禁止 AI 自行执行全仓重置、全仓格式化、生产数据库迁移和高风险物理删除。

## 十四、运行节奏

### 每日开始

```bash
git status --short
npm run audit:batches
npm run audit:backend
```

确认：

- 今天只推进一个主批次。
- 暂存区只包含目标批次。
- 后端 BLOCK 数量没有扩大。

### 每日结束

- 保存测试结果。
- 更新批次状态。
- 记录新增风险。
- 清空无效暂存。
- 保留可恢复工作点。

### 每周治理评审

固定检查：

1. 当前活动批次数量。
2. 后端 BLOCK 与 WARN。
3. 未索引 ACTIVE 文档。
4. 根目录违规资产。
5. 知识索引版本。
6. 发布与回滚记录。
7. 产品闭环指标。
8. 下周冻结范围。
