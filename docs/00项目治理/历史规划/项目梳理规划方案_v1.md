## 二、世界先进项目管理方法论参考

### 2.1 Diátaxis 文档框架（核心分类法）

> 来源：[diataxis.fr](https://diataxis.fr/)，被 Django、Gatsby、Cloudflare 采用

四分类法：
- **Tutorial（学习）**：入门教程，引导新手
- **How-to（操作）**：解决具体问题的步骤
- **Reference（参考）**：API、字段、配置的权威清单
- **Explanation（解释）**：架构决策、设计原理、复盘

### 2.2 Atlassian Confluence Space 模型

> 来源：Atlassian 官方文档结构最佳实践

按"空间 → 页面树"组织：
- **产品空间**：PRD、需求、路线图
- **工程空间**：API、DB、部署、测试
- **运营空间**：复盘、事故、经验
- **归档空间**：过期版本、历史决策

### 2.3 Shape Up 版本切片（Basecamp）

> 来源：*Shape Up* by Ryan Singer

- **Pitch**：问题定义 + 方案提案
- **Bet**：决策是否做
- **Build**：6 周闭环
- **Ship**：上线验收

对应文档切片：每个版本有独立的 PRD → 工程文档 → 复盘，版本结束后归档。

### 2.4 Docs as Code

> 来源：Google SRE、GitLab Flow

- 文档随代码版本化（Git）
- 文档与代码同 PR 提交
- CI 检查文档完整性
- 单一真相源（Single Source of Truth）

### 2.5 综合应用方案

## 六、分步执行计划（一步一验收）

### A. 目标与边界

- **目标一句话**：把人生决策宗师项目的文档、组件、经验按世界先进项目管理标准归位，让当前生效文档一眼可找、历史文档不污染、可复用资产跨项目可用
- **本轮做**：
  1. 创建目标目录结构（01-05）
  2. 迁移 docs 根目录散落文件
  3. 合并三个 engineering 目录
  4. 归档 legacy 到 03
  5. 迁徙 10 个通用组件到公用组件库
  6. 沉淀 5 份经验到记忆系统
- **本轮不做**：
  1. 不删除任何文件（只移动）
  2. 不修改代码逻辑
  3. 不动 knowledge/ 知识库目录
  4. 不动 references/ 旧项目目录
  5. 不动 apps/ 代码（仅复制组件到公用组件库）
- **约束**：
  1. 每步必须 git commit 备份
  2. 每步必须可独立验证
  3. 每步必须可回滚
  4. 涉及删除前必须确认
  5. 中文路径注意转义

### B. 选定拆解视角

- **刀法选择**：模块边界（前端/后端/文档/组件/经验）
- **理由**：本任务是"归位"而非"开发"，按资产类型切刀最清晰；不同资产类型互不依赖，可并行验证

### C. 最小闭环（MVP-0）

- **MVP-0 定义**：创建 5 个目标目录 + 迁移 1 个文件验证流程跑通
- **临时项**：无（目录创建即正式）
