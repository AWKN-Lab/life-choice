## 1. 目标与边界

### 目标一句话

在 D+30 前完成 20 人真实用户验证，确认宝宝取名首发产品是否值得继续投入，并跑通 1 笔真实订单验证付费路径。

### 本轮做（3-5 条）

1. 招募 20 名真实目标用户（三入口各 7 人，命名 6 人额外覆盖）
2. 三入口测试任务清单（K线/问事/取名）
3. 数据收集模板（基于 Validation Kit）
4. 继续/停止/转向判定规则
5. 1 笔真实订单验证路径（宝宝取名 PDF 导出付费）

### 本轮不做（3-5 条）

1. 不做大规模推广（仅 20 人样本）
2. 不做 A/B 测试（样本量不足）
3. 不做品牌取名完整验证（仅标实验能力）
4. 不做 0-100 岁长期曲线验证（v0.2 范围）
5. 不做付费会员体系完整上线（仅验证单笔订单）

### 约束与假设（≤10）

1. 样本必须是真实目标用户（准父母/父母/成人改名需求者），不是亲友捧场
2. 每次验证必须有证据记录（截图/录音/问卷）
3. 任何结论都必须落到：继续 / 停止 / 转向
4. 若样本不足 5 人某入口，结论只能为"待验证"
5. 测试期间产品不做大改动，只修 P0 BUG
6. 1 笔真实订单必须走完整付费链路（下单→支付→交付）
7. 用户数据按隐私框架处理，测试后提供删除选项
8. 测试结果写入本文档"复盘记录"段

## 2. 20 人样本获取路径

### 样本结构

| 入口 | 样本数 | 目标人群 | 获取路径 |
|------|--------|---------|---------|
| 宝宝取名（首发主产品） | 7 | 准父母（孕期 28-40 周）/ 新手父母（宝宝 < 6 月） | 朋友圈精准触达 + 妈妈群 + 小红书取名帖 |
| 问事 | 7 | 25-45 岁有具体决策困惑者 | 玄学社群（豆瓣/知乎命理板块）+ 朋友圈 |
| 命运K线 | 6 | 25-40 岁对"人生趋势"感兴趣者 | 朋友圈 + 知识星球 + 玄学社群 |

### 获取渠道优先级

1. **朋友圈精准触达**（优先）：发"我在做一个取名/问事产品，需要 20 个真实用户测试，免费体验 + 1 对 1 反馈"——效率最高，信任度最高
2. **妈妈群/育儿群**（针对宝宝取名）：社群渗透，转化率高
3. **小红书取名帖**：自然流量，但需筛选真实需求
4. **玄学社群**（豆瓣/知乎命理板块）：问事 + K线目标用户
5. **知识星球**：付费意愿高，适合 K 线验证

### 招募话术模板

```
我在做一个【人生决策宗师】产品，其中宝宝取名功能需要 20 位真实用户测试。
你是准父母或新手父母吗？如果是，免费帮你取 1 次名，只需要：
1. 完成取名流程（约 10 分钟）
2. 填写 1 份简短反馈问卷（约 5 分钟）
3. （可选）接受 15 分钟电话访谈

名额有限，先到先得。如果你身边有需要的朋友，也欢迎转发。
```

## 4. 数据收集模板（基于 Validation Kit）

### 4.1 用户基本信息

| 字段 | 说明 |
|------|------|
| 用户编号 | B01-B07 / Q01-Q07 / K01-K06 |
| 入口类型 | 宝宝取名 / 问事 / 命运K线 |
| 人群特征 | 年龄段、身份（准父母/父母/职场人等） |
| 真实场景 | 一句话描述为什么来测试 |
| 现有解决方式 | 之前怎么取名/问事/看运势 |

### 4.2 行为数据（自动采集）

| 字段 | 说明 |
|------|------|
| 入口到达时间 | 用户从哪里来、几点到达 |
| 任务完成数 | B1-B8 / Q1-Q5 / K1-K5 完成几个 |
| 关键步骤耗时 | 生成耗时、付费决策耗时 |
| 错误发生次数 | 400/500/前端报错 |
| 收藏/淘汰数 | 取名交互数据 |

### 4.3 主观反馈问卷（10 题）

1. 整体体验打分（1-5 分）
2. 最喜欢的 1 点是什么？
3. 最不喜欢的 1 点是什么？
4. 结果可信度打分（1-5 分）
5. 是否愿意推荐给朋友？（是/否，原因）
6. 是否愿意付费？（是/否，底线价格）
7. 觉得哪里最绕/最难用？
8. 如果只能保留 1 个功能，保留哪个？
9. 如果只能砍掉 1 个功能，砍哪个？
10. 今天有最简版本，愿意再试用 1 次吗？

### 4.4 深度访谈（可选，15 分钟）

- 最近一次遇到这个问题是什么时候？
- 现在怎么解决？哪里最难受？
- 这个产品解决你的问题了吗？差在哪？
- 什么情况下愿意付费？
- 做到什么程度会推荐？

## 5. 继续/停止/转向判定规则

### 5.1 继续（Go）

满足 ≥2 条：
- G1：≥60% 用户完成核心任务（B3/Q2/K3）
- G2：≥60% 愿意再试用 1 次
- G3：≥40% 愿意付费
- G4：≥70% 能理解产品在做什么
- G5：1 笔真实订单支付成功

### 5.2 停止（Stop）

满足任一条：
- S1：大多数人不觉得这是问题
- S2：已有更简单替代且很满意
- S3：关键代价无法接受（价格/隐私/操作复杂度）
- S4：1 笔真实订单支付链路跑不通

### 5.3 转向（Pivot）

满足任一条：
- P1：痛点成立但方案不对（用户要的不是这个）
- P2：愿意用但不愿意付费
- P3：愿意付费但不愿意授权/给资料
- P4：宝宝取名不成立，但成人改名或问事成立

### 5.4 判定时间点

- D+7：初步反馈（10 人完成）
- D+14：中期判定（15 人完成，决定是否继续招募）
- D+30：最终判定（20 人完成 + 1 笔订单验证）

## 6. 1 笔真实订单验证路径

### 6.1 路径设计

```
用户完成取名 → 查看 PDF 预览（带水印）→ 点击"导出完整 PDF"→
跳转支付页 → 微信/支付宝支付 → 支付成功 → 下载完整 PDF（无水印）
```

### 6.2 验证点

| 验证点 | 期望结果 | 数据采集 |
|--------|---------|---------|
| PDF 预览可见 | 带水印的 PDF 预览正常显示 | 预览打开率 |
| 付费按钮可见 | "导出完整 PDF"按钮清晰可见 | 按钮曝光率 |
| 支付链路畅通 | 微信/支付宝支付成功回调 | 支付成功率 |
| PDF 下载成功 | 支付后可下载无水印 PDF | 下载成功率 |
| 资金到账确认 | 后台可查订单 + 资金到账 | 订单记录 |

### 6.3 兜底方案

- 若支付链路不通：降级为"扫码转账 + 人工发 PDF"，验证付费意愿即可
- 若 PDF 生成失败：降级为"网页版完整内容 + 截图工具"
- 若用户不愿付费：提供免费完整 PDF，但收集"为什么不愿付费"原因
