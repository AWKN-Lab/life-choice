## 1. 文档目的

本文件把 CEO 目标从“方向”收敛为“经营动作”。

它回答 5 个问题：

1. 接下来一个季度，真正要打赢的仗是什么。
2. 哪些指标说明产品在变好，哪些指标说明项目在失控。
3. `命运K线 / 问事 / 取名` 三条线分别要承担什么经营责任。
4. 技术、内容、模型、数据资产如何服务经营目标。
5. CEO 周会、双周复盘、月度经营会应看哪些统一口径。

---

## 2. 本季度 CEO 总目标

本季度不是继续铺功能，而是完成以下 3 个经营结果：

1. 把“命运K线、问事、取名”三入口做成真实可转化的主闭环。
2. 把“咨询记录、命盘、追问、深推、回看”真正沉淀成后台资产。
3. 把 LLM 输出从“能生成”提升到“像真人顾问、能支撑复访与付费”。

对应一句话：

`先把产品做成能稳定成交、能持续回访、能沉淀资产的系统，再谈功能扩张。`

## 3. 季度 OKR

## O1. 跑通三大入口的商业闭环

### KR

1. 命运K线生成链路成功率达到 `>= 95%`
2. 问事首问完成率达到 `>= 70%`
3. 问事深入推演点击率达到 `>= 20%`
4. 取名完整流程完成率达到 `>= 60%`
5. 三入口结果页到会员页/积分页的有效转化率达到 `>= 8%`

### 关键动作

1. 收敛首页入口层级，避免用户先被导航页劝退。
2. 问事与取名统一在对话前台收信息，不再依赖割裂弹窗。
3. 命运K线输入步骤压缩，减少无效表单。
4. 深推失败不整页刷新，保留上下文和重试能力。
5. 免费与付费边界前置说清，避免用户走到最后才发现被拦截。

### D+30 收缩决策（2026-07-12 Phase 11 新增）

**产品首发收缩**：
- **宝宝取名**：D+30 前作为**首发主产品**，承担用户验证 + 付费验证主链路
- **成人改名**：标记为 **Beta**，保留入口但不主推，收集需求但不验证付费
- **品牌取名**：标记为**实验能力**，保留入口但评分标注"待核验"，不验证付费
- **命运K线**：36 个月月线作为近期决策窗口展示，0-100 岁长期曲线推迟到 v0.2
- **问事**：作为流量入口之一，验证首问完成率 + 深推点击率，不验证付费

**1 笔真实订单验证路径**：
- **付费权益**：宝宝取名完整 PDF 导出（无水印）作为付费权益
- **预览策略**：PDF 预览版带水印，完整版需付费解锁
- **验证目标**：D+30 前完成 1 笔真实订单（下单→支付→交付→资金到账）
- **兜底方案**：若支付链路不通，降级为"扫码转账 + 人工发 PDF"，优先验证付费意愿
- **配套文档**：`docs/01商业计划/D30-用户验证计划-20260712.md`

## O2. 建成用户数据资产闭环

### KR

1. 新产生咨询记录后台入库率达到 `100%`
2. 结果页追问记录后台入库率达到 `100%`
3. 历史记录回看可打开率达到 `>= 98%`
4. 历史记录支持单删/多选/全选删除并可追溯
5. 管理员后台可按用户查看命盘、咨询、追问、深推结果

### 关键动作

1. 把前端缓存态改成后端真源态。
2. 统一 consultation、profile、question、result、followup 的数据口径。
3. 历史记录按“人 / 事项 / 时间”组织，不按“咨询记录四个字”组织。
4. 为管理员建立最小可用后台查询视图。
5. 为后续案例库、复盘、用户画像预留结构化字段。

---

## O3. 提升 LLM 结果质量到可复访水平

### KR

1. 初步结论中模板残渣、JSON 残渣、英文异常出现率降到 `< 1%`
2. 深入推演超时率降到 `< 5%`
3. 用户追问回复可连续承接率达到 `>= 90%`
4. 结果页中“像真人顾问”的人工抽样评分达到 `>= 7/10`
5. 高价值场景样本库至少沉淀 `100` 条可复用案例

### 关键动作

1. 建立算法证据包 -> 表达层 -> 页面结构层的三级输出链。
2. 为问事、取名、命运K线分别建立风格约束和禁出规则。
3. 引入案例级 few-shot 和专题知识块，而不是只堆总 prompt。
4. 把“初判、深推、追问”三类输出分开建模板与质量基线。
5. 把异常重试做成局部动作，不破坏当前对话。

## 4. 本季度战略红线

以下事项一旦出现，说明项目在偏航：

1. 三入口还能演示，但真实用户主流程仍频繁断。
2. 用户数据仍主要停留在 localStorage、session 或前端状态。
3. LLM 结果还能看到明显的字段残渣、程序残渣、模板残渣。
4. 新增大量术数入口，但核心三入口转化和复访没有提升。
5. 命运K线仍只是“截图功能”，没有成为传播和回访锚点。
6. 历史记录不能支撑删除、回看、复盘和管理员查看。

## 5. CEO 周经营看板

CEO 每周只看以下 12 个数，不被零碎功能进度带偏：

### 用户与转化

1. 周活跃咨询用户数
2. 首问完成用户数
3. 深推付费用户数
4. 会员新增数

### 产品闭环

5. 命运K线生成成功率
6. 问事首问完成率
7. 取名完整流程完成率
8. 历史回看打开率

### 质量与稳定性

9. API 4xx/5xx 比例
10. 深推超时率
11. LLM 异常输出率
12. 关键页面白屏/资源错误次数

说明：

- 这 12 个指标必须每周同口径更新。
- 没有可追踪数据的目标，不算目标。
- 不能只报“修了多少问题”，要报“对经营指标是否产生影响”。

### 实施口径（2026-07-11）

- 统一接口：`GET /api/v1/analytics/admin/operating-dashboard?days=7`。
- 管理后台：概览页“CEO 周经营看板”，展示指标值、目标和计算口径。
- 无法由业务数据库可靠证明的指标必须返回 `availability=unavailable`、`value=null`，不得以 `0` 冒充健康。
- API 4xx/5xx 已由后端按 30 秒窗口聚合持久化，避免逐请求写库；关键页面错误由前端统一上报，并用 `frontend_error_tracking_ready` 区分“零错误”和“未接入”。Nginx 静态资源错误仍由前端资源加载事件补证，后续可再接日志侧校验。

## 6. 三条产品线的经营定位

## 6.1 命运K线

经营角色：`传播入口 + 差异化招牌 + 中轻度付费承接`

本季度任务：

1. 缩短进入门槛。
2. 提高首屏震撼感和可信感。
3. 做出愿意分享的结果卡。
4. 让用户理解“为什么这条线这样走”。
5. 做好免费体验和付费解锁层级。

不该承担的任务：

1. 不承担全部玄学百科展示。
2. 不承担长篇顾问式推演主职责。

## 6.2 问事

经营角色：`高频需求入口 + 深推转化主阵地`

本季度任务：

1. 让用户一句话就能开始。
2. 在对话里补齐关键信息。
3. 初判要快，深推要稳，追问要连续。
4. 强化结果结构化表达和行动建议。
5. 建立“这事后来怎样”的复盘链。

不该承担的任务：

1. 不把用户先推入重表单。
2. 不把结果做成只有术语堆积的命理报告。

## 6.3 取名

经营角色：`高客单场景 + 可传播场景 + 口碑场景`

本季度任务：

1. 统一到对话前台。
2. 强化候选名字解释和比较逻辑。
3. 把“命理依据 + 风格理由 + 使用建议”说清。
4. 打通宝宝取名、改名、品牌取名三个主要场景。

不该承担的任务：

1. 不继续维护一套孤立的旧页面流程。
2. 不只给名单，不给判断框架。

## 7. 30 / 60 / 90 天执行节奏

## D+30

1. 收口线上 P0：白屏、403、404、登录与管理员异常、深推刷新整页等。
2. 三入口核心链路跑通。
3. 用户咨询与结果留存入库。
4. 建立第一版经营看板。

## D+60

1. 命运K线完成第一轮传播卡升级。
2. 问事完成对话式首问、补问、追问统一。
3. 取名完成统一前台承接。
4. 管理员可查看核心用户资产。
5. LLM 异常残渣问题基本清零。

## D+90

1. 三入口完成第一轮付费转化优化。
2. 建立样本案例库与风格库。
3. 历史回看和复盘体系上线。
4. 命运K线形成稳定分享锚点。

## 8. 组织与分工口径

虽然当前团队可能是轻量执行，但职责必须拆清：

1. 产品负责人：定义入口、闭环、付费边界、结果形态。
2. 算法负责人：保证盘面、大运、关键因子、趋势数据可信。
3. 后端负责人：保证记录留存、接口稳定、权限与积分真实可控。
4. 前端负责人：保证对话流、结果页、历史页、K线体验一致。
5. 内容/提示词负责人：保证真人顾问感、案例沉淀、表达质量。
6. CEO：只盯三件事，闭环、复访、付费，不被零碎需求牵着走。

---

## 9. 决策原则

出现需求冲突时，统一按下面顺序判断：

1. 是否强化三入口闭环。
2. 是否提升用户复访和付费。
3. 是否增强数据资产沉淀。
4. 是否提升结果可信度和顾问感。
5. 是否只是“看起来更丰富”，但对经营没有实质帮助。

如果第 5 条成立，优先级自动下调。
