# 人生决策宗师 / 命运K线 — CEO目标与北极星指标

> 日期：2026-06-24
> 状态：ACTIVE
> 适用范围：产品定位、PRD、路线图、商业计划、阶段执行

---

## 1. CEO目标

在未来 6-12 个月内，把“人生决策宗师”建设为一个可持续增长、可复购、可沉淀用户资产的现代术数决策产品。

这个目标不是“继续堆功能”，而是完成以下 7 件事：

1. 做出一个用户愿意反复打开的核心产品，而不是一次性测算工具。
2. 建立清晰差异化，让用户一想到“命运走势可视化”就想到“命运K线”。
3. 把用户每一次咨询、追问、命盘、回看都沉淀为后台资产，而不是停留在前端缓存。
4. 让 LLM 从“会写报告”升级到“像真人顾问一样会理解、会判断、会连续交流”。
5. 收敛产品结构，对外减少入口混乱，对内建设统一中台。
6. 建立可信度，让算法、表达、结果、历史回看都能被用户感知为靠谱。
7. 跑通商业闭环，让免费功能负责传播，付费功能负责复购和长期价值。

---

## 2. 一句话战略

把人生决策宗师做成一个以“命运K线”为差异化核心、以“问事/取名”为高频入口、以“用户长期数据资产”为护城河的现代术数决策平台。

---

## 3. 产品形态定义

### 3.1 对用户的外部形态

前台不是传统“功能堆叠网站”，而是三类能力清晰分工：

1. 命运K线：负责出圈、传播、趋势感知、长期回看。
2. 问事：负责高频问题输入、即时判断、追问和转化。
3. 取名：负责高价值付费场景、拟人化前台承接和分享传播。

### 3.2 对内部的系统形态

后台逐步收敛为四层中台能力：

1. 算法中台：八字、五行、大运、十神、六壬、六爻、后续奇门/紫微等。
2. 知识库中台：术数规则、判例、提示词、案例库、表达素材。
3. 用户数据中台：命盘、问题、咨询记录、追问、结果、回看、权益。
4. LLM表达中台：把算法证据和知识库内容，转成更像真人顾问的输出。

---

## 4. 北极星指标

CEO层面不以“页面数量”或“新增功能数”作为核心指标，统一看以下指标：

### 4.1 核心北极星

`7日内完成一次有效咨询并再次回访的用户数`

说明：

- 不是只看 UV。
- 不是只看注册。
- 不是只看一次性生成结果。
- 核心是“用户真的觉得有用，所以又回来”。

### 4.2 一级经营指标

1. 命运K线生成数与分享率
2. 问事首问完成率与深入推演转化率
3. 取名完整链路完成率与付费率
4. 7日回访率
5. 会员转化率与复购率
6. 历史记录留存率与可回看率

### 4.3 一级质量指标

1. 算法结果可信度投诉率
2. LLM输出异常率
3. 页面主流程中断率
4. 深入推演超时率
5. 用户对“像真人顾问”的主观满意度

---

## 5. 战略取舍

### 5.1 重点做什么

1. 重点做三大高感知能力：命运K线、问事、取名。
2. 重点做连续互动，而不是一次性结果页。
3. 重点做结果可传播、可回看、可复购。
4. 重点做后台沉淀，把数据资产真正留在系统里。
5. 重点做 LLM 表达质量，让内容既不像死板报告，也不像空泛鸡汤。

### 5.2 明确暂时不做什么

1. 不以神煞、十神、藏干等术数细节露出量作为核心增长目标。
2. 不继续无限增加首页入口。
3. 不把前台做成传统工具站导航页。
4. 不优先追求“算法全覆盖”，而忽视用户能否理解和愿不愿付费。
5. 不把核心数据继续留在本地缓存或临时状态里。

---

## 6. 差异化定位

相对于传统玄学网站，人生决策宗师的差异不应只是“功能更多”，而应是：

1. 有走势感：命运K线把抽象运势可视化。
2. 有互动感：问事和取名可以在拟人化前台里完成。
3. 有顾问感：输出不是模板堆砌，而是像真人判断。
4. 有资产感：用户历史、问题、回看和关系数据长期留存。
5. 有验证感：不是只给结论，还能回看、复盘、再判断。

---

## 7. 免费与付费原则

### 7.1 免费功能的角色

免费能力负责传播、体验和信任建立：

1. 基础命盘与基础趋势感
2. 问事的浅层承接
3. 命运K线的部分体验
4. 取名的前置互动和部分展示

### 7.2 付费功能的角色

付费能力负责深度价值和复购：

1. 深入推演
2. 完整命运K线与多维走势
3. 长期回看与复盘
4. 关系分析、人物对照、专题能力
5. 高频权益和连续顾问服务

原则只有一条：收费点必须对应用户能明显感知到的“更深、更准、更连续、更有用”。

## 8. 12个月阶段目标

### Phase 1：先跑通一个强主闭环

目标：

- 让命运K线、问事、取名三入口都能真实跑通
- 修掉主流程断点
- 建立后台资产留存

验收标准：

- 主流程不依赖前端缓存
- 历史记录可见、可删、可回看
- 结果页可继续追问
- 管理员可查看关键后台数据

### Phase 2：把结果做得更像真人顾问

目标：

- 强化算法证据到自然表达的转换
- 增强案例、知识库、提示词和风格层
- 降低模板感和机器感

验收标准：

- 输出内容显著优于当前“算法摘要 + 空泛建议”
- 用户能感知“像人在看问题”
- 深推结果可被分享、收藏、回看

### Phase 3：把平台做成复购型产品

目标：

- 提升会员转化和回访
- 用数据资产反哺模型和产品
- 形成稳定的增长与复盘机制

验收标准：

- 命运K线成为稳定传播锚点
- 问事成为高频回访场景
- 取名成为高价值付费场景

---

## 9. CEO层执行原则

1. 不以“做了多少功能”评估项目，而以“是否形成复访与付费”评估。
2. 不让产品结构继续发散，所有新增需求都要回答“是否强化三大核心入口”。
3. 不让工程文档脱离真实代码和真实线上状态。
4. 不让核心数据继续散落在本地缓存、临时变量和多个口径中。
5. 不让 LLM 只做包装层，必须逐步变成算法、知识库、用户上下文之间的表达中台。
