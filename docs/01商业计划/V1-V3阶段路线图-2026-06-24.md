## 1. 文档目的

本文件回答 4 个问题：

1. 未来 2-3 个版本先做什么，不做什么。
2. `命运K线 / 问事 / 取名` 三条产品线如何分阶段推进。
3. `稳定性 / LLM质量 / 数据资产` 三条底座线如何配套建设。
4. 现有工程计划、PRD、交接文档该如何对齐到同一条路线。

本文件不替代具体工程交接文档，也不替代单模块 PRD。它的职责是统一阶段目标和优先级。

---

## 2. 当前判断

基于现有项目状态，当前不是“缺更多功能”，而是 5 个核心问题尚未完全收口：

1. 三大入口仍存在链路断点，特别是问事与取名的对话式闭环不够稳定。
2. 命运K线有差异化潜力，但数据利用深度、分享传播性和付费承接还不够强。
3. LLM 输出还常停留在“算法摘要 + 空泛建议”，真人顾问感不足。
4. 用户互动、命盘和历史记录的后台留存还没有完全成为稳定资产链。
5. 文档、执行计划、代码状态存在漂移，容易造成团队判断口径不一致。

所以接下来版本推进的原则是：

- 先收主闭环，再扩能力。
- 先做强入口，再补百科。
- 先做复访和转化，再做术数细枝末节的展示丰富。

## 3. 版本定义

### V1：把主流程跑通

目标：从“能演示”升级到“能稳定让用户完成一次有效体验”。

关注点：

1. 命运K线能正常生成、能看、能传播、能承接付费。
2. 问事能在对话前台内完成首问、补充、追问、深推，不再频繁跳步骤页。
3. 取名能在统一对话前台完成信息收集、结果输出、追问和转化。
4. 用户数据进入后台，历史可回看、可删除、可管理。
5. 线上 P0 稳定性不再反复出问题。

### V2：把结果做得更像真人顾问

目标：从“能跑通”升级到“用户觉得真有用、真像人在判断”。

关注点：

1. LLM 输出质量显著提升。
2. 深推结果从单纯文本变成结构化、可读、可追问的顾问式输出。
3. 命运K线从单一图表升级为多维趋势产品。
4. 知识库、案例、风格层、提示词体系进入实际调用链。
5. 历史回看与复盘开始形成长期价值。

### V3：把产品做成可复购的平台

目标：从“单次体验产品”升级到“长期陪伴型决策平台”。

关注点：

1. 用户有持续回访理由。
2. 会员权益形成清晰层次。
3. 后台沉淀的数据资产开始反哺推荐、内容、模型和产品策略。
4. 术数中台支撑更多能力扩展，而不是前台继续堆入口。

## 4. 总体推进框架

六条线并行，但优先级不同：

1. 产品主线 A：命运K线
2. 产品主线 B：问事
3. 产品主线 C：取名
4. 底座线 D：稳定性与部署
5. 底座线 E：LLM质量与知识库调用
6. 底座线 F：数据资产与后台运营

优先级规则：

`D 稳定性` 和 `F 数据资产` 是硬底座。  
`A/B/C` 是用户可见主价值。  
`E LLM质量` 决定复访和转化上限。

## 5. V1 目标与范围

### 5.1 V1核心目标

在一个版本周期内，完成“三入口可用 + 数据可留 + 结果可转化”的最小闭环。

### 5.2 V1必须完成

#### A. 命运K线

1. 首页入口清晰，与问事、取名并列。
2. 输入流程足够短，不把用户卡死在多层表单。
3. K线结果页能稳定展示。
4. 免费版和付费版差异明确。
5. 分享卡片或海报具备传播性。

#### B. 问事

1. 首问直接在对话框内完成，不先把用户推入复杂步骤流。
2. 补充信息也在对话流内完成，不频繁弹窗打断。
3. 结果页支持继续追问。
4. 深度推演失败时不整页刷新，不打断当前上下文。
5. 历史记录里能回看“问了什么、系统怎么答”。

#### C. 取名

1. 统一使用对话前台，不单独维护另一套重页面流程。
2. 基础信息采集、补充要求、结果展示、追问都在同一前台完成。
3. 结果有清晰的命理依据、风格理由和选择建议。
4. 支持付费层级承接。

#### D. 稳定性与部署

1. `/life` 子站静态资源、子路径、API代理稳定。
2. 管理员账号、权限和积分逻辑稳定。
3. 线上常见 404/400/403 问题收口。
4. 构建、部署、回滚路径有文档和校验。

#### E. LLM质量

1. 去掉明显的模板残渣、JSON 残渣、英文异常、半成品字段。
2. 初步结论、深入推演、追问回复三段输出口径统一。
3. 错误重试和超时兜底逻辑合理。

#### F. 数据资产

1. 用户互动、命盘、问题、结果、追问写入后台。
2. 历史列表以“人/事项”为核心组织，不只是一串咨询记录。
3. 管理员可查看用户核心咨询资产。

### 5.3 V1不做

1. 不优先新增大量术数入口。
2. 不优先把每个神煞、十神、细枝末节都前台可视化。
3. 不先做复杂百科式资料站。
4. 不先追求算法全覆盖而忽略产品闭环。

### 5.4 V1验收标准

1. 三大入口主流程都能被真实用户走通。
2. 问事和取名不再依赖割裂的步骤弹窗主导流程。
3. 历史记录、后台数据留存、管理员查看形成基本闭环。
4. K线具备基础传播能力和付费承接能力。

## 6. V2 目标与范围

### 6.1 V2核心目标

把“能用”升级成“值得反复用”，核心是输出质量、内容表现和趋势产品深度。

### 6.2 V2必须完成

#### A. 命运K线增强

1. 从单一运势图扩展到事业、财运、情感等主题线。
2. 把大运、流年、流月、十神、神煞、藏干、长生等更多结构化因子纳入计算。
3. 做出更像产品而不是截图工具的传播卡。
4. 强化“看走势 + 看节点 + 看建议”的完整体验。

#### B. 问事增强

1. 深推结果版式升级，接近“专家顾问卡片流”而不是纯长文本。
2. 更强的上下文工程，让追问、补问、复问更自然。
3. 加入案例、知识库和风格约束，减少机器感。

#### C. 取名增强

1. 补齐五格、三才、生肖禁忌、音韵、美感等综合评分逻辑。
2. 结果展示从“给名单”升级到“给选择框架”。
3. 支持宝宝取名、改名、品牌取名的分支表达。

#### D. 数据与后台增强

1. 建立按用户、按事项、按人物、按主题的后台视图。
2. 支持回看、复盘、标注、删除、导出等能力。
3. 积累优质案例，为 LLM 表达和营销内容反哺。

#### E. LLM与知识库增强

1. 知识库不只是参考目录，要进入实际调用链。
2. 建立算法证据包到自然语言输出的转换层。
3. 针对问事、K线、取名分别建立质量基线与评测集。

### 6.3 V2验收标准

1. 用户能明显感知“像真人顾问”。
2. 深推结果显著优于当前算法摘要式表达。
3. 命运K线成为产品差异化最强资产之一。
4. 后台积累的案例与数据开始反哺前台质量。

## 7. V3 目标与范围

### 7.1 V3核心目标

把产品做成长期复购型平台，而不是单次咨询站。

### 7.2 V3必须完成

1. 构建分层会员体系：浅体验、进阶服务、长期顾问权益。
2. 把历史、复盘、回看、提醒、推荐串成持续回访机制。
3. 让算法中台、知识中台、表达中台支持更多能力扩张。
4. 形成面向管理员和运营的内容、数据、案例管理后台。
5. 评估紫微、奇门、梅花、六爻等新能力如何接入中台，而不是粗暴加入口。

### 7.3 V3验收标准

1. 用户有明确复购理由。
2. 会员权益不靠“解锁页面”，而靠“持续决策价值”。
3. 平台具备从数据到内容到模型的正反馈循环。

## 8. 三大核心产品线优先级

### 8.1 命运K线

定位：差异化出圈产品。  
阶段优先级：`V1 高` / `V2 最高` / `V3 高`

原因：

1. 最容易形成记忆点。
2. 最适合传播和视觉化。
3. 最能区别于普通问答型玄学产品。

### 8.2 问事

定位：高频主入口。  
阶段优先级：`V1 最高` / `V2 最高` / `V3 高`

原因：

1. 用户真实需求最直接。
2. 决定完成率、复访和付费。
3. 是“像真人顾问”能力的核心战场。

### 8.3 取名

定位：高价值付费场景。  
阶段优先级：`V1 高` / `V2 高` / `V3 中高`

原因：

1. 付费意愿相对更明确。
2. 易形成结果展示和分享。
3. 适合作为拟人化前台的高价值场景。

## 9. 关键里程碑

### 里程碑 M1：V1主闭环跑通

证明标准：

1. 三入口都可用。
2. 历史可回看。
3. 数据写后台。
4. 管理员可查看。
5. 线上不再频繁因部署和路径问题中断。

### 里程碑 M2：V2顾问感建立

证明标准：

1. 用户愿意继续追问。
2. 输出具备自然度、结构感、判断力。
3. 命运K线具备更多维度和更高传播性。

### 里程碑 M3：V3复购平台形成

证明标准：

1. 用户有回访理由。
2. 会员体系清楚。
3. 平台能依赖数据资产持续变强。

## 12. 迭代评审节奏（2026-06-25 追加）

### 12.1 评审触发条件

- 每个版本（V1/V2/V3）结束时
- 每个里程碑（M1/M2/M3）达成时
- 重大事故复盘后

### 12.2 评审流程

1. **准备**：版本负责人整理该周期的 PRD 完成度、工程交付物、测试报告
2. **评审会**：逐条核对 V1/V2/V3 验收标准（第 5.4/6.3/7.3 节）
3. **产出**：复盘报告 → 写入 `docs/04复盘总结/项目复盘/版本复盘-V{X}-{日期}.md`
4. **回写**：路线图追加"版本实际状态"标注
5. **归档**：该版本 PRD + 工程文档 + 复盘 → `docs/03开发过程稿/已完成执行计划/`

### 12.3 回写规则

- 路线图 Ch5/6/7 各版本节追加"实际状态"子节
- 未达成的验收项标注 `⚠️ 部分达成` 或 `❌ 未达成`
- 达成项标注 `✅ 已达成（证据：xxx）`

### 12.4 经验沉淀

- 每个版本结束时，至少产出 1 条 E 编号经验
- 写入 `记忆系统/02-evolution/E{编号}_{主题}.md`
- 更新 `记忆系统/02-evolution/learned-rules.md`

### 12.5 归档路径
