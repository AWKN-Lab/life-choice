### 2.2 NamingResult 新增（Phase 1）

**Migration**：`20260616_add_naming_result_model`

**模型定义**：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | String | 是 | uuid() | 主键 |
| userId | String | 是 | — | 用户 ID |
| consultRecordId | String | 是 | — | 关联 ConsultRecord |
| names | String | 是 | — | JSON：`[{name, score, analysis}]` |
| wuge | String? | 否 | null | JSON：五行分析 |
| sancai | String? | 否 | null | JSON：三才分析 |
| createdAt | DateTime | 是 | now() | 创建时间 |

**Prisma Schema**：
```prisma
model NamingResult {
  id               String   @id @default(uuid())
  userId           String
  consultRecordId  String
  names            String   // JSON: [{name, score, analysis}]
  wuge             String?  // JSON: 五行分析
  sancai           String?  // JSON: 三才分析
  createdAt        DateTime @default(now())

  user          User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  consultRecord ConsultRecord @relation(fields: [consultRecordId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([consultRecordId])
}
```

**关联变更**：
- `User` 模型需新增 `namingResults NamingResult[]`
- `ConsultRecord` 模型需新增 `namingResult NamingResult?`

**回滚**：删除 NamingResult 表 + 移除 User/ConsultRecord 中的关联字段

**风险**：🟠 中（新表 + 两个关联变更）

## 4. Migration 执行顺序

```
1. 备份 DB
   cp prisma/dev.db prisma/dev.db.bak.20260616

2. Phase 0 migration
   pnpm prisma migrate dev --name add_utm_fields_to_page_visit

3. Phase 1 migration
   pnpm prisma migrate dev --name add_naming_result_model

4. 同步 schema 到根目录
   pnpm sync:schema
```

## 5. 数据风险

| 风险 | 影响 | 预防 |
|------|------|------|
| PageVisit 新增字段导致 migration 失败 | 低（可空字段） | 先备份 |
| NamingResult 外键约束失败 | 中（consultRecordId 必须存在） | 先确保 ConsultRecord 有数据 |
| prod 环境为 PostgreSQL | SQL 语法可能不同 | Prisma ORM 自动适配 |
