### 1.3 关键架构原则

1. **守卫分层**：所有写入接口必须显式声明守卫，禁止"裸路由"。`/seed` 是反面教材，Phase 1 修复。
2. **DTO 契约唯一**：前端 payload 类型必须与 DTO 装饰器一致。`stylePreference` 类型冲突是反面教材，Phase 2 修复。
3. **数据来源可追溯**：所有生成型数据（K线/潮汐/取名）必须带 `source` / `dataVersion` / `generatedAt`。Phase 6-7 落地。
4. **评分确定性**：禁止用 `Math.random()` 生成用户可见评分。Phase 4 修复 BrandStrategy。
5. **失败显式**：禁止静默补默认值掩盖用户输入缺失。Phase 3 修复取名 service。
6. **经营可观测**：CEO 12 指标必须可聚合、可对比、可下钻。Phase 9 落地。

## 2. 接口契约（目标态）

> 本节描述 Phase 0-11 完成后的目标态接口契约。每个接口标注"增量"或"基线"，"增量"表示 P0-P1 修复引入的变更。

### 2.1 K线与潮汐

#### 2.1.1 POST /api/v1/kline-tide/seed【增量：Phase 1 安全加固】

**守卫**：`@UseGuards(JwtAuthGuard, AdminGuard)`

**业务约束**：
- 生产环境（`NODE_ENV=production`）必须显式开启 `ALLOW_SEED_WRITE=true`
- 否则 service 层抛 `ForbiddenException`
- 非生产环境无此限制

**请求**：
```
POST /api/v1/kline-tide/seed?userId=xxx&klineMonths=36&tideMonths=12
Authorization: Bearer <admin_token>
```

**响应**：
| 状态码 | 场景 | 响应体 |
|--------|------|--------|
| 200 | admin + 非 prod 或 admin + prod + ALLOW_SEED_WRITE=true | TidePackage |
| 401 | 未携带 token | `{ statusCode: 401, message: "Unauthorized" }` |
| 403 | 非 admin 用户 | `{ statusCode: 403, message: "Forbidden" }` |
| 403 | prod + ALLOW_SEED_WRITE≠true | `{ statusCode: 403, message: "Forbidden: seed write disabled in production" }` |

**side effect**：
- 删除该 userId 的全部 KlineBar + StateSnapshot
- 重新生成模拟数据
- **Phase 6 后**：写入时 `source='simulated'`, `dataVersion='v1'`, `generatedAt=now()`

#### 2.1.2 GET /api/v1/kline-tide/:userId【基线，无变更】

返回 TidePackage，含 KlineBar[] + StateSnapshot[] + meta。

**Phase 6 后 meta.source 取值**：
- `real`：数据库真实数据
- `simulated`：seed 生成
- `llm_inferred`：LLM 推导
- `fallback`：降级
- `unknown`：历史存量（回填）

**前端展示口径**（Phase 1 已落地部分）：
- `real` → "已有数据"
- `simulated` → "模拟数据"
- `llm_inferred` → "LLM推导"
- `fallback` → "降级数据"
- `unknown` → "历史数据（待标注）"

### 2.2 咨询与取名

#### 2.2.1 POST /api/v1/consult（routeType=quming）【增量：Phase 2, 3】

**DTO 契约（目标态）**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `routeType` | string | ✅ | 固定 `quming` |
| `namingType` | string | ✅ | `baby` / `adult` / `brand` |
| `surname` | string | ✅ | 姓氏 |
| `stylePreference` | **string[]** | ❌ | 风格偏好数组（**Phase 2 改为数组**） |
| `birthDate` | string | 条件必填 | `namingType=baby` 时必填 |
| `birthTime` | string | ❌ | HH:mm |
| `gender` | string | ❌ | male/female |
| `parentWish` | string | ❌ | 家长期望（baby 专用） |
| `avoidChars` | string[] | ❌ | 忌用字 |
| `industry` | string | ❌ | 行业（brand 专用） |
| `targetAudience` | string | ❌ | 目标受众（brand 专用） |
| `originalName` | string | ❌ | 原名（adult 专用） |
| `customDescription` | string | ❌ | 自定义描述 |
| `improveFocus` | string | ❌ | 改进焦点 |

**Service 行为分叉（Phase 3 目标态）**：

| namingType | birthDate | 路径 | 调用 Agent |
|-----------|-----------|------|-----------|
| baby | 有 | 八字排盘 + 取名 | QumingAgent |
| baby | 无 | 400 "需要出生日期" | — |
| adult | 有 | 八字排盘 + 取名 | QumingAgent |
| adult | 无 | **场景化命名**（新分支） | NamingService.scenarioBased() |
| brand | 有或无 | **不走八字路径**，直接场景化 | NamingService.scenarioBased() |

**禁止行为**（Phase 3 修复）：
- ❌ `birthDate: dto.birthDate || ''`（静默补空串）
- ❌ `birthTime: dto.birthTime || '12:00'`（静默补午时）
- ❌ `gender: dto.gender || 'male'`（静默补男性）
- ❌ `JSON.parse(dto.stylePreference)`（DTO 已是数组）

**响应**：200 LlmResult（含 name_suggestions），与基线结构一致。

## 6. 部署架构（目标态）

### 6.1 部署拓扑

```
开发机（Windows / TRAE）
  │
  │ 1. npm run build
  │ 2. tar -czf dist-XXX.tar.gz dist/
  ▼
scp /tmp/dist-XXX.tar.gz user@server:/tmp/
  │
  ▼
生产服务器（Linux）
  ├─ /opt/awkn-life/awkn-life-backend/apps/api-server/
  │   ├─ dist/                    ← 新产物覆盖
  │   ├─ dist.bak.YYYYMMDD.XX/    ← 备份
  │   ├─ prisma/
  │   │   ├─ dev.db               ← SQLite 主库
  │   │   ├─ dev.db.bak.YYYYMMDD.XX  ← 备份
  │   │   └─ schema.prisma
  │   └─ ecosystem.config.js
  │
  ├─ PM2 → awkn-life-backend → bootstrap-production.js → dist/main.js
  │
  ├─ /www/wwwroot/awkn.cn/life/    ← 前端静态产物
  │
  └─ Python 3.11 知识服务 127.0.0.1:8701
```

### 6.2 三批次部署节奏

| 批次 | 包含 Phase | DB 变更 | 风险 | 部署窗口 |
|------|-----------|---------|------|---------|
| 部署 1 | 0-5 | 否 | 中（鉴权 + DTO） | 低峰期 |
| 部署 2 | 6-7 | 是（加字段 + 新建 3 表） | 高（数据模型） | 低峰期 + DB 备份 |
| 部署 3 | 8-11 | 否 | 低（仅 Phase 9 接口） | 任意 |

### 6.3 回滚矩阵

| 场景 | 回滚动作 | 数据影响 |
|------|---------|---------|
| 部署 1 代码异常 | `cp -r dist.bak.20260712.p0 dist && pm2 restart` | 无 |
| 部署 2 schema 异常 | `cp dev.db.bak.20260712.schema dev.db && cp -r dist.bak.20260712.p0 dist && pm2 restart` | 丢失 Phase 6-7 后业务数据 |
| 部署 3 代码异常 | 同部署 1 | 无 |
| git HEAD 异常 | `git revert <sha>` | 无 |

### 6.4 SQLite migration 限制

SQLite 不支持 `DROP COLUMN`，因此：
- 加字段：保留（无害）
- 加表：`DROP TABLE` 可逆
- 删字段：不可逆（需重建表）

**Phase 6-7 的 schema 变更均为"加字段 + 加表"，无 DROP 操作，回滚安全。**
