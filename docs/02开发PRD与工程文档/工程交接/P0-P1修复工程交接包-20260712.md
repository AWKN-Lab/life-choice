## 3. 接口变更详情

### 3.1 POST /api/v1/kline-tide/seed（Phase 1）

**变更性质**：安全加固

**Before**：
- 路由：`@Post('seed')` 无 Guard
- Service：`seed()` 直接执行 deleteMany + 重新生成，无环境检查

**After**：
- 路由：`@Post('seed')` + `@UseGuards(JwtAuthGuard, AdminGuard)`
- Service：`seed()` 入口加 `if (NODE_ENV === 'production' && ALLOW_SEED_WRITE !== 'true') throw new ForbiddenException`

**请求**：
```
POST /api/v1/kline-tide/seed?userId=xxx&klineMonths=36&tideMonths=12
Authorization: Bearer <admin_token>
```

**响应**：
- 200：TidePackage（admin 调用 + ALLOW_SEED_WRITE=true 时）
- 401：未携带 token
- 403：非 admin 用户
- 403 ForbiddenException：生产环境且 ALLOW_SEED_WRITE≠true

### 3.2 POST /api/v1/consult（routeType=quming）（Phase 2, 3）

**变更性质**：契约修复 + 业务逻辑分叉

**Before**：
- DTO：`@IsString() stylePreference?: string`
- Service：`birthDate: dto.birthDate || '', birthTime: dto.birthTime || '12:00', gender: ... || 'male'`
- Service：`JSON.parse(dto.style_preference || dto.stylePreference)`

**After**：
- DTO：`@IsArray() @IsString({ each: true }) stylePreference?: string[]`
- Service：`birthDate: dto.birthDate || undefined, birthTime: dto.birthTime || undefined, gender: ... || undefined`
- Service：直接返回 `dto.style_preference || dto.stylePreference`（数组）
- Service：按 namingType 分叉
  - baby：要求 birthDate（L242 已校验保留），走 QumingAgent 八字路径
  - adult：birthDate 可选；有则八字，无则场景化命名（新分支）
  - brand：不走八字路径，直接场景化命名（基于 industry/targetAudience/stylePreference）

**请求**：
```json
{
  "routeType": "quming",
  "namingType": "baby|adult|brand",
  "stylePreference": ["古典", "文雅"],
  "birthDate": "2026-07-12",
  "birthTime": "12:00",
  "gender": "male",
  "surname": "张",
  "improveFocus": "...",
  "industry": "...",
  "targetAudience": "...",
  "originalName": "...",
  "customDescription": "..."
}
```

**响应**：200 LlmResult（与现有结构一致，含 name_suggestions）

## 4. 数据库变更详情

### 4.1 KlineBar 加字段（Phase 6）

**Migration**：`add_kline_source_fields`

```sql
ALTER TABLE KlineBar ADD COLUMN source TEXT DEFAULT 'unknown';
ALTER TABLE KlineBar ADD COLUMN dataVersion TEXT DEFAULT 'v1';
ALTER TABLE KlineBar ADD COLUMN generatedAt DATETIME DEFAULT CURRENT_TIMESTAMP;

ALTER TABLE StateSnapshot ADD COLUMN source TEXT DEFAULT 'unknown';
ALTER TABLE StateSnapshot ADD COLUMN dataVersion TEXT DEFAULT 'v1';
ALTER TABLE StateSnapshot ADD COLUMN generatedAt DATETIME DEFAULT CURRENT_TIMESTAMP;

UPDATE KlineBar SET source = 'unknown' WHERE source IS NULL;
UPDATE StateSnapshot SET source = 'unknown' WHERE source IS NULL;
```

**source 枚举值**：
- `real`：数据库中的真实数据（非 LLM 推导）
- `simulated`：seed 生成的模拟数据（ALLOW_SEED_WRITE=true 时）
- `llm_inferred`：LLM 推导的数据
- `fallback`：降级数据
- `unknown`：历史存量数据（回填）

### 4.2 取名三表（Phase 7）

**Migration**：`add_naming_three_tables`

```sql
CREATE TABLE NamingProject (
  id TEXT PRIMARY KEY,
  userId TEXT NOT NULL,
  namingType TEXT NOT NULL,
  surname TEXT,
  stylePreference TEXT,
  industry TEXT,
  targetAudience TEXT,
  originalName TEXT,
  customDescription TEXT,
  status TEXT DEFAULT 'active',
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (userId) REFERENCES User(id) ON DELETE CASCADE
);

CREATE TABLE NamingCandidate (
  id TEXT PRIMARY KEY,
  projectId TEXT NOT NULL,
  name TEXT NOT NULL,
  score REAL DEFAULT 0,
  analysis TEXT,
  status TEXT DEFAULT 'pending',
  candidateVersion INT DEFAULT 1,
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (projectId) REFERENCES NamingProject(id) ON DELETE CASCADE
);

CREATE TABLE NamingIteration (
  id TEXT PRIMARY KEY,
  projectId TEXT NOT NULL,
  iterationNo INT NOT NULL,
  promptSnapshot TEXT,
  modelUsed TEXT,
  generatedAt DATETIME DEFAULT CURRENT_TIMESTAMP,
  createdAt DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (projectId) REFERENCES NamingProject(id) ON DELETE CASCADE
);

CREATE INDEX NamingCandidate_projectId_idx ON NamingCandidate(projectId);
CREATE INDEX NamingIteration_projectId_idx ON NamingIteration(projectId);
```

**NamingCandidate.status 枚举**：
- `pending`：待处理
- `favorited`：已收藏
- `eliminated`：已淘汰
- `selected`：已选中（最终选择）

### 7.2 git 回滚

若需回滚 git HEAD：
```bash
git revert <commit-sha>  # 单个 commit 回滚
# 或
git reset --soft HEAD~N  # 退回最近 N 个 commit（保留工作区，需用户授权）
```

### 7.3 DB 回滚

SQLite 不支持 DROP COLUMN，因此：
- 加字段：保留（无害）
- 新表：`DROP TABLE NamingProject; DROP TABLE NamingCandidate; DROP TABLE NamingIteration;`
- 若需完全恢复：用 `dev.db.bak.20260712.schema` 覆盖（会丢失 Phase 6-7 之后的业务数据）
