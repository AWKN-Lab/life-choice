## 1. 变更摘要

把 3 个战略锚（人生K线 / 公司取名 / 海报拉新）从"可跑"做到"可量化拉新"。

**核心改动**：
- 共享底座：真 QR + UTM 链路 + 埋点扩展
- K线锚：海报接真 QR + 名人对比
- 取名锚：结果落库 + 强制登录 + 付费墙
- 海报锚：真 QR + UTM + 裂变层级

**改动规模**：25+ 文件，3 个 Phase，约 11 人天

## 4. 接口文档

### 4.1 新增接口

#### P0：UTM 埋点

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| POST | `/api/v1/analytics/event` | 扩展支持 `landing_view` / `qr_scan_back` 事件类型 | 无 |

**landing_view 事件 payload**：
```json
{
  "event": "landing_view",
  "properties": {
    "utm_source": "poster",
    "utm_medium": "wechat",
    "utm_campaign": "kline_v1",
    "pageName": "landing"
  }
}
```

**qr_scan_back 事件 payload**：
```json
{
  "event": "qr_scan_back",
  "properties": {
    "source": "kline_poster",
    "inviteCode": "xxx"
  }
}
```

#### P1：取名历史查询

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/consult/naming/history` | 查询当前用户的取名历史 | JWT |

**Response**：
```json
{
  "records": [
    {
      "id": "uuid",
      "consultRecordId": "uuid",
      "names": [{ "name": "张三", "score": 95 }],
      "wuge": { "tian": "火", "di": "土" },
      "sancai": { "tian": "火", "ren": "木", "di": "土" },
      "createdAt": "2026-06-16T00:00:00Z"
    }
  ]
}
```

#### P2：K线名人对比

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/kline/compare` | 对比用户 K 线与名人 K 线 | JWT |

**Query**：`?celebrityId=xxx&birthDate=1990-01-15&gender=male`

#### P2：限免记录

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| GET | `/api/v1/membership/free-trial` | 查询用户是否已使用限免 | JWT |
| POST | `/api/v1/membership/free-trial/record` | 记录限免使用 | JWT |

## 5. 数据库文档

### 5.1 PageVisit 扩展（Phase 0，Step 0.4）

**现有字段**：id, userId, sessionId, pageName, pageUrl, referrer, deviceInfo, screenSize, ipCountry, ipCity, entryTime, exitTime, duration, createdAt

**新增字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `source` | String? | 否 | UTM source（如 `poster`, `kline`） |
| `medium` | String? | 否 | UTM medium（如 `wechat`, `moments`） |
| `campaign` | String? | 否 | UTM campaign（如 `kline_v1`） |
| `qrCodeId` | String? | 否 | 关联的 QR 码标识 |

**Migration**：`20260616_add_utm_fields_to_page_visit`

**回滚**：`pnpm prisma migrate resolve --rolled-back 20260616_add_utm_fields_to_page_visit`

### 5.2 NamingResult 新增（Phase 1，P1-1）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | String | 是 | UUID 主键 |
| `userId` | String | 是 | 用户 ID |
| `consultRecordId` | String | 是 | 关联 ConsultRecord |
| `names` | String | 是 | JSON：`[{name, score, analysis}]` |
| `wuge` | String? | 否 | JSON：五行分析 |
| `sancai` | String? | 否 | JSON：三才分析 |
| `createdAt` | DateTime | 是 | 创建时间 |

**关联**：
- `consultRecordId` → `ConsultRecord.id`
- `userId` → `User.id`

**Migration**：`20260616_add_naming_result_model`

### 5.3 已有模型（不需改动，仅供参考）

**Referral**（已有 source/medium/campaign）：
- id, inviteId, inviteCode, referredUserId, source, medium, campaign, status, createdAt
- P2-3 裂变扩展：在 growth.service.ts 中增加 `level` 计算逻辑，不改表结构

**Invite**：
- id, code, userId, usedCount, rewardTier, createdAt, updatedAt

## 7. 部署说明

### 7.1 Phase 0 部署步骤

```bash
# 1. 备份数据库
cd apps/AWKN-LABlife/awkn-life-backend
cp prisma/dev.db prisma/dev.db.bak.20260616

# 2. 前端安装依赖
cd apps/AWKN-LABlife/app
pnpm install

# 3. 后端 migration
cd apps/AWKN-LABlife/awkn-life-backend
pnpm prisma migrate dev --name add_utm_fields_to_page_visit

# 4. 同步 schema 到根目录
pnpm sync:schema

# 5. 前端构建
cd apps/AWKN-LABlife/app
pnpm build

# 6. 后端构建
cd apps/AWKN-LABlife/awkn-life-backend/apps/api-server
npx tsc --noEmit && npx nest build

# 7. 部署（scp + chmod）
# 参考现有 deploy-awkn-life.ps1
```
