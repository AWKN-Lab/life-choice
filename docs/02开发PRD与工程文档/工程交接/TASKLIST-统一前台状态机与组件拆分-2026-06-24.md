## 3. 任务拆分

## T1. 收口入口分发

目标：

1. 首页点击问事、取名统一进入同一前台壳层。
2. `/life/question`、`/life/naming` 仅保留兼容职责。

动作：

1. 检查 `HomePage.tsx` 的入口分发逻辑。
2. 建立统一 `activeFrontdesk` / `frontdeskMode` 控制。
3. 清理旧入口中直接跳不同页面的分支。

交付物：

1. 首页入口分发收口
2. 兼容路由复用同一前台

验收：

1. 首页点击问事、取名不再进入两套主流程。

## T2. 拆壳层

目标：

让壳层职责和业务状态职责分离。

动作：

1. 新增或抽出 `FrontdeskShell`。
2. 壳层只负责：
   - 打开关闭
   - 页面/弹层模式
   - 标题与布局
   - 最外层 loading / error shell
3. `FrontdeskChat` 不再负责最外层容器行为。

交付物：

1. `FrontdeskShell.tsx`
2. 壳层接入点改造

验收：

1. 页面模式与弹层模式只差壳层，不差业务逻辑。

## T3. 统一 phase 状态机

目标：

问事与取名共用同构 phase 状态机。

动作：

1. 在 `types.ts` 中定义统一 phase 模型。
2. 抽出 mode 无关事件集合。
3. 补齐 `error_retry` 显式状态。
4. 深推失败必须走状态机恢复，不允许整页刷新。

建议 phase：

1. `input`
2. `clarify`
3. `submitting`
4. `preview`
5. `deepening`
6. `followup`
7. `error_retry`

交付物：

1. 统一 phase 类型
2. 统一状态事件
3. `FrontdeskChat` 状态流重构

验收：

1. 问事和取名都能在状态图上对齐，不再依赖隐式局部状态。

## T4. 抽 mode config

目标：

把问事、取名的差异收敛为配置，而不是散在组件里的 `if/else`。

动作：

1. 重构 `frontdeskConfigs.ts`。
2. 为 `question`、`naming` 建立同构配置结构：
   - greeting
   - quick intents / type options
   - clarify strategy
   - payload builder
   - success mapping
   - retry copy
3. 禁止 mode 走“特殊硬编码主流程”。

交付物：

1. `frontdeskConfigs` 统一 shape
2. 两个 mode 的配置实现

验收：

1. 新增 mode 时不需要复制一套组件。

## T5. 统一 analyze / followup 提交协议

目标：

从前台到后端记录的链路可追踪。

动作：

1. 统一首问提交接口适配层。
2. 统一 followup 提交接口适配层。
3. 明确 `recordId` 的进入、更新、返回规则。
4. 禁止只依赖 query 参数维持事项上下文。

交付物：

1. submit adapter
2. followup adapter
3. `recordId` 贯穿规则

验收：

1. 任一模式都可追溯到后端真记录。

## T6. 统一结果承接

目标：

preview、deep result、followup 都能从同一事项继续。

动作：

1. 约束 `ResultPage.tsx` 的承接边界。
2. 问事显示“用户问了什么”。
3. 取名区分“首轮候选”与“完整方案”。
4. 深推失败局部重试。

交付物：

1. 结果承接协议
2. 页面内 retry 逻辑

验收：

1. 用户不会因一次错误被迫重开整个事项。

---

## 4. 建议实施顺序

1. T1 入口分发
2. T2 壳层拆分
3. T3 phase 状态机
4. T4 mode config
5. T5 提交协议
6. T6 结果承接

原因：

1. 先收口入口和壳层，避免后面重构时双轨存在。
2. 先定状态机，后定配置，不反过来。
3. 提交协议必须在状态机清楚后落地。

## 6. 风险与禁止项

禁止：

1. 新起第二套 `QuestionFrontdeskNew` / `NamingFrontdeskNew`
2. 为赶进度继续把逻辑堆进 `FrontdeskChat.tsx`
3. 继续依赖页面刷新恢复错误
4. 用路由参数临时凑上下文而不写后端记录

风险：

1. `FrontdeskChat` 越改越大
2. `ResultPage` 继续失控
3. 旧兼容路由保留太久形成双轨

缓解：

1. 每完成一层就删旧分支
2. 组件与状态机同步拆

## 7. 验收用例

1. 首页点击问事，直接进入统一前台，可首问、补问、出初判、深推、追问
2. 首页点击取名，直接进入统一前台，可选类型、定方向、补信息、出候选、解锁完整方案
3. `/life/question` 与 `/life/naming` 行为与首页入口一致
4. 深推失败仅重试当前模块，不刷新整页
5. 历史回看可重新进入同一事项链
