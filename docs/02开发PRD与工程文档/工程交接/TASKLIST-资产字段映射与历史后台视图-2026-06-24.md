## 1. 文档目的

本任务单用于把“数据资产底座”拆成可执行工程任务。

交付目标只有一个：

`三入口的关键互动、结果和行为都能稳定写入后台，并被用户历史页和管理员视图消费。`

---

## 2. 任务范围

涉及重点域：

1. `consult`
2. `followup`
3. `membership / credits`
4. `history`
5. `admin view`

涉及重点事实口径：

1. `sourceEntry`
2. `questionIntent`
3. `namingType`
4. `unlockStatus`
5. `shareGenerated`
6. `recordId / consultationId`

---

## 3. 数据目标

Q3 至少要让以下数据成为真资产：

1. 用户是谁
2. 问/算了什么
3. 用了哪个入口
4. 补充了什么信息
5. 生成了什么结果
6. 是否深推、分享、解锁、重试
7. 后续追问了什么

---

## 4. 任务拆分

## T1. 统一事项主键链路

目标：

让同一事项从首问到追问都串在一起。

动作：

1. 梳理 `analyze -> result -> followup` 主链路。
2. 明确 `recordId` / `consultationId` 的真主键口径。
3. 禁止某些入口只在前端存在临时事项态。

交付物：

1. 主键贯穿说明
2. 主链路字段表

验收：

1. 任一事项都能追到首问、结果、追问。

## T2. 资产字段映射表

目标：

让三入口字段写入规则明确，不再靠隐式约定。

动作：

1. 建立字段映射表：
   - 入口
   - 字段名
   - 来源
   - 写入时机
   - 展示消费者
2. 覆盖问事、取名、命运K线三个入口。

建议最小字段组：

1. sourceEntry
2. routeType
3. questionIntent
4. namingType
5. profile snapshot
6. preview result summary
7. deep result summary
8. unlock status
9. share status
10. retry count

交付物：

1. 字段映射表

验收：

1. 工程师可以据表实现，而不是靠猜。

## T3. 写入收口

目标：

让所有关键动作稳定落库。

动作：

1. analyze 创建记录字段补全
2. clarify 更新记录字段补全
3. deep result 更新记录字段补全
4. followup 链写入补全
5. unlock/share/retry 行为写入补全

交付物：

1. 写入点清单
2. 写入缺口清单

验收：

1. 不再出现“页面上有，后台没有”的关键数据。

## T4. 历史页信息架构改造

目标：

让历史页从“咨询记录列表”变成“我的人和事”。

动作：

1. 重写列表卡片字段优先级。
2. 按人物/事项/时间组织。
3. 接入单删、多选、全选删除。
4. 支持从历史继续追问或回看完整结果。

卡片建议字段：

1. 人物名或匿名标签
2. 入口类型
3. 出生信息摘要
4. 事项摘要
5. 最近更新时间
6. 状态标签

交付物：

1. 历史页 IA 方案
2. 历史页任务清单

验收：

1. 用户能快速认出“这是谁、这是什么事”。

## T5. 管理员后台最小视图

目标：

让管理员查看的是“资产”，不是数据库碎片。

动作：

1. 定义用户总览视图
2. 定义事项总览视图
3. 定义入口维度视图
4. 定义行为转化视图

最小问题集：

1. 某个用户最近问了什么
2. 该用户有哪些命盘快照
3. 哪个事项深推失败最多
4. 哪个入口转化更高

交付物：

1. 管理员最小视图字段集
2. 管理员页面任务清单

验收：

1. 客服/运营/复盘可以不查原始表完成基础工作。

## T6. 回归测试清单

目标：

让资产链不是一次性修补，而是可回归验证。

动作：

1. 定义三入口新建记录回归用例
2. 定义 followup 追问回归用例
3. 定义历史页回看与删除回归用例
4. 定义管理员视图抽查用例

交付物：

1. 资产留存回归清单

验收：

1. 每次改前台或接口后都能验证资产链没断。

## 6. 建议实施顺序

1. T1 事项主键链路
2. T2 字段映射表
3. T3 写入收口
4. T4 历史页 IA
5. T5 管理员最小视图
6. T6 回归测试

原因：

1. 不先定主键和字段，后面的历史页与后台视图都会返工。
2. 不先补写入，前台改再漂亮也是假资产。

## 8. 风险与禁止项

禁止：

1. 只改历史 UI，不补后端写入
2. 只存展示文案，不存算法快照或结构化摘要
3. 用 localStorage 充当记录真源
4. 管理员直接读数据库表做业务查看

风险：

1. 三入口字段继续各写各的
2. 历史删除只删前端列表不删后端记录
3. 继续追问无法回挂原事项

缓解：

1. 先做字段表，再做代码补全
2. 所有行为围绕 `recordId` 检查

---

## 9. 验收用例

1. 问事新建一条事项，后台可见完整问题、结果摘要、追问链
2. 取名新建一条事项，后台可见类型、偏好、候选摘要、解锁状态
3. 命运K线生成后，后台可见入口、命盘快照、分享/解锁状态
4. 历史页可单删、多选、全选删除
5. 管理员可按用户查看最近事项和结果
