## 1. 概述

三锚全打涉及 3 个 Phase 的部署，每个 Phase 有独立的部署步骤和回滚方案。

**关键约束**：
- Phase 0 是后续所有 Phase 的前提，必须 100% 通过再进 Phase 1
- 涉及 DB migration 的步骤必须先备份
- 付费墙功能必须 Feature Flag 灰度，不能直接全量

## 3. Phase 0 部署步骤

### 3.1 前置检查

```bash
# 确认当前分支和状态
git status
git log --oneline -3

# 确认后端可启动
cd apps/AWKN-LABlife/awkn-life-backend/apps/api-server
npx tsc --noEmit
```

### 3.2 备份数据库

```bash
cd apps/AWKN-LABlife/awkn-life-backend
cp prisma/dev.db prisma/dev.db.bak.20260616
```

### 3.3 前端依赖安装

```bash
cd apps/AWKN-LABlife/app
pnpm add qrcode @types/qrcode
```

### 3.4 后端 Migration

```bash
cd apps/AWKN-LABlife/awkn-life-backend
pnpm prisma migrate dev --name add_utm_fields_to_page_visit

# 同步 schema 到根目录
pnpm sync:schema
```

### 3.5 构建

```bash
# 前端
cd apps/AWKN-LABlife/app
pnpm build

# 后端
cd apps/AWKN-LABlife/awkn-life-backend/apps/api-server
npx nest build
```

### 3.6 部署到生产

```bash
# 使用现有部署脚本
cd scripts/deploy
.\deploy-awkn-life.ps1

# 或手动 scp
scp -r apps/AWKN-LABlife/app/dist/* user@server:/path/to/static/life/
scp -r apps/AWKN-LABlife/awkn-life-backend/apps/api-server/dist/* user@server:/path/to/api-server/

# 远程 chmod
ssh user@server "chmod -R 755 /path/to/static/life /path/to/api-server"

# 重启后端
ssh user@server "cd /path/to/api-server && pm2 restart all"
```

### 3.7 健康检查

```bash
# 后端
curl https://awkn.cn/api/v1/health

# K线 API
curl https://awkn.cn/api/v1/kline/bars?userId=seed-user-001

# 前端
curl -I https://awkn.cn/life/
```

### 3.8 回滚

```bash
# 回滚 migration
pnpm prisma migrate resolve --rolled-back 20260616_add_utm_fields_to_page_visit

# 回滚代码
git revert <commit-hash>

# 恢复 DB
cp prisma/dev.db.bak.20260616 prisma/dev.db
```

## 5. Phase 2 部署步骤

### 5.1 Feature Flag 配置

付费墙功能必须通过 Feature Flag 控制：

```env
# .env
FEATURE_PAYWALL=false          # 付费墙开关
FEATURE_PAYWALL_ROLLOUT=0.05   # 灰度比例 5%
FEATURE_REFERRAL_LEVEL=1       # 裂变层级（1/2/3）
```

### 5.2 灰度发布流程

```
Day 1: FEATURE_PAYWALL_ROLLOUT=0.05  (5% 用户)
Day 3: FEATURE_PAYWALL_ROLLOUT=0.20  (20% 用户)
Day 5: FEATURE_PAYWALL_ROLLOUT=0.50  (50% 用户)
Day 7: FEATURE_PAYWALL=true, ROLLOUT=1.0  (全量)
```

### 5.3 监控指标

| 指标 | 告警阈值 | 检查方式 |
|------|----------|----------|
| 付费墙拦截率 | > 95% | `paywall_view` 事件数 / 访问数 |
| 限免使用率 | < 80% | `free_trial_used` 记录数 / 新用户数 |
| 裂变层级错误 | > 0 | `referral_chain` 事件错误数 |
| K线对比 API 错误率 | > 5% | 5xx 响应数 / 总请求数 |

### 5.4 回滚

```bash
# 关闭 Feature Flag（即时生效，无需重新部署）
ssh user@server "cd /path/to/api-server && echo 'FEATURE_PAYWALL=false' >> .env && pm2 restart all"
```

## 6. 通用部署检查清单

每个 Phase 部署前必须确认：

- [ ] `npx tsc --noEmit` 零错误
- [ ] `pnpm lint` 零 error
- [ ] `pnpm test` 通过
- [ ] `pnpm build` 成功
- [ ] DB 已备份
- [ ] migration 已在本地验证
- [ ] 健康检查端点返回 200
- [ ] 回归用例 REG-01~06 通过

每个 Phase 部署后必须确认：

- [ ] 健康检查通过
- [ ] 对应 Phase 的 verify/*.mjs 脚本 PASS
- [ ] PM2 日志无 ERROR
- [ ] 前端页面无白屏
