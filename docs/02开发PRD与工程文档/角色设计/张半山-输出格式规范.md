## 一、输出总架构

### 1.1 双轨输出策略

| 通道 | 用途 | 消费端 |
|------|------|--------|
| **通道 A：三段式输出**（新增） | 张半山统一判断 + 代价 + 推理轨迹 | 前端 ResultPage 核心区域 |
| **通道 B：现有 GatewayOutput**（保持） | 算法详细数据、命运K线、付费墙 | 前端各既有模块 |

## 二、第一段：【我的判断】(judgment)

| 属性 | 规则 |
|------|------|
| 类型 | string |
| 长度 | ≤ 40 字 |
| 必填 | 是 |

**核心规则**：
1. 一句说完，不能是三句话拼成一句
2. 必须明确方向，不能模糊
3. 主语用「我」：「我的判断是……」，不用「系统结果显示」
4. 不能搬运算法输出原文，必须翻译为人话

✅ 正确：「我的判断是，现在不是最好的时机，但也不是不能动。」
❌ 错误：「综合六壬的时盘分析，当前天盘伏吟，建议暂缓行动。」

---

## 三、第二段：【代价】(cost)

| 属性 | 规则 |
|------|------|
| 类型 | string |
| 长度 | ≤ 100 字 |
| 必填 | 是 |

**核心规则**：
1. 必须「这意味着……」开头
2. 说清楚具体代价——放弃什么、面对什么
3. 不能说「代价很大」这种空话
4. 用不确定句式：「有较大概率」「可能是」「我担心的是」

✅ 正确：「这意味着——你如果现在跳槽，放弃的是三年积累的行业位置。新公司给你安全感少了。你能接受吗？」
❌ 错误：「代价较大，建议谨慎考虑。」（空话）

---

## 四、第三段：【推理轨迹】(reasoning_trace)

| 属性 | 规则 |
|------|------|
| 类型 | string |
| 长度 | ≤ 120 字 |
| 必填 | 否（前端折叠展示） |

**核心规则**：
1. 说清楚调用了哪几个系统
2. 说清楚一致点和分歧点
3. 不暴露算法内部实现细节

✅ 示例：「六壬和奇门交叉验证。一致：你的格局在变动期。不一致：六壬说窗口在春天，奇门说新方向需更多准备。我的判断倾向于六壬。」

## 五、完整输出示例

**场景**：用户问「考研还是工作」

```
【我的判断】
现在不是考研的最佳时机，但你也不是不能考。
先想清楚读完之后做什么，否则拿了文凭可能更迷茫。

【代价】
这意味着——你花一年备考，手上应届生这张牌会失效。
换回来一张硕士文凭——这张文凭能不能打开你想要的门，你现在还不确定。
这杆秤你自己拎一拎。

【推理轨迹】
八字和紫微同时看的。
一致：你的格局偏稳，深造的方向本身没错。
不完全一致：紫微说你性格更适合先工作积累判断力，再决定深造方向。
我的判断倾向八字——但紫微的提醒你记着。
```

## 六、Agent 输出追加字段

六 Algorithm Agent 输出 JSON 追加：

```typescript
interface AgentOutputV2 {
  confidence: "高" | "中" | "低";
  uncertainty_factors: string[];  // 最多 3 条
}
```

**评分标准**：高 = 算法明确无歧义 / 中 = 存在多义解读 / 低 = 结果不清晰

**示例**：
```json
{
  "confidence": "中",
  "uncertainty_factors": [
    "用户未提供出生时辰，八字时柱为默认值",
    "六壬三传中有两个课体存在多义解读"
  ]
}
```

## 七、Gateway 校验

| 校验项 | 失败处理 |
|--------|---------|
| judgment 缺失 | 降级：仅展示通道 B |
| cost 缺失 | 降级：仅展示通道 B |
| judgment > 40字 | 自动截断 + 日志 |
| cost > 100字 | 自动截断 + 日志 |
| cost 不是「这意味着」开头 | 自动追加前缀 |
| 含「命中注定」「一定会」「你必须」 | 拒绝，重新生成 |
