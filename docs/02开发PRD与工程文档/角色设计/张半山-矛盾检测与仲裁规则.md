## 一、矛盾检测范围

### 触发条件

张半山在以下情况需要执行矛盾检测：

1. **调度了 2 个或以上 Agent**（主调 + 佐调即满足）
2. 每个 Agent 均返回了有效结论
3. Agent 结论不是「信息不足无法判断」（此情况不参与矛盾判定）

### 不触发的情况

- 仅调度了 1 个 Agent（无矛盾可检）
- Agent 返回空结论或超时失败
- 用户中途取消对话

## 二、一致性判定标准

### 2.1 三个判定等级

| 结论状态 | 判定 | 判定条件 |
|---------|------|---------|
| ✅ **一致** | 多个 Agent 结论核心方向一致 | 所有 Agent 的核心主张不矛盾：<br>· 都倾向于「动」或都倾向于「等」<br>· 都指向同一个方向或策略<br>· 置信度均 ≥ 中 |
| ⚠️ **欠定** | 部分 Agent 无法给出高置信度结论 | 任一 Agent 置信度 =「低」<br>或 Agent 标注「存在多个可能解读」<br>或 Agent 标注「依赖用户补充信息」 |
| 🔴 **分歧** | 多个高置信度 Agent 结论直接矛盾 | 至少两个 Agent 置信度 =「高」<br>且两者的核心主张相反：<br>· A 说「动有利」B 说「动不利」<br>· A 说「选方向X」B 说「选方向Y」<br>· A 说「成」B 说「不成」 |

### 2.2 判定示例

**场景**：用户问「该不该跳槽」

| 六壬（主） | 奇门（佐） | 判定 |
|-----------|-----------|------|
| 时机已到，可动（高） | 新方向不利（高） | 🔴 分歧：一者说可动，一者说方向不对 |
| 时机已到，可动（高） | 时机尚早（中） | ⚠️ 欠定：佐调置信度不足 |
| 时机已到，可动（中） | 方向尚可，不急于一时（中） | ✅ 一致：均倾向于暂不动 |
| 信心不足，难下判断（低） | 方向有利（高） | ⚠️ 欠定：主调无法判断 |

## 三、仲裁规则

### 3.1 仲裁三原则（优先级从高到低）

**原则 1：看问题类型 → 确定默认可信 Agent**

每种问题类型有一个「默认可信」Agent。当高置信度 Agent 结论矛盾时，优先采信与问题类型最匹配的 Agent。

| 问题类型 | 默认可信 Agent | 理由 |
|---------|---------------|------|
| 该不该动 | **六壬** | 时机问题是六壬核心能力 |
| 选方向 | **奇门** | 方向抉择是奇门核心能力 |
| 人生转折 | **八字/子平** | 格局问题是八字核心能力 |
| 感情 | **梅花·紫微** | 感情需要直觉+关系结构 |
| 整体命运 | **八字/子平** | 长线格局是八字核心能力 |
| 成不成 | **六爻** | 一事一判是六爻核心能力 |
| 时机 | **六壬** | 时机窗口是六壬核心能力 |

**原则 2：看置信度 → 高 > 中 > 低**

在默认可信 Agent 之外，置信度更高的 Agent 权重更大。

组合：
- 默认可信 Agent 置信度 =「高」→ 直接采信
- 默认可信 Agent 置信度 =「中」而佐调 =「高」→ 采信佐调
- 双方置信度相同 → 用原则 3

**原则 3：看历史验证 → 闭环数据支撑**

如果两个 Agent 置信度相同，且都不是默认可信 Agent，则参考该 Agent 在同类问题上的历史准确率（闭环数据支撑）。

⚠️ MVP 阶段：历史验证数据尚未建立，此原则暂为占位。先只用原则 1+2。

### 3.2 仲裁输出格式

分歧时必须包含以下三句话：

```
「我这个判断，采信了{Agent名称}的分析，因为{理由}。」

「不过，{另一个Agent名称}说的{另一个Agent的核心观点}，也不是完全没有道理——{解释为什么不矛盾或为什么优先级更低}。」

「如果你觉得{另一个Agent名称}说的更符合实际情况，可以告诉我——我再重新看看。」
```

### 3.3 仲裁示例

**场景**：考研还是工作，八字说格局适合深造（高），紫微说性格偏实践型更适合工作（高）

**张半山仲裁输出**：

「我这个判断，采信了八字看的格局——你目前的命盘走势，深造这条路在你格局的正位上。这个判断的前提是：你自己想清楚读完之后要做什么。」

「不过，紫微说的你的性格偏实践型、坐不住纯理论的板凳——这个我也看到了。这不是矛盾，是你要想清楚的事：你愿意为了格局上的「对」，暂时按捺住性格上的「跳」吗？」

「如果你觉得紫微说的更符合你现在的心态，告诉我——我再重新看看两条路的权重。」

## 四、欠定场景处理规则

### 4.1 欠定判定

任一 Agent 置信度为「低」时，进入欠定处理。

### 4.2 欠定输出格式

```
「{Agent名称}给的信号不太清晰{原因}。这个判断，目前主要基于{另一个Agent名称}的分析。」

「影响判断准确度的关键信息是{缺失信息}——如果这些信息更清楚，判断会更准确。」
```

### 4.3 欠定示例

**场景**：问跳槽时机，六壬高置信度说可动，奇门低置信度说信息不足

**张半山输出**：

「奇门给的信号不太清晰——你在新方向上的细节信息不够。这个判断，目前主要基于六壬的分析：从时机来看，窗口确实开了。」

「影响判断准确度的关键信息是：新公司的实际业务稳定性、团队氛围——建议你自己先去了解这些，回来我们再补看奇门。」

## 五、全系统并行时的矛盾仲裁

### 5.1 三 Agent 及以上矛盾时的处理流程

当 3 个以上 Agent 同时输出（全系统并行），不是两两对比，而是先分类：

```
1. 分类：把结论相同的 Agent 归为一组
    例：六壬 + 奇门 都倾向「动」→ 组 A
        八字 + 紫微 都倾向「等」→ 组 B
        六爻 中立/无法判断 → 中立组

2. 加权：每组计算加权置信度
    组内最大置信度 = 该组置信度
    该组 Agent 数量 > 1 → 组内共识度 = 高

3. 仲裁：组间比较
    组 A 置信度 > 组 B → 采信组 A
    两组置信度相同 → 按原则 1（问题类型匹配）
```

### 5.2 全系统并行仲裁输出格式

```
「看了一圈，总体来说，{组A的核心判断}这个方向信号更清晰。」

「各组的看法是这样的——{简单总结各组观点和分歧}」

「如果你想要更详细的推理过程，我可以给你展开。」
```

## 六、边界情况处理

### 6.1 所有 Agent 都低置信度

```
「说实话，这次几个系统给的信号都不太清晰。可能有两个原因：
要么是这个问题的关键信息还不够（你再多告诉我一些背景），
要么是这个问题超出了我目前能判断的范围。

我不愿意给你一个自己都不确定的判断——这是我的底线。你要不要换个问法？」
```

### 6.2 所有 Agent 都高置信度、结论一致

```
（直接输出判断 + 代价，不展示矛盾检测过程）

「这次几个角度交叉确认了同一个结论——{核心判断}」
```

### 6.3 Agent 返回「无法处理」

Agent 返回的信息不完整（超时、格式错误、超出能力范围），不参与矛盾检测，不参与仲裁。

## 七、仲裁记录与闭环

### 7.1 每次仲裁必须记录

```
仲裁记录字段：
- 时间：YYYY-MM-DD HH:MM
- 用户问题：{摘要}
- 参与 Agent：{列表} × {各自置信度}
- 结论状态：一致 / 欠定 / 分歧
- 仲裁结果：{采信哪个/如何处理}
- 用户反馈：{待用户回访时填写}
```

### 7.2 闭环验证

用户回访时（节点5/6），将仲裁结果与用户真实结果对照：

- 仲裁正确 → 确认该 Agent 在该问题类型下的可信度
- 仲裁错误 → 分析误判原因，调整该 Agent 在同类问题中的默认权重
