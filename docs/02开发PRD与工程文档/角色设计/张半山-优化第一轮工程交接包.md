## 一、变更摘要

### 做了什么

将张半山从输出层包装角色升格为调度协调层。核心变更三项：

1. **六 Agent 输出格式增加置信度字段**（改 prompt，不动 CalcEngine）
2. **张半山 SKILL.md** 作为统一人格 + 调度协调层的提示词模板
3. **三段式输出格式规范**（判断 / 代价 / 推理轨迹）

### 影响范围

| 模块 | 影响 | 说明 |
|------|------|------|
| `liuren-agent/` | 输出格式变更 | 增加 confidence + uncertainty_factors 字段 |
| `liuyao-agent/` | 输出格式变更 | 同上 |
| `qimen-agent/` | 输出格式变更 | 同上 |
| `ziping-agent/` | 输出格式变更 | 同上 |
| `ziwei-agent/` | 输出格式变更 | 同上 |
| `quming-agent/` | 不受本轮影响 | 取名走独立流程 |
| `llm-gateway/` | 新增调度逻辑 | 张半山作为调度层的路由判断 |
| `consult/` | 输出格式校验 | 三段式缺一不可 |

### 不动的东西

- CalcEngine 数据结构
- 现有 API 接口签名
- 前端页面结构（三段式的第三段做成可展开即可）
- 数据库 schema

## 二、接口变更

### 2.1 Agent 输出追加字段

六个算法 Agent 的输出 JSON 追加两个字段：

```typescript
// 现有输出（保持不变）
interface AgentOutput {
  analysis: string;        // 分析原文
  conclusion: string;      // 核心结论
  suggestions: string[];   // 建议列表
  // ... 其他现有字段
}

// 追加字段（本轮新增）
interface AgentOutputV2 extends AgentOutput {
  confidence: "高" | "中" | "低";           // 本判断置信度
  uncertainty_factors: string[];             // 不确定性来源（最多3条）
}
```

**confidence 评分标准**：

| 值 | 条件 |
|----|------|
| 高 | 算法结果明确，术语单一，无歧义 |
| 中 | 存在多个可能解读，或依赖用户补充信息 |
| 低 | 算法结果不清晰，或问题超出本系统核心能力 |

**uncertainty_factors 示例**：

```json
{
  "confidence": "中",
  "uncertainty_factors": [
    "用户未提供出生时辰，八字时柱为默认值",
    "六壬三传中有两个课体存在多义解读"
  ]
}
```

### 2.2 LLM Gateway 输出格式变更

Gateway 输出从现有格式改为三段式：

```typescript
interface GatewayOutput {
  judgment: string;          // 【我的判断】≤40字
  cost: string;              // 【代价】≤100字
  reasoning_trace?: string;  // 【推理轨迹】可选展开
  sources: {                 // 本次调用的 Agent 清单
    agent: string;           // Agent 名称
    confidence: string;      // 该 Agent 的置信度
    role: "primary" | "supplementary";
  }[];
}
```

**judgment 字段规则**：
- 必须是人话，不能有术语
- 张半山说「我的判断是」，不说「系统结果显示」
- 一句说完，控制在 40 字内

**cost 字段规则**：
- 必须说清楚这个选择的具体代价
- 「这意味着……」开头
- 不能是「代价很大」这种空话

**reasoning_trace 字段规则**：
- 前端做成可展开项，不强制展示
- 包含：用了哪几个系统、一致点在哪、分歧点在哪

## 四、数据流变更

### 变更前

```
用户 → FrontdeskChat → LLM Gateway（路由）
                           ↓
                      单个 Agent（liuren/qimen/etc）
                           ↓
                      标准化输出 → 用户
```

### 变更后

```
用户 → FrontdeskChat → 张半山调度层（判断该调哪些Agent）
                           ↓
                    并行调用多个 Agent
                    每个 Agent 返回: analysis + conclusion + confidence
                           ↓
                    张半山交叉分析层
                    检查置信度 → 判断一致性 → 写仲裁理由（如分歧）
                           ↓
                    三段式输出
                    【判断】+【代价】+【推理轨迹】
```

### 关键逻辑

**一致性判定**：

| 情况 | 判定 | 张半山行为 |
|------|------|-----------|
| 所有 Agent 置信度 ≥ 中，结论一致 | 一致 | 直接输出判断 + 代价 |
| 存在 Agent 置信度 = 低 | 欠定 | 输出判断，注明「这个判断基于置信度较高的系统，XX 系统给出的信号不清晰」 |
| 多个高置信度 Agent 结论矛盾 | 分歧 | 输出仲裁：「我倾向于 X 的判断，因为……」 |

**仲裁规则优先级**：
1. 看问题类型：时机问题六壬优先，方向问题奇门优先，格局问题八字优先
2. 看置信度：高 > 中 > 低
3. 看历史验证：该 Agent 在同类问题上历史准确率更高（闭环数据支撑）

## 五、调度决策树（完整版）

张半山收到用户问题后，第一步不是回应，是判断意图类型。以下规则写入 SKILL.md。

| 用户场景 | 关键词 | 张半山第一问 | 主调 Agent | 佐调 Agent | 调度理由 |
|---------|--------|------------|-----------|-----------|---------|
| 现在该不该动 | 跳槽/辞职/出国/要不要走 | 「你是想动还是想等？」 | 六壬 | 奇门 | 六壬最擅长时机判断 |
| 两个方向选哪个 | 选A还是选B/哪个更/抉择 | 「两个方向你最怕哪个结果？」 | 奇门 | 六壬 | 奇门擅长空间+方向 |
| 考研/创业/重大人生 | 考研/创业/转行 | 「你现在最担心的是什么？」 | 八字 | 紫微 | 八字看格局，紫微看性格匹配 |
| 感情要不要继续 | 分手/离婚/感情/关系 | 「你是累了还是寒了？」 | 梅花 | 紫微 | 梅花捕第一直觉，紫微看关系结构 |
| 整体命运如何 | 命运/命盘/命中注定 | 「你想看哪一段？」 | 八字 | 六壬 | 八字看长线，六壬看关键节点 |
| 一件事成不成 | 能不能/成不成/行不行 | 「这事是你想做的还是该做的？」 | 六爻 | 奇门 | 六爻擅长一事一问 |
| 想知道时机 | 什么时候/时机 | 「你现在卡在哪里？」 | 六壬 | 梅花 | 六壬看时机窗口，梅花捕直觉方向 |
| 重大决策（用户特别焦虑或问了多个维度） | 触发词：人生大事/不知道怎么选 | 先确认用户状态 | 全系统并行 | — | 重大决策强制多维交叉确认 |

## 六、风险清单

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| confidence 字段依赖 Agent prompt 质量 | 中 | 如果 Agent 不自评置信度，字段为空 | 降级：Gateway 检查字段是否为空，空的话标注「未评估」 |
| 三段式输出导致延迟增加 | 中 | 多 Agent 并行调用 + 交叉分析可能增加响应时间 | 先单 Agent MVP，多 Agent 用并行 + 超时降级 |
| 调度决策树过度规则化 | 低 | 规则太死板会导致张半山失去灵活性 | 决策树是初始依据，张半山有权根据对话动态调整 |
| 推理轨迹暴露算法细节 | 低 | 让用户看见内部逻辑可能降低神秘感 | 推理轨迹折叠展示，新手不强制看 |

## 七、部署说明

### 环境变量

无需新增。

### 部署步骤

1. 更新六个 Agent 的 prompt 文件（输出格式章节追加 confidence 规则）
2. 新增张半山 SKILL.md 到 `docs/` 目录
3. 在 LLM Gateway 中注册张半山调度层（作为新的路由策略，与现有策略共存）
4. 更新 Gateway 输出格式校验（三段式基本检查）
5. 前端在三段式中对第三段「推理轨迹」做折叠展开交互

### 回滚方案

- LLM Gateway 路由策略可以随时切回原始策略（单 Agent 直出）
- Agent prompt 用 git 恢复
- 不影响现有功能

### 健康检查

- 跑 5 个预定义测试用例，检查：
  - Agent 输出中 confidence 字段不为空
  - 三段式输出 three fields 齐全
  - 张半山说话风格正确（不输出术语、不说「天意」类禁句）

## 八、测试用例

### 用例 1：考研还是工作

**输入**：「我大四，考研还是工作，想问问。」

**预期 Gateway 行为**：调度八字（主）+ 六壬（佐）

**预期输出结构**：
```json
{
  "judgment": "我的判断是，先想清楚读完之后做什么再考，否则拿了文凭会更迷茫。",
  "cost": "这意味着你可能花一年备考，错过应届生身份带来的工作窗口。你能接受这个时间成本吗？",
  "reasoning_trace": "八字看你的格局偏稳，六壬显示当前时机不算最佳……"
}
```

### 用例 2：跳槽

**输入**：「有个新机会涨薪20%，但新公司小，要不要去？」

**预期 Gateway 行为**：调度六壬（主）+ 奇门（佐）

**预期输出结构**：判断说清楚涨薪不是离开的核心理由 + 代价说清楚新公司的不确定性

### 用例 3：感情

**输入**：「和他在一起三年了，累了。」

**预期 Gateway 行为**：调度梅花（主）+ 紫微（佐）

**预期输出结构**：先判断是累了还是寒了 + 代价说清楚分与不分的后续走向
