# 人生决策宗师首页三入口、会员分层与自然增长闭环 PRD

> 版本：V1.1  
> 日期：2026-06-22  
> 范围：首页、命运K线、取名、问事、拟人化前台、免费/会员分层、首问价值、3 次追问、局势卡分享、复访提醒、深推付费闭环  
> 不影响范围：`awkn.cn` 根主页、后台管理页、旧 demo 页、全站重构

## 1. 核心需求

人生决策宗师需要从“传统玄学功能集合”升级为“用户按真实需求进入的专家工具站”。用户并不先关心八字、十神、神煞、纳音等专业模块，而是带着明确问题进入：

- 想知道自己的走势：看运势、看事业财运感情。
- 想取一个名字：宝宝取名、成人改名、品牌取名。
- 想判断一件事：工作、关系、合作、财务、选择。

首页应以这三类用户需求为一级入口：

1. 命运K线
2. 取名
3. 问事

命运K线使用“生成图表 + 解盘”的工具体验；取名和问事使用拟人化前台体验，让用户像面对真人顾问一样自然表达，再由系统自动分流到对应算法和 LLM 流程。

V1.1 的核心增补不是继续增加新术数入口，而是把现有三入口、追问、分享、历史记录、回访和会员解锁串成自然增长闭环：

```text
真实困惑进入
→ 首问给到“说中感”
→ 系统主动给 3 个追问入口
→ 生成可保存/可分享的局势卡、金句卡或今日提醒卡
→ 7 天/关键日期/静默用户触发复访
→ 回到原事项继续追问或复盘
→ 在“想问透”的节点承接 ¥1 单事深推破冰成交，再用追问、复访和会员权益承接深度价值
```

产品判断：当前闭环不了的主要原因不是算法不足，而是用户第一次得到结果后缺少继续追问、保存、分享、回访和付费深推的连续路径。PRD 后续所有功能都必须服务这条闭环。

## 2. 成功标准

### 2.1 业务指标

- 首页三入口点击率提升。
- 命运K线生成完成率提升。
- 取名表单完成率提升。
- 问事提交率提升。
- 免费结果到会员解锁转化率提升。
- 用户保存/分享命运K线海报次数提升。
- 历史记录复看率提升。
- 首问结果后追问启动率提升。
- 结果卡保存率、分享卡生成率提升。
- D1 / D7 复访打开率提升。
- ¥1 单事深推支付转化率提升。
- 用户从“单次问完”转为“同一事项持续追问/复盘”的比例提升。
### 2.2 体验指标

- 新用户进入首页后 5 秒内能理解三个主要入口。
- 用户点击任一入口后，3 步内看到有效反馈。
- 免费用户在充值前能看到可感知价值。
- 会员权益出现在“想继续看深”的节点，而不是挡在入口前。
- 中文、英文模式无混杂文案。
- 用户看完免费结果后能明确看到“下一步还能问什么”。
- 分享内容不暴露完整命盘、隐私问题和深度推演，只展示可传播的摘要资产。
- 回访提醒必须回到原事项上下文，而不是重新开始一次泛问答。

### 2.3 工程指标

- 不破坏现有 `/life` 子站部署。
- 不影响 `awkn.cn` 根主页。
- 复用现有 React 页面、咨询流程、会员模块、结果页能力。
- 本期不新增复杂数据库架构，只在现有记录体系中补足关键字段。
- 复用现有 `ConsultRecord.shareGenerated`、`ConsultRecord.closedLoopResult`、`ConsultFollowUp`、`followup.service.ts`、`active-moves.ts`、`analytics.ts` 等资产。
- 自然增长闭环一期优先用现有记录、分享、回访和埋点能力串联，不先做复杂社区、内容广场或公开案例池。

## 4. 目标用户

### 4.1 新用户

需求特点：

- 不懂术数。
- 不知道该选八字、六爻、大六壬还是奇门。
- 只知道自己想看运势、取名字、问一件事。

产品策略：

- 入口文案必须是用户语言。
- 系统负责分流，用户不负责选术数。

### 4.2 轻度兴趣用户

需求特点：

- 愿意尝试看一眼。
- 对命运K线、名字评分、问事初判有兴趣。
- 未必愿意立刻付费。

产品策略：

- 免费给结果感。
- 会员锁深度，不锁入口。

### 4.3 高意愿用户

需求特点：

- 愿意为深度分析、完整方案、复看记录付费。
- 关注事业、财运、关系、孩子名字、合作判断等强需求。

产品策略：

- 会员给完整图表、完整名字方案、完整问事推演。
- 支持历史留存和复看。

## 5. 首页信息架构

### 5.1 首屏结构

首页首屏由品牌标题、价值说明、三大入口组成。

建议文案：

```text
人生决策宗师
用东方术数与智能推演，看清人生节律、名字气象和当下难事
```

三大入口：

| 入口 | 主标题 | 副标题 | 交互方式 |
|---|---|---|---|
| 命运K线 | 生成我的命运K线 | 看人生阶段、事业财运感情走势和关键年份 | 出生信息表单 + K线图 |
| 取名 | 帮我取个好名字 | 宝宝取名、成人改名、品牌取名 | 拟人化前台 + 取名表单 |
| 问事 | 问一件当下的事 | 工作、感情、合作、选择，先判断这事的底 | 拟人化前台 + 自动分流 |

### 5.2 次级内容

次级内容只承接信任，不抢主入口：

- 命运K线示例图
- 取名方案示例
- 问事结果示例
- 用户历史记录入口
- 会员权益入口

## 6. 入口一：命运K线

### 6.1 产品目标

命运K线是人生决策宗师最具传播性的核心产品。它负责“出圈”和“建立差异化”。

### 6.2 用户流程

```text
首页点击命运K线
→ K线引导页
→ 填写出生信息
→ 生成免费预览
→ 解锁完整四线
→ 查看关键年份、AI解盘、高清海报
```

### 6.3 免费功能

- 生成基础命运K线。
- 展示当前阶段。
- 展示总势线简版。
- 展示未来三年简述。
- 展示 1 个机会窗口。
- 展示 1 个风险窗口。
- 生成基础分享图。

### 6.4 会员功能

月会员：

- 完整总势线。
- 事业K线。
- 财运K线。
- 情感K线。
- 年份级解读。
- 关键年份列表。
- AI 解盘师引导问题。
- 高清分享海报。

年会员：

- 长周期趋势报告。
- 年度复看。
- 多次记录对比。
- 未来 V3 的事件校准与回看验证。

### 6.5 验收标准

- 用户无需付费即可完成一次命运K线预览。
- 用户点击完整四线、关键年份、高清海报时出现会员承接。
- 会员用户进入后可直接查看完整四线。
- 管理员用户可真实扣积分体验完整流程，失败时不跳充值页。

## 7. 入口二：取名

### 7.1 产品目标

取名是刚需型转化入口。用户关心的不是算法，而是能不能得到一组“能用、好听、有解释、有筛选依据”的名字。

### 7.2 拟人化前台

取名前台像真人顾问一样先问方向，而不是直接丢表单。

第一句：

```text
我先帮你定名字方向。你是想给宝宝取名、成人改名，还是品牌取名？
```

第二步按选择分流：

| 类型 | 追问 |
|---|---|
| 宝宝取名 | 宝宝姓什么？出生时间确定了吗？希望名字偏稳重、灵动、书卷气，还是现代感？ |
| 成人改名 | 原名是什么？更想改善气质、人际、事业，还是整体能量？ |
| 品牌取名 | 行业是什么？面向什么人群？希望名字偏高级、亲和、东方感，还是商业感？ |

### 7.3 免费功能

- 取名方向判断。
- 3 个候选名字。
- 简短解释。
- 基础五行倾向提示。

### 7.4 会员功能

月会员：

- 10-20 个候选名字。
- 八字五行匹配。
- 音形义解释。
- 名字评分。
- 避坑说明。

年会员：

- 多轮筛选。
- 改名对比。
- 品牌命名策略。
- 完整 PDF/海报版方案。

### 7.5 验收标准

- 用户点击取名后先进入拟人化前台，而不是复杂表单。
- 用户回答 2-3 个问题后再进入结构化表单。
- 免费用户能拿到可感知的候选名字。
- 会员用户能看到完整评分和解释。

## 8. 入口三：问事

### 8.1 产品目标

问事负责高频使用和用户留存。用户不需要理解六爻、大六壬、奇门、八字的差异，只需要把事情说出来。

### 8.2 拟人化前台

第一句：

```text
你现在最没底的是哪件事？可以直接说，比如：要不要换工作、这段关系还要不要继续、合作能不能做。
```

系统收到用户输入后，自动做意图判断：

- 事业工作
- 财务投资
- 感情关系
- 合作人际
- 出行迁移
- 重大选择
- 其他

### 8.3 自动分流策略

| 用户问题 | 推荐底层能力 |
|---|---|
| 当下具体事件 | 大六壬 / 六爻 |
| 长期事业方向 | 八字 / 大运 / 命运K线 |
| 合作关系 | 八字辅助 / 问事模型 / 人物关系 |
| 时间选择 | 择日 / 流年 / 月运 |
| 情感判断 | 六爻 / 八字关系 / 问事模型 |

### 8.4 免费功能

- 事项归类。
- 初步判断。
- 关键风险点。
- 一个最小行动建议。

### 8.5 会员功能

月会员：

- 深度推演。
- 证据链展示。
- 多路径判断。
- 行动建议。
- 复盘提醒。

年会员：

- 重大事项庙算。
- 多次追问。
- 历史事项复盘。
- 人物关系沉淀。

### 8.6 验收标准

- 用户不需要选择术数模型。
- 用户输入自然语言后，系统自动分流。
- 免费结果不是纯文本堆砌，应至少包含结论、风险、行动三块。
- 会员结果应有更完整的判断结构和可执行建议。

## 9. 免费与会员总策略

### 9.1 核心原则

```text
免费给答案感，会员给深度感。
```

不要在入口前收费。收费点应该出现在用户已经看到价值、想继续看深的时候。

### 9.2 分层总表

| 能力 | 免费 | 月会员 | 年会员 |
|---|---|---|---|
| 命运K线 | 总势预览 | 四线完整解读 | 长周期报告与复看 |
| 取名 | 少量候选 | 完整方案与评分 | 多轮筛选与改名/品牌策略 |
| 问事 | 初判 | 深度推演 | 重大事项长期跟踪 |
| 历史记录 | 基础记录 | 完整记录 | 对比、复盘、资产沉淀 |
| 分享图 | 基础图 | 高清图 | 报告图与年度图 |
| AI 引导 | 少量问题 | 多个引导问题 | 深度连续追问 |

### 9.3 不建议免费开放

- 完整四线命运K线。
- 全部关键年份解释。
- 完整名字评分体系。
- 大量候选名字。
- 深度问事推演。
- 高清报告导出。
- 历史多记录对比。

### Phase 6：V1.1 自然增长闭环

目标：把“首问、追问、分享、保存、复访、复盘、深推付费”串成一条连续路径，让用户不是一次性看完报告，而是围绕同一件事持续回来。

#### 6.1 首问价值闭环

首问结果必须从“报告式输出”改为“真人大师式点破”。免费结果不追求长，而追求用户一眼觉得有用。

首问结果固定包含 5 块：

| 模块 | 作用 | 前台表现 |
|---|---|---|
| 一句话断语 | 给用户“说中感” | 顶部大字，20-40 字 |
| 当前局势 | 告诉用户这事卡在哪 | 2-3 条短句 |
| 关键风险 | 提醒不能踩的坑 | 风险标签 + 解释 |
| 最小行动 | 今天或本周能做什么 | 1 个行动建议 |
| 下一步追问 | 引导用户继续问透 | 3 个按钮 |

结果页首屏原则：

```text
先让用户看见“这事的底”，再让用户选择是否继续问深。
```

不得把免费结果写成完整长报告，也不得只展示“请付费查看”。

#### 6.2 3 次追问闭环

每次首问结果下方必须生成 3 个追问入口，追问不能随机生成，要从本次结果里长出来。

追问类型：

| 类型 | 场景 | 示例 |
|---|---|---|
| 风险追问 | 用户担心踩坑 | “这件事最容易败在哪一步？” |
| 时间追问 | 用户关心什么时候动 | “这件事接下来 30 天怎么走？” |
| 行动追问 | 用户需要具体动作 | “我现在该先做哪一步？” |
| 人物追问 | 合作、感情、人际场景 | “对方现在更可能是什么态度？” |
| 复盘追问 | 已经发生或快发生的事 | “如果我这么做，后面怎么验？” |

追问规则：

- 免费用户可看到追问建议，但深度回答受次数和权益限制。
- 单次付费深推默认包含 3 次追问。
- 追问必须继承原事项上下文，不允许变成新咨询。
- 追问耗尽后出现“继续问透此事”的付费承接。
- 追问承接文案围绕“把这件事问透”，不是“购买会员”。

工程复用：

- 前端：`app/src/pages/ResultPage.tsx`
- 后端：`consult/followup/followup.service.ts`
- 现有素材：`consult/followup/active-moves.ts`
- 已有测试参考：`consult/__tests__/test-8-active-followup.spec.ts`

#### 6.3 分享卡闭环

分享不是把完整结果发出去，而是生成低隐私、可传播、能带回流的轻资产。

V1.1 只做三类卡：

| 卡片 | 内容 | 适合分享场景 | 隐私规则 |
|---|---|---|---|
| 局势卡 | 一句话断语 + 当前局势 + 行动提醒 | 朋友圈/私聊 | 不展示出生信息、完整问题、命盘细节 |
| 金句卡 | 张半山式断句/提醒 | 社交传播 | 不展示个人数据 |
| 今日提醒卡 | 今日宜忌/决策提醒 | 日常分享/保存 | 只展示通用提醒 |

分享卡必须带回流入口：

```text
看我的局势卡
→ 朋友点击
→ 进入同类入口/同类问题模板
→ 朋友生成自己的首问结果
```

验收：

- 用户能从结果页一键生成卡片。
- 卡片默认隐藏敏感信息。
- 分享卡带来源参数：`share_source`、`card_type`、`record_id_hash`。
- 分享回流能进入对应入口，不进入空白首页。

工程复用：

- `ConsultRecord.shareGenerated`
- `app/src/lib/analytics.ts`
- `app/src/utils/analytics.ts`
- 现有命运 K 线海报生成能力

#### 6.4 保存与复访闭环

用户看完结果后，应有三个轻动作：

1. 保存此事。
2. 7 天后提醒我复盘。
3. 到关键日期前提醒我。

复访触发类型沿用现有 `ConsultFollowUp.triggerType`：

| triggerType | 用途 | 示例 |
|---|---|---|
| `key_date_before` | 关键日期前提醒 | 面试、签约、考试、谈判前 |
| `contract_eve` | 合同前提醒 | 合作、租约、投资协议 |
| `action_window` | 行动窗口提醒 | 适合动手的 3 天前 |
| `quarter_review` | 阶段复盘 | 每季度看一次事业/财运/关系 |
| `silent_user` | 静默用户召回 | 7-14 天没回来，提醒复盘旧事 |

V1.1 先落地两个最小闭环：

- `7 天后复盘`：所有问事结果都可订阅。
- `关键日期前提醒`：当用户问题中出现时间锚点时可订阅。

复访消息必须回到原记录：

```text
你上次问的“要不要签这个合作”，到了该复盘的时候。
当时判断的风险点是：合同条款和对方履约能力。
现在这事走到哪一步了？
```

#### 6.5 复盘闭环

复盘不是简单问“准不准”，而是沉淀信任和案例。

复盘表单字段：

| 字段 | 说明 | 对应现有字段 |
|---|---|---|
| 实际结果 | 事情最后怎么发展 | `closedLoopResult.actualOutcome` |
| 用户感受 | 用户觉得哪里说中/没说中 | `closedLoopResult.userReflection` |
| 准确性选择 | 准 / 部分准 / 不准 / 还没发生 | `closedLoopResult.accuracyCheck` |
| 是否继续追问 | 是否基于结果进入下一轮 | 新增前台动作，不必先改库 |

复盘完成后：

- 用户可继续追问“下一步怎么走”。
- 后台可沉淀匿名案例。
- 高质量案例未来可进入案例库，但 V1.1 不做公开案例广场。

#### 6.6 深推付费闭环

付费点从“解锁报告”调整为“把这件事问透”。

单次深推建议产品化为：

| 产品 | 价格 | 权益 | 适用场景 |
|---|---:|---|---|
| 单事深推破冰版 | ¥1 | 完整推演基础版 + 3 次追问 + 保存复盘 | 首次付费、工作、感情、合作、选择 |
| 单事深推标准版 | 后续待定 | 更完整证据链 + 行动方案 + 复访提醒 | 已完成 ¥1 破冰后的高意向用户 |
| 月卡 | 待定 | 每月固定问数 + 历史记录 | 高频用户 |
| 年卡 | ¥588 参考 | 长周期复盘 + 多事项记录 | 长期陪跑用户 |

支付承接位置：

- 用户点击“继续问透”。
- 用户点击第 2/3 次追问的深度回答。
- 用户点击“看完整证据链”。
- 用户点击“生成完整行动方案”。

不得在用户未看到首问价值前强制付费。

## 13. 风险与约束

| 风险 | 说明 | 处理 |
|---|---|---|
| 首页入口变多 | 三入口可能削弱命运K线主推力度 | 三入口同列，但命运K线用更强视觉示例承接 |
| 拟人化过度 | 容易变成泛聊天产品 | 前台只负责收集需求和分流，不做开放聊天 |
| 会员点过早 | 用户没看到价值就流失 | 免费必须先给预览 |
| 数据留存不足 | 用户资产沉淀不完整 | Phase 5 补齐快照和后台查看 |
| 英文文案残留 | 影响海外体验 | 新增文案必须进入 i18n |
| 分享隐私泄露 | 用户真实问题、出生信息或命盘细节被发出 | 分享卡默认只展示摘要，不展示敏感字段 |
| 复访变成骚扰 | 用户未主动订阅却收到提醒 | 仅对保存/订阅/明确关键日期触发 |
| 追问变泛聊天 | 追问脱离原事项，破坏信任 | 追问必须继承 recordId / dialogue context |
| 付费点粗暴 | 用户没觉得被说中就被要求付费 | 先给首问价值，再用“继续问透”承接 |
| 自然增长只做表面分享 | 有分享按钮但没有回流路径 | 分享卡必须带 card_type 和入口回流参数 |
