## 0. 当前判断

取名已具备宝宝、成人、品牌三类入口、对话式信息采集、八字计算、五行分析、喜用神、生肖禁忌、五格校验、算法候选、LLM 候选、质量守卫、Top 3 展示、完整结果页、PDF 导出和历史存储。

当前主问题集中在三类场景共用一套输入和结果契约：

1. 宝宝、成人、品牌的用户任务差异很大，当前统一进入 QumingAgent。
2. QumingInput 把 birthDate、birthTime、gender 定义为必填，品牌命名没有天然出生信息。
3. ConsultService 在资料缺失时会把取名输入补为 `birthDate=''`、`birthTime='12:00'`、`gender='male'`，存在静默默认风险。
4. 前端已收集 improveFocus、industry、targetAudience、originalName、customDescription，`buildNamingConsultPayload` 没有完整透传这些结构化字段。
5. 前端 `stylePreference` 当前传数组，后端 DTO 将该字段校验为字符串，存在接口契约冲突。
6. parentWish、avoidChars 在 Agent 输入中存在，前台主流程尚未完整传递。
7. 当前付费模块仍复用通用 `morning / breakthrough / kline`，缺少取名专属商品和交付边界。
8. 结果能提供候选和理由，尚未形成“推荐、比较、排除、决策”的完整选择框架。
9. 品牌名称当前没有商标、域名、平台重名和敏感词核验能力，前台必须明确标注。

下一阶段目标：

```text
三类场景分开定义
输入字段真实有效
候选可以比较
淘汰理由说清
结果可以保存与继续筛选
付费交付有明确边界
```

## 1. 产品定义

### 1.1 一句话定位

> 取名帮助用户在宝宝、成人和品牌命名中，获得一组有依据、能比较、可筛选、可继续调整的名称方案。

### 1.2 用户最终获得

一次完整取名服务应交付：

```text
明确的命名方向
一组通过基础规则校验的候选
每个候选的推荐理由
候选之间的差异比较
不推荐或淘汰原因
最终选择建议
可保存和导出的完整方案
```

### 1.3 三类产品任务

| 类型 | 用户真正要解决的问题 | 核心判断依据 |
|---|---|---|
| 宝宝取名 | 给孩子选一个长期使用、顺口、好写、有寓意且与家庭偏好一致的名字 | 姓氏、出生信息、音形义、五行、避讳、家庭期望 |
| 成人改名 | 找到更符合个人身份、气质、使用场景和改善方向的名字 | 原名、使用身份、目标、出生信息可选、社会使用成本 |
| 品牌取名 | 找到符合品类、人群、定位、传播和商业气质的名称 | 行业、目标人群、品牌定位、语言、记忆点、风险检查 |

品牌命名的主判断不能由个人八字代替商业定位。创始人或项目起始信息只可作为可选辅助条件。

### 1.4 北极星子指标

> 生成候选后，完成一次收藏、对比、继续筛选、导出或付费完整方案的用户数。

一级指标：

```text
类型选择完成率
信息采集完成率
候选生成成功率
候选收藏率
对比使用率
继续筛选率
完整方案解锁率
PDF导出率
7日回看率
```

质量指标：

```text
空候选率
重复候选率
禁用字命中率
五格校验失败率
默认假资料使用率
结构化字段丢失率
低质量警告率
品牌风险误导率
```

## 6. 统一结果契约

```ts
interface NamingResultEnvelope {
  recordId: string;
  namingType: 'baby' | 'adult' | 'brand';
  status: 'completed' | 'partial' | 'failed_retryable';
  inputCompleteness: {
    score: number;
    missingFields: string[];
    uncertainty: string[];
  };
  strategy: {
    summary: string;
    strengthen: string[];
    avoid: string[];
    styleTags: string[];
  };
  basis: {
    bazi?: unknown;
    wuxing?: unknown;
    xiYongShen?: unknown;
    usageContext?: string[];
    brandContext?: string[];
  };
  candidates: Array<{
    candidateId: string;
    name: string;
    pronunciation?: string;
    reason: string;
    strengths: string[];
    caution: string[];
    scores: Record<string, number | null>;
    wuge?: unknown;
    zodiacCheck?: unknown;
    qualityFlags: string[];
    status: 'new' | 'saved' | 'rejected' | 'finalist' | 'selected';
  }>;
  comparison?: {
    dimensions: string[];
    recommendation: string;
  };
  risks: string[];
  actions: string[];
  checks: {
    trademarkChecked: boolean;
    domainChecked: boolean;
    duplicateChecked: boolean;
    sensitiveWordChecked: boolean;
  };
  audit: {
    source: 'algorithm' | 'llm' | 'hybrid' | 'fallback';
    model?: string;
    qualityScore?: number;
    fallback: boolean;
    version: string;
  };
}
```

### 6.1 候选唯一性

每个候选使用 `candidateId`，收藏、淘汰、对比和最终选择不得依赖数组位置。

### 6.2 资料缺失

资料缺失时：

```text
结果明确缺失项
相关评分返回 null
结果不填伪默认值
允许用户补资料后重新计算
```

### 6.3 低质量结果

当 `lowQuality=true` 或 quality guard 未通过：

```text
不展示为正式推荐
进入可重试状态
保留用户输入
不扣第二次权益
记录失败原因
```

## 7. 计算与质量规则

### 7.1 宝宝取名


五格只作为一个参考维度，不承担最终排序的全部权重。

### 7.2 成人改名

最低规则：

```text
原名问题
使用身份
改善方向
音形义
社会使用成本
与姓氏或原名的连续性
出生信息辅助（用户提供时）
```

### 7.3 品牌取名

最低规则：

```text
行业关联
目标人群
品牌定位
记忆度
发音
文字视觉
延展性
竞品差异
敏感词提示
```

五行或创始人信息只能作为次级参考。

### 7.4 LLM 职责

LLM 负责：

```text
根据结构化条件生成候选
解释差异
调整风格
形成选择建议
```

LLM 不负责：

```text
伪造商标可用结论
伪造域名可用结论
跳过确定性校验
把缺失出生资料当成已知
```

### 7.5 质量闸门

正式候选至少通过：

```text
Schema有效
名称非空
候选不重复
未命中avoidChars
理由与名称一致
没有明显巴纳姆话术
没有敏感或不当内容
场景字段完整
```

2. 修复 `stylePreference` 数组与后端字符串校验冲突。
3. 完整透传 improveFocus、industry、targetAudience、originalName、customDescription、parentWish、avoidChars。
4. 删除 birthDate、gender、birthTime 的静默默认。
5. 时辰未知采用明确状态。
6. 品牌命名不再强制走个人八字主逻辑。
7. 低质量结果进入可重试状态。
8. 取名主链生成真实 recordId。

## P1｜结果与选择闭环

1. 落地 NamingResultEnvelope。
2. 每个候选生成 candidateId。
3. 增加收藏、淘汰、对比和最终选择。
4. 增加候选评分维度和 caution。
5. PDF 使用同一结果数据源。
6. 建立 NamingProject、NamingCandidate、NamingIteration 或等价结构。
7. 结果历史支持版本回看。

## P2｜商业交付

1. 建立取名专属 SKU。
2. 明确免费、完整方案、多轮调整的交付差异。
3. 失败重试不重复扣费。
4. 品牌取名增加人工核验清单。
5. 导出与分享支持隐私控制。
6. 历史页展示最终选择和版本。

## P3｜增强能力

1. 扩展字库和来源治理。
2. 音韵、方言和多语言发音评估。
3. 品牌敏感词、平台重名、域名与商标接口评估。
4. 多人评选和共同决策。
5. 用用户最终选择和反馈校准排序。

## 13. 验收标准

### 13.1 产品验收

- [ ] 宝宝、成人、品牌进入各自正确流程。
- [ ] 用户在 3 个主要步骤内看到首轮候选。
- [ ] 每个候选有理由、优点和注意点。
- [ ] 用户可收藏、淘汰、比较和继续筛选。
- [ ] 完整方案可以保存、导出和回看。
- [ ] 品牌结果明确提示外部核验边界。

### 13.2 输入验收

- [ ] 三套 DTO 分开校验。
- [ ] 前端采集字段全部结构化透传。
- [ ] 无静默生日、时辰和性别默认值。
- [ ] 时辰未知不会被写成 12:00。
- [ ] avoidChars、parentWish 等字段真实生效。

### 13.3 结果验收

- [ ] 候选无重复。
- [ ] 禁用字不会出现在正式候选。
- [ ] 候选理由与具体名称一致。
- [ ] 低质量结果不进入正式推荐。
- [ ] 算法、LLM 和 fallback 来源可查。
- [ ] 商标、域名检查状态真实。

### 13.4 数据验收

- [ ] 每次命名有真实 recordId。
- [ ] 输入、候选、收藏、淘汰和最终选择可查询。
- [ ] 每轮筛选保留版本。
- [ ] PDF 与历史读取同一数据源。
- [ ] 用户可删除自己的命名项目。

### 13.5 商业验收

- [ ] 取名使用专属 SKU。
- [ ] 购买内容和交付结果一致。
- [ ] 重试不重复扣费。
- [ ] 三类场景分别可统计转化率。
- [ ] 导出、分享和回看均可归因。
