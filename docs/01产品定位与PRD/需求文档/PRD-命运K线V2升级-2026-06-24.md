## 1. 产品定义

### 1.0 版本裁决（v1.1 新增）

**裁决：v0.1 仅实现 36 个月月线，0-100 岁长期曲线留 v0.2**

- **理由**：36 个月月线可对应"近期决策窗口"，与问事/取名形成闭环；0-100 岁是长期愿景，需更多数据资产支撑。
- **影响范围**：v0.1 阶段 KlineBar 仅生成最近 36 个月的月线数据；0-100 岁长期曲线（含十年线、人生阶段线）推迟到 v0.2。
- **数据源约束**：36 个月月线的 source 取值遵循 P01 数据契约（real | simulated | llm_inferred | fallback | unknown）。
- **回看策略**：v0.1 历史回看仅支持 36 个月范围内的版本对比；v0.2 扩展到人生长期曲线回看。

### 1.1 一句话定位

> 命运K线把人生阶段、趋势变化和关键窗口转成可观看、可解释、可追问、可回看的个人决策坐标。

### 1.2 用户获得的结果

用户打开命运K线后，应在首屏回答四个问题：

1. 我当前处于哪个阶段？
2. 未来一段时间整体向上、承压或震荡？
3. 哪些时间值得推进，哪些时间适合收缩？
4. 此刻最值得做的一件事是什么？

完整体验继续回答：

```text
事业、财富、关系分别怎么走
当前阶段由哪些因素构成
关键节点为什么出现
节点对当前事项有什么影响
下一次何时回来复看
```

### 1.3 产品结构

```text
命运K线：看长期走势
人生潮汐：看当前状态和行动偏向
节点解释：看某个月份的原因与建议
问此事：把趋势转成具体决策
历史回看：验证过去判断与个人变化
```

### 1.4 核心指标

北极星子指标：

> 生成命运K线后，7 日内再次回看、分享或进入问事的用户数。

一级指标：

```text
生成完成率
首屏看懂率
节点展开率
K线进入问事转化率
完整版本解锁率
分享率
7日回看率
30日复看率
```

质量指标：

```text
空数据率
fallback占比
模拟数据误展示率
节点解释失败率
前后端口径不一致率
用户对数据来源的投诉率
```

### 2.4 当前数据对象

#### KlineBar

七条人生线：

```text
career
wealth
health
relationship
growth
freedom
buffer
```

每条线保存 OHLCV：

```text
open / high / low / close / volume
```

**OHLCV 业务定义（v1.1 新增）**：

| 字段 | 业务含义 | 计算口径 |
|------|---------|---------|
| `open` | 月初综合生命资本分 | 基于上月 `close` + 本月已知事件预判 |
| `high` | 本月峰值 | 基于 `favorableEvents` 触发的最高分 |
| `low` | 本月谷值 | 基于 `unfavorableEvents` 触发的最低分 |
| `close` | 月末综合生命资本分 | 基于本月实际决策与事件收敛 |
| `volume` | 本月"决策密度" | 基于 `ConsultRecord` + `FollowUp` + `ChronicleEntry` 数量 |

> **约束**：`open` ≤ `high`，`open` ≥ `low`，`close` ∈ [`low`, `high`]。`volume` 为非负整数，反映本月用户主动决策行为总量。

综合字段：

```text
compositeCapital

opportunityScore
riskScore
upsideRange
downsideRange
factorScores
signalLabel
source
```

### 2.5 数据来源

代码已经定义四种来源：

| source | 含义 | 产品展示要求 |
|---|---|---|
| `real` | 数据库存量或真实记录 | 标记“已有记录” |
| `simulated` | seed 生成 | 禁止伪装成用户真实历史 |
| `llm_inferred` | LLM 推导 | 标记“系统推演”与不确定性 |
| `fallback` | 无数据时降级 | 只展示基础提示，不给强判断 |

当前 `real` 的代码注释仅表达“数据库中的非 LLM 数据”，没有证明它来自用户真实行为。产品文案不得把 `real` 自动翻译为“真实人生表现”。

## 3. 目标用户与使用场景

### 3.1 初次体验用户

用户问题：

```text
我的人生走势是什么样？
我现在处于上升期还是调整期？
```

交付重点：当前阶段、总体趋势、一个机会窗口、一个风险窗口。

### 3.2 具体事项用户

用户问题：

```text
今年适合换工作吗？
这两个月适合推进合作吗？
```

交付重点：把节点带入问事，生成带 `recordId` 的事项判断。

### 3.3 长期回看用户

用户问题：

```text
过去的判断有没有发生？
我的状态是否发生变化？
```

交付重点：历史快照、复盘记录、变化原因、下一次观察点。

### 3.4 分享传播用户

用户任务：生成隐私安全、视觉清楚、能引发讨论的分享卡。

交付重点：阶段名称、趋势句、关键节点、产品品牌，不包含完整出生信息和敏感咨询内容。

## 4. 用户主流程

### 4.1 首次生成

```text
首页进入命运K线
→ 检查登录与出生档案
→ 缺资料时进入最短资料补齐
→ 请求 /kline-tide/package 与 /scores
→ 展示当前阶段首屏
→ 展示走势与关键节点
→ 引导展开解释、问此事或解锁完整版本
→ 保存访问与行为记录
```

### 4.2 节点问事

```text
用户点击某个节点
→ 节点成为 question context
→ 进入 /question 或 /consult/analyze
→ 携带 targetDate / questionType / profileId
→ 生成真实 recordId
→ 结果页返回
→ 关联原 K线节点
```

### 4.3 历史回看

```text
用户再次进入
→ 展示上次生成时间
→ 展示当前数据版本
→ 展示新增月份或变化
→ 用户记录实际发生情况
→ 写入 closed-loop / chronicle / interaction event
→ 更新下一次观察点
```

### 4.4 无数据处理

```text
无 KlineBar / StateSnapshot
→ 检查数据源和生成条件
→ 允许生成时明确显示“系统推演”
→ 不允许生成时返回空态
→ 禁止自动写入模拟数据
```

### 6.2 空态

空态必须区分：

```text
未登录
缺出生档案
无已生成数据
无权限
生成失败
仅有fallback
```

每种空态提供唯一主动作，避免统一显示“加载失败”。

### 6.3 可信度表达

| 来源 | 前台标签 | 可用语气 |
|---|---|---|
| real | 已有数据 | 中等强度判断 |
| llm_inferred | 系统推演 | 概率与趋势表达 |
| simulated | 演示数据 | 仅开发和演示环境 |
| fallback | 基础参考 | 弱判断，提示补齐或重试 |

## 11. 验收标准

### 11.1 产品验收

- [ ] 用户进入后 5 秒内看懂当前阶段。
- [ ] 首屏回答当前状态、趋势、窗口和行动。
- [ ] K线与潮汐职责清楚。
- [ ] 节点可直接进入问事。
