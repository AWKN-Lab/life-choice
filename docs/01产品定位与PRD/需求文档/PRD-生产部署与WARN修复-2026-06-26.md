## Ch1｜产品背景与目标

### 1.1 背景

生产环境（`https://awkn.cn`）当前存在两类问题：
1. **WARN 残留**：spec 中记录的两个 WARN（Agent 层 LLM 注入缺失 + 知识库 assets 路径错）—— **经核查代码，两个修复均已存在于 master 分支**（ziping/qimen/quming/ziwei/liuyao 5 个 Agent 全部使用 `@Optional() @Inject(LlmProvidersService)`；`nest-cli.json` 已包含 `**/knowledge-base/**/*.json`）
2. **本地有 60+ 文件未部署**：包括前端 40+ 组件、后端 20+ 服务模块、LLM gateway、各 orchestrator 等

**这意味着**：本 PRD 不是"修代码"，而是"**部署已经修好的代码 + 验证生产 WARN 已消失**"。

### 1.2 目标

| 维度 | 目标 |
|------|------|
| 业务 | 让生产环境 `https://awkn.cn/life/` 体现本地的 60+ 文件改进，用户能访问到命运K线、玄学展示、新组件等 |
| 技术 | 让生产的 WARN 日志归零；`/health/ready` 持续 200；Sentry 静默 |
| 流程 | 部署事故半径可控，30-60 分钟可回滚 |

## Ch2｜需求概述（Why/What/Impact）

### Why
- 生产环境与本地代码存在显著 drift（60+ 文件），用户实际使用的产品不是最新版本
- 生产 WARN 长期存在，掩盖了真实告警信号（噪声 → 沉默 → 事故）
- 命运K线 v1 已通过前端构建验证（Task 9.1），仅差最后端到端真机验收

### What Changes
1. 部署 `awkn-life-backend` 后端（带 5 个 Agent 装饰器修复 + 知识库 assets 修复）
2. 部署 `awkn-life` 前端（带 40+ 新组件 + 命运K线主 CTA）
3. 在生产验证：WARN 消失 / `/health/ready` 200 / 关键链路 OK
4. 顺手完成：destiny-kline-v1 Task 9.2 桌面+移动端目视验收

### Impact
- **受影响的接口**：无（部署类，无 API 变更）
- **受影响的代码**：仅打包，无代码改动
- **受影响的运维**：1 次生产部署 + 1 次 prod 稳定观察（24h）

## Ch4｜功能需求（EARS 格式）

### REQ-1｜生产部署
- **WHEN** 本计划被产品方触发
- **THEN** 在 30-60 分钟内完成 staging→prod 完整流程
- **AND** 部署过程中用户保持在场监督

### REQ-2｜WARN 归零验证
- **WHEN** prod 部署完成
- **THEN** `pm2 logs --lines 500 | grep -i 'agent.*llm.*配置' | wc -l` = 0
- **AND** `pm2 logs --lines 500 | grep -i '知识库.*加载' | wc -l` = 0
- **AND** 上述命令在 prod 部署后 30 分钟观察窗口内无新出现

### REQ-3｜健康端点持续可用
- **WHEN** prod 部署完成
- **THEN** `https://awkn.cn/api/health` 返回 200
- **AND** `https://awkn.cn/api/health/db` 返回 200 + `status: ok`
- **AND** `https://awkn.cn/api/health/ready` 返回 200（DB + LLM + JWT 全部就绪）
- **AND** 上述 3 个端点在 30 分钟观察窗口内持续 200

### REQ-4｜核心链路 smoke-test
- **WHEN** prod 部署完成
- **THEN** `bash scripts/smoke-test.sh` 5/5 全部通过
- **AND** 该测试在 30 分钟观察窗口内执行 3 次（间隔 10 分钟）
- **AND** 3 次执行 5/5 全通过

### REQ-5｜回滚能力
- **WHEN** 部署后任意时刻检测到 P0 故障
- **THEN** 运维可在 5 分钟内执行 `bash /opt/awkn-life/scripts/rollback.sh` 完成回滚
- **AND** 回滚后 `/health/ready` 仍 200
- **AND** 回滚日志写入 `/var/log/awkn-rollback.log`

### REQ-6｜Sentry 静默
- **WHEN** prod 部署完成 + 24h 观察期
- **THEN** Sentry 控制台无新 ERROR 级别事件
- **AND** 至多 1-2 条 INFO 级别（部署相关）

### REQ-7｜前端目视验收（destiny-kline-v1 Task 9.2）
- **WHEN** prod 部署完成
- **THEN** 桌面端 + 移动端浏览器访问 `https://awkn.cn/life/` 显示命运K线主 CTA
- **AND** 桌面端 + 移动端浏览器访问结果页 `https://awkn.cn/life/result/xxx` 显示 K线总览
- **AND** 4 张截图（桌面首页/结果页 + 移动首页/结果页）保存到 `docs/05审核与质量/验收截图/2026-06-26/`
- **AND** 检查项清单 10 项全部 ✅

## Ch11｜工程哲学

### 11.1 决策：本次按"部署类变更"处理，不触发 v0.1→v0.2 的版本升级

**理由**：
- 无代码改动
- 无接口变更
- 无新功能
- 仅打包 + 部署 + 验证

**ADR-1**（本次决策）：命运K线 v1 走的是 `app/` 目录的代码，与生产当前 app 版本号一致（如 v0.1.x），不算 minor release。后续如推出命运K线 v2（功能差异较大），再走 minor。

### 11.2 经验沉淀（必须执行）

本计划完成后，必须把以下知识写入 `docs/04复盘总结/经验整合/`：
- **E1-001**：spec 中的"待修复问题"必须先 `git grep` 验证是否已修复，再列入计划（避免重复劳动）
- **E1-002**：本地代码与生产 drift 超过 50 文件时，必须做"全量 WIP 备份"（避免回滚丢文件）
- **E1-003**：prod 部署窗口期必须明确"用户监督 vs AI 监督"，避免责任真空

### 11.3 反模式

- ❌ **不要"先看 spec 就照做"** — 必须用批判性思维验证 spec 是否过时
- ❌ **不要"5 个 Agent 装饰器一次改完"** — 应每改 1 个 build 1 次
- ❌ **不要"prod 部署完就下班"** — 必须 24h 稳定观察期
- ❌ **不要"prod 部署和评测并行"** — 会争抢 LLM 配额
