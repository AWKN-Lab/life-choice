# PRD：多轮对话整改与上下文工程

> 版本：v0.1
> 日期：2026-05-28
> 来源：从 多轮对话整改PRD_批判性分析与重构方案.md 中提取的未完成任务

## 一、产品定位
重构多轮对话系统，统一状态机、增强上下文工程、实现智能追问，提升对话连贯性和信息获取效率。

## 二、MVP功能清单

### P0（必须完成）
1. **状态机统一**：将6态与9节点状态机合并为一套统一状态机
2. **滑动窗口上下文**：实现Token计算和滑动窗口构建，防止上下文溢出
3. **摘要压缩服务**：当上下文超长时自动压缩历史摘要

### P1（应该完成）
4. **追问智能化**：槽位定义、信息完整性评估、统一追问服务
5. **对话管线统一**：DialogueService改为调用Orchestrator服务
6. **安全护栏增强**：多轮对话路径接入与单轮一致的安全机制

### P2（可以延后）
7. **记忆系统增强**：向量检索和对话历史独立表结构
8. **多轮对话质量评估**：自动评估对话连贯性和信息完整度

## 三、不做清单
1. 不做实时语音对话
2. 不做多用户群聊
3. 不做对话内容审核（由安全护栏统一处理）
4. 不做对话导出功能
5. 不做跨会话记忆共享

## 四、验收用例
1. 统一状态机覆盖所有现有对话场景
2. 滑动窗口在2000 Token限制内正确截断
3. 摘要压缩保留关键信息 ≥ 80%
4. 追问服务正确识别缺失槽位 ≥ 90%
5. 安全护栏拦截率与单轮一致

## 五、约束
- 不影响现有单轮对话功能
- 状态机迁移需向后兼容
- Token限制遵循LLM Provider约束
