## 第三层：经验沉淀

### 新编号经验

#### E91｜PowerShell 函数隐式输出陷阱

- **教训**：PowerShell 函数返回所有管道输出，不仅 `return` 语句。`Get-Content`、`Tee-Object`、甚至 `npm run build` 的输出都会混入返回值
- **反例**：`Invoke-BuildCommand` 3 次修复（cmd /c → Start-Process → Tee-Object → Out-Null + Write-Host），每次都是因为上一行输出混入 `$LASTEXITCODE` 或 `return`
- **触发词**：PowerShell 函数返回值 / exit code 异常 / 管道输出 / $LASTEXITCODE 错误 / 部署脚本
- **修复模式**：`... | Out-Null` + `Write-Host` 显式输出（不经过管道）
- **来源**：2026-06-16 部署脚本 exit code 误判修复，3 次迭代
- **置信度**：high（已验证 3 次）

#### E92｜组件开发→接入 checklist

- **教训**：组件开发完成后，必须检查是否被任何页面/路由导入。8 个孤儿组件（conclusion 4 + home 3 + form 1）都是预开发后遗忘
- **反例**：`BaguaDiagram`、`ConfidenceRing` 等 8 个组件写完 ≥30 天，从未被任何页面引用
- **触发词**：新建组件 / 新增页面 / 组件开发 / 孤儿组件
- **修复模式**：开发完成后运行 `grep -r "import.*ComponentName"` 确认引用
- **来源**：2026-06-16 执行检查孤儿文件扫描
- **置信度**：high

#### E93｜修复后必须再审核（Fix→Re-review 闭环）

- **教训**：审核发现的问题修复后，必须再跑一次审核（至少快速扫描），否则修复可能引入新问题
- **反例**：本次修复 P0 竞态条件后，直接进入 CI/CD 而非再审核；虽然 CI/CD 全通过，但缺少审核视角的二次确认
- **触发词**：修复后 / 修复完成 / fix done / 审核→修复
- **修复模式**：修复后至少跑一次快速审核（安全扫描 + 代码审查 5 分钟版）
- **来源**：2026-06-16 审核→修复→CI/CD 流程
- **置信度**：medium（本次未出现新问题，但模式风险存在）
