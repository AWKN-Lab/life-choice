# E87｜评分必须基于验证而非假设

## 触发条件
评分 / 打分 / 评估 / 现状分析 / 质量评估

## 教训
部署就绪打了 50 分是因为"假设没有 Docker"，实际全都有。评分偏差 32 分（50→82），根因是没读文件就打分。

## 反例
直接按"没有 CI/CD"假设打分，实际 .github/workflows/ci.yml 已存在。Dockerfile/docker-compose/nginx 配置全部已存在。

## 判断规则
评分前必须先读关键文件确认事实：
1. 列出评分维度
2. 每个维度先读文件确认现状
3. 基于事实打分，不基于假设打分
4. 标注"已验证"vs"待确认"
