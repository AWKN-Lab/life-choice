## 二、假设与决策

### 决策 1：P0-5 知识库调用链路 — 前端预留 + UI 展示
- **决策**：前端扩展 `consultApi.analyze` 参数（添加 `knowledge_base_id?` / `retrieval_context?`），并在 `UnifiedResult` 类型添加 `citations?` 字段；ResultPage 展示 citations 引用来源卡片
- **理由**：后端 RAG 集成属于第三阶段（上线后 1-2 月），前端先预留接口与 UI，后端就绪后即可联调
- **不做**：不实现前端向量检索，不调用 embedding API

### 决策 2：P1-4 意图路由升级 — 前端 AI 路由接口 + 关键词降级
- **决策**：`intentRouter.ts` 新增 `routeIntentAI()` 函数，调用后端 `/consult/route` API；保留 `routeIntent()` 关键词匹配作为 fallback；网络失败/超时自动降级
- **理由**：后端已有 `/consult/route` 接口（`consult.ts` L83-87），前端只需接入并保留降级
- **不做**：不实现前端 LLM 调用

### 决策 3：P0-1 ResultPage 继续抽取 — 渐进抽取 3 块独立逻辑
- **决策**：将 L1218-1293 的 4 个 `<details>` 内联块抽取为 `ResultAdvancedTools` 组件（单独文件），目标 ResultPage 降至 ~1100 行
- **理由**：这 4 块逻辑（八字详情/综合报告/海报/K线卡片）功能内聚，抽取风险低
- **不做**：不重构 ResultPage 的 state 管理（40+ useState 风险过高，留待后续）

### 决策 4：P1-1 首页重构 — 3 屏以内
- **决策**：合并 AnimatedText 入 HeroBanner；EngineFeatures 与 HomeFAQ 合并为可折叠的 `HomeEngineAndFAQ`；保留 MetaphysicsShowcase（扩展后）和 CriticalMoments
- **理由**：减少滚动层级，突出核心入口
- **不做**：不删除任何功能模块，只重组层级

### 决策 5：P1-2 取名结果闭环 — 跳转 ResultPage 完整报告
- **决策**：FrontdeskChat 取名结果展示后，增加"查看完整分析报告"按钮，通过 `saveConsultData` 传递数据并 `navigate('/result?type=quming')`
- **理由**：复用现有 ResultPage 报告视图，无需新建页面

### 决策 6：P2-4 PWA 支持 — 最小可用
- **决策**：添加 `manifest.json` + Vite PWA 插件基础配置（仅缓存静态资源，不缓存 API）
- **理由**：移动端体验优化，离线可用基础框架
- **不做**：不实现复杂离线策略
