**文件**: `.github/workflows/ci.yml` L113-121

```yaml

  cd /opt/awkn-life
  git pull origin main

  npx prisma migrate deploy
```

## 五、假设与决策

### 假设
1. 服务器部署路径为 `/opt/awkn-life`（CI 脚本现有路径）
2. 前端静态文件部署到 `/var/www/awkn-life/`（需根据实际 nginx 配置确认）
3. knowledge-service 的 top1_text 错误已修复，acceptance_log.txt 为过期日志
4. useMembershipTier hook 的 checkIsAdmin 签名与 ResultPage 内联定义一致
5. vite-plugin-pwa 与当前 vite 版本兼容

### 决策
1. **CI 部署脚本**: 补充前端构建步骤，使用 rsync 同步到 nginx 目录

5. **PWA**: 使用 vite-plugin-pwa 的 autoUpdate 模式
6. **console.log 清理**: 保留 console.error，删除 console.log
7. **eslint 升级**: 仅升级 2 条关键规则，避免大规模重构
8. **commit 粒度**: 按任务类型分批，不按文件分批

## 七、风险与回滚

### 风险点
1. **F5 意图路由**: async 改造可能引入 loading 状态 bug → 保留同步 routeIntent 作为降级
2. **F8 K线 WebSocket**: WS 连接可能不稳定 → 保留轮询降级逻辑
3. **F9 PWA service worker**: 缓存可能导致用户看到旧版本 → 使用 autoUpdate + skipWaiting
4. **F11 console.log 清理**: 可能误删有用日志 → 逐文件 review，保留 error 级别
5. **F13 eslint 升级**: 可能暴露大量现有 warn → 先修复再升级

### 回滚策略
- 每个 F1-F14 独立 commit，可单独 revert
- F15 分批 commit 确保粒度可控
- 若某阶段 build 失败，立即停止并回滚该阶段最后一个 commit
