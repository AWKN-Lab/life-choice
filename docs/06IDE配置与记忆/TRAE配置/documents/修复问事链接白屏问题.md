# 修复"问事"链接白屏问题

## 摘要

用户反馈"问事"链接（`/consult` 路由，ConsultPage 组件）打开后白屏。经深度探索，静态分析未发现单一必然导致白屏的代码路径，但发现 **App.tsx 的 `<Suspense>` 外层缺少 `<ErrorBoundary>`** 是最关键的架构缺陷——一旦 ConsultPage 的 lazy 加载失败或渲染时抛异常，整个应用白屏且无任何错误提示。本计划通过添加全局 ErrorBoundary + lazy 加载错误恢复 + 实际浏览器验证来定位和修复根因。

### 发现的关键问题

#### 问题 1：App.tsx Suspense 外层无 ErrorBoundary（最高风险）

**位置**：[App.tsx](file:///C:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/App.tsx) 第 72-105 行

**现状代码**：
```tsx
function App() {
  return (
    <BrowserRouter basename={import.meta.env.BASE_URL.replace(/\/$/, '')}>
      <Suspense fallback={<PageLoader />}>
        <Routes>
          <Route path="/consult" element={<ConsultPage />} />
          {/* ...其他路由 */}
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

**问题分析**：
- `<Suspense>` 外层没有 `<ErrorBoundary>` 包裹
- ConsultPage 使用 `lazy()` 加载（第 11 行）
- 若 ConsultPage 的 lazy import 失败（模块加载错误），React.lazy 抛出的异常**不会被捕获**，导致整个应用白屏
- ConsultPage 组件本身的 `useSearchParams()` 和 `useNavigate()`（第 464、466 行）在内部 ErrorBoundary **外部**，若抛异常也无法被捕获

**影响**：任何 lazy 加载失败或组件渲染异常 → 整个应用白屏，无错误提示

#### 问题 2：无法获取白屏的实际错误证据

- 浏览器工具超时，无法查看控制台错误
- 静态分析无法确定具体的运行时错误
- 需要添加错误日志收集机制

#### 问题 3：线上版本与本地版本不一致

- 线上：`index-CynjNVCw.js`、`ConsultPage-Bid86P4z.js`
- 本地最新构建：`index-1euDjxxP.js`、`ConsultPage-CgFT1n7z.js`
- 可能是部署脚本构建环境差异，但不影响功能

## 修复方案

### 改动 1：App.tsx 添加全局 ErrorBoundary

**文件**：[App.tsx](file:///C:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/App.tsx)

**改什么**：在 `<Suspense>` 外层包裹 `<ErrorBoundary>`，捕获 lazy 加载失败和渲染异常

**为什么**：当前 Suspense 外层无 ErrorBoundary，lazy 加载失败会导致整个应用白屏且无错误提示

**怎么改**：
```tsx
// 在 App 组件中，Suspense 外层包裹 ErrorBoundary
function App() {
  return (
    <BrowserRouter basename={import.meta.env.BASE_URL.replace(/\/$/, '')}>
      <ErrorBoundary>
        <Suspense fallback={<PageLoader />}>
          <Routes>
            {/* ...现有路由 */}
          </Routes>
        </Suspense>
      </ErrorBoundary>
    </BrowserRouter>
  );
}
```

需要导入 ErrorBoundary：
```tsx
import { ErrorBoundary } from '@/components/ErrorBoundary';
```

### 改动 2：ErrorBoundary 增强错误日志

**文件**：[ErrorBoundary.tsx](file:///C:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/components/ErrorBoundary.tsx)

**改什么**：在 `componentDidCatch` 中添加更详细的错误日志，包括错误堆栈和组件栈

**为什么**：当前只 `console.error`，需要更详细的错误信息来定位白屏根因

**怎么改**：
```tsx
componentDidCatch(error: Error, errorInfo: ErrorInfo) {
  console.error('[ErrorBoundary] 错误捕获:', {
    error: error.message,
    stack: error.stack,
    componentStack: errorInfo.componentStack,
    timestamp: new Date().toISOString(),
  });
  this.props.onError?.(error, errorInfo);
}
```

### 改动 3：lazy 加载添加错误恢复机制

**文件**：[App.tsx](file:///C:/Users/10919/Desktop/AWKN-Lab/人生决策宗师/apps/AWKN-LABlife/app/src/App.tsx)

**改什么**：为 lazy 加载添加重试机制，防止临时性加载失败导致永久白屏

**为什么**：网络抖动或临时性加载失败不应导致永久白屏

**怎么改**：
```tsx
function lazyWithRetry<T extends ComponentType<any>>(
  factory: () => Promise<{ default: T }>
) {
  return lazy(() =>
    factory().catch((error) => {
      // 记录错误并重试一次
      console.error('[Lazy Load Error]', error);
      return factory();
    })
  );
}

// 使用 lazyWithRetry 替代 lazy
const ConsultPage = lazyWithRetry(() => import('@/pages/ConsultPage').then(m => ({ default: m.ConsultPage })));
```

## 假设与决策

### 假设
1. 白屏是由于 ConsultPage lazy 加载失败或渲染时抛异常导致
2. 添加 ErrorBoundary 后，即使白屏也能显示错误信息，便于定位根因
3. 线上版本与本地版本不一致不影响功能（仅 hash 不同）

### 决策
1. **优先添加 ErrorBoundary**：即使不能立即确定根因，添加 ErrorBoundary 也能防止白屏并显示错误信息
2. **添加 lazy 加载重试**：防止临时性加载失败导致永久白屏
3. **部署后实际验证**：静态分析有局限，需要浏览器实际验证
