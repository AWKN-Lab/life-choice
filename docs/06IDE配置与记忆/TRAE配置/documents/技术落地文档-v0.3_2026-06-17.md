### 2.2 修复方案

#### 方案A：统一 API 客户端（推荐）

**新增文件**：`app/src/services/apiClient.ts`

```typescript
// 统一 fetch 封装，自动注入 JWT
const API_BASE = import.meta.env.VITE_API_BASE_URL || '/api/v1';

export async function apiFetch<T>(
  path: string,
  options: RequestInit = {}
): Promise<T> {
  const token = localStorage.getItem('auth_token');
  const headers: Record<string, string> = {
    'Content-Type': 'application/json',
    ...options.headers as Record<string, string>,
  };
  if (token) {
    headers['Authorization'] = `Bearer ${token}`;
  }
  const res = await fetch(`${API_BASE}${path}`, { ...options, headers });
  if (res.status === 401) {
    // 触发登录模态框
    window.dispatchEvent(new CustomEvent('auth:required'));
    throw new Error('Authentication required');
  }
  if (!res.ok) throw new Error(`API error: ${res.status}`);
  return res.json();
}
```

**修改文件**：3个 API 服务文件统一改用 `apiFetch`

- `shumiyuanApi.ts`：`fetch(...)` → `apiFetch(...)`
- `chronicleApi.ts`：移除 `?userId=${userId}`，改用 `apiFetch`（JWT 自动注入）
- `starChartApi.ts`：`fetch(...)` → `apiFetch(...)`

**修改文件**：2个页面文件移除硬编码

- `TongjianPage.tsx` L21/L44：移除 `const userId = ''`，API 调用不再传 userId
- `ShumiyuanPage.tsx` L37：speak 调用注入 userId（从 auth context 获取）

#### 方案B：拦截器模式（备选）

在 `app/src/api/` 下新增拦截器，monkey-patch 全局 fetch。**不推荐**，侵入性高。

## 四、M3：CI/CD 补部署阶段

### 4.1 修改文件

**文件**：`.github/workflows/ci.yml`

新增 deploy job：

```yaml
deploy:
  needs: [backend, frontend, docker-build]
  if: github.ref == 'refs/heads/main'
  runs-on: ubuntu-latest
  steps:
    - name: Deploy via SSH
      uses: appleboy/ssh-action@v1
      with:
        host: ${{ secrets.DEPLOY_HOST }}
        username: ${{ secrets.DEPLOY_USER }}
        key: ${{ secrets.DEPLOY_SSH_KEY }}
        script: |
          cd /opt/awkn-life
          git pull origin main
          cd awkn-life-backend
          npm ci --production
          npx prisma migrate deploy
          npm run build
          pm2 reload awkn-life-backend
```

### 4.2 GitHub Secrets 需配置

| Secret | 说明 |
|--------|------|
| DEPLOY_HOST | 服务器 IP |
| DEPLOY_USER | SSH 用户 |
| DEPLOY_SSH_KEY | SSH 私钥 |

### 4.3 验证方式

1. push 到 main 分支
2. GitHub Actions 页面查看 4 个 job 全绿
