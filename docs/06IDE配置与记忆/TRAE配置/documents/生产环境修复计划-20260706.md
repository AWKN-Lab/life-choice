## A. 目标与边界

### 目标一句话
将生产环境从"能跑但不可信"状态治理为"可追溯、可复现、可回滚"的稳定基线。

### 本轮做（5 项）
1. 修复 5 个已识别问题（P0-001/002, P1-001/002, P2-001）
2. 对齐端口不一致（3002 vs 30000）— 隐藏 P0
3. 完善服务器 .gitignore（治理 519 个未提交修改）
4. 回写部署标准文件（project-deploy-standards.md / project-天火Life.md）
5. 沉淀"本地 build dist → 上传"为唯一可信部署方式

### 本轮不做（5 项）
1. ❌ 不恢复生产 src 的 47 个缺失模块（成本高，dist 上传已可行）
2. ❌ 不建立生产 Git 仓库与远程的 push/pull 同步（风险大，单独项目）
3. ❌ 不排查 awkn.life 域名 HTTPS 超时（不在本次问题清单，awkn.cn 可用）
4. ❌ 不重跑 Golden Case（需要 LLM API key + 长耗时，留后续）
5. ❌ 不做端到端问事流程验证（需要真实用户登录，留后续）

### 约束与假设
1. 本地 commit `4b27314f` (main) 是唯一可信源
2. 部署技能 E-A6：未核验线上实况前，禁止修改 Nginx 或 PM2 端口配置
3. 部署技能 E-A22：改 PM2/Nginx 配置前先确认生产是否使用该配置启动
4. 任何高风险操作前必须先备份（SAFETY GATE）
5. 端口对齐以"生产实况 ss -tlnp + Nginx -T"为准，禁止凭标准文件反向修改生产
6. 当前生产服务 online（pid=1085329），任何修改不得中断服务
