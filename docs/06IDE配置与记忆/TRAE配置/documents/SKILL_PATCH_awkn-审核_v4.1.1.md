- 审核打回的问题已修复
- 修复完成后准备进入 CI/CD 或部署
- 用户说"修复完成"或"fix done"

### E93.2 核心规则

**修复后必须再审核。** 审核发现的问题修复后，必须重新跑一次审核（至少快速扫描），否则修复可能引入新问题。

快速审核（5 分钟版）至少覆盖：
1. **安全扫描**：修复是否引入了新的竞态/SQL注入/XSS
2. **diff 审查**：修复代码的 diff 扫描（新增代码是否有明显问题）
3. **测试覆盖**：修复涉及的模块是否有对应测试

### E93.3 反例
审核发现 4 个问题（P0 竞态 + P1 N+1 + P1 占位符 + P2 空指针）→ 修复 → 直接进入 CI/CD 和部署。修复可能引入新问题（如乐观锁的 edge case、批量查询的边界条件），但未经审核视角二次确认。

### E93.4 防复发
- 审核打回的问题修复后，必须重新提交审核，不得直接进入 CI/CD
- 质量门禁增加"修复后再审核"检查项
- 触发词：修复后、修复完成、fix done、审核→修复、打回→修复
