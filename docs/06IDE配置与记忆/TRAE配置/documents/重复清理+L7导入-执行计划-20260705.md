- **回滚方式**: `rm scripts/dedupe_passages.py`
- **风险标记**: 中（去重逻辑错误可能误删）

- **风险标记**: 高（生产部署 + 1.4GB 文件传输）
- **Plan B**: 若 PM2 启动失败（OOM），设置 `KNOWLEDGE_USE_MMAP=1` 重启

## 4. 假设与决策

### 4.1 关键假设

1. **去重保留策略**：每组重复保留 passage_id 排序最小的那条（首遇保留）
   - 替代方案：保留 text 最长的（信息量最大），但实现复杂
2. **22 个 md 文件质量良好**：OCR 转换的 md 文件可被 split_md_content 正确切分
   - 风险：OCR 质量差可能导致 passages 短/乱
3. **L7 新增 passages 数预计 5000-20000**：基于 L6 的 15 本 92,284 passages 推算
4. **服务器磁盘 3.8GB 足够**：替换后净变化小（去重 -34975 + L7 新增 ≈ 平衡）

### 4.2 关键决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 去重保留策略 | 首遇保留（passage_id 最小） | 实现简单，可重现 |
| L7 数据源 | 复制到 knowledge/ 下 | _archive 被 .gitignore 排除 |
| L7 切分策略 | 复用 split_md_content（MAX_LEN=400） | 保持与现有索引一致 |
| L7 分类策略 | 复用 detect_system_type | 保持与现有索引一致 |
| 部署方式 | 任务 A+B 合并部署 | 减少生产重启次数 |
| Commit 策略 | 任务 A 一个 commit + 任务 B 一个 commit | 可独立回滚 |
