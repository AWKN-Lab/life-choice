## 3. 假设与决策

### 3.1 假设

1. **假设**: 修复计划中已读取的代码行号在撰写文档时仍有效
   - **依据**: 修复计划生成于 2026-07-03，距今 0 天，代码未变
   - **风险**: 若期间有其他会话修改了 main.py/loader.py/knowledge_ingest.py，行号会失效
   - **缓解**: 撰写前用 Grep 快速验证关键行（L7/L22/L61/L93/L109/L132/L225）

2. **假设**: 生产 knowledge-service 当前未部署（main.py L357 是开发模式）
   - **依据**: PRD 第 1 节"当前 /retrieve 返回 0 条"
   - **风险**: 如果生产有其他实例在运行，文档中的端口 8701 可能与生产冲突
   - **缓解**: 在交接文档"未确认项"中列出"生产 knowledge-service 部署状态"

3. **假设**: 12 个分类中至少有 bazi/ziwei/quming/daoism 4 个有实际书籍
   - **依据**: knowledge_ingest.py L93 的"斗数"关键词表明有紫微书；PRD 第 4 节提到取名/康熙字典/道德经/道教
   - **风险**: 其他 8 个分类（qimen/liuren/liuyao/meihua/zhouyi/fengshui/xiangshu/other）可能为空
   - **缓解**: 在交接文档"测试用例"中加"分类非空验证"

### 3.2 决策

1. **决策**: 文档 A 顺序按 G1→G3→G0+G2→G6（与修复计划一致，与 PRD 不同）
   - **理由**: 修复计划已论证 G1 优先的合理性（用户正在受影响）
   - **文档处理**: 在文档 A 章节 1 附"与 PRD 差异说明"，明确不违背 PRD，只是调整执行顺序

2. **决策**: 文档 B 不重复文档 A 的变更细节
   - **理由**: 沿用 RULE DOC-LAYER-SPLIT，避免混层
   - **文档处理**: 文档 B 引用文档 A 的章节号（如"详见工程交接文档 §3.2"），不复制代码片段

3. **决策**: 接口示例响应使用"修复后真实形态"，不用"当前坏形态"
