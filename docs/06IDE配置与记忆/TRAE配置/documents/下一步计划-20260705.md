## 三、推荐执行方案（3 选 1）

### 方案 A：技术债优先（推荐）
**路径**：P0-4 → L7 → P1-5/6/7 → P1-4 部署 → 服务器扩容 → L8/L9
**优点**：
- 清掉最后一个 P0 阻断，技术债收口
- L7 简单（已 OCR），快速完成
- 为后续产品开发和扩容争取时间
**缺点**：产品功能延后，用户可见收益慢
**适用**：技术债累积风险高，需要先稳住基础

### 方案 B：产品功能优先
**路径**：任务 2（K线/潮汐）→ 任务 3（¥1 深推）→ P0-4 → L7 → 扩容
**优点**：
- 快速交付用户可见功能（差异化 + 变现）
- 任务 1 已 PASS，可立即开工
**缺点**：
- P0-4 阻断累积，风险上升
- 产品功能可能踩到 P0-4 未修复的坑
**适用**：业务压力大，需要快速验证产品价值

### 方案 C：并行推进
**路径**：P0-4 + 任务 2/3 并行 → L7 → 扩容
**优点**：技术债和产品功能同步推进
**缺点**：注意力分散，需要多线程协调
**适用**：有多个执行者，可以分工
