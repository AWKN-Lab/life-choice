### ⚠️ 部署阶段的 5 个关键卡点（教训）

#### 卡点 1：scp 直接传目录超时
- **现象**：`scp -r apps/ root@server:/opt/awkn-life/` 等待 2+ 分钟 timeout
- **原因**：未排除 node_modules，单个目录可能含 10000+ 文件
- **错误做法**：重试同样的命令
- **正确做法**：立刻 tar 排除后单文件传输
- **影响**：浪费时间约 3-5 分钟
- **进化方向**：scp/deploy 任务前置命令必须 tar 化

#### 卡点 2：PM2 路径错误
- **现象**：`Error: Cannot find module '/opt/awkn-life/awkn-life-backend/apps/api-server/dist/src/main.js'`
- **根因**：`bootstrap-production.js` 写死 `dist/src/main.js`，但 tsconfig 是：
  ```json
  { "outDir": "./dist", "rootDir": "./src" }
  ```
  → tsc 实际输出 `dist/main.js`
- **错误做法**：在远程端用 sed 改（PowerShell heredoc 转义复杂，3 次才成功）
- **正确做法**：本地编辑 → scp 上传 → pm2 restart
- **影响**：浪费时间约 5-8 分钟，且本地未编辑前已尝试远程改
- **进化方向**：本地构建产物路径必须在本地验证，再 scp

#### 卡点 3：累积 121 文件一起提交
- **风险**：一次 commit 含 UI/后端/部署脚本/路由修复，回滚粒度太粗
- **系统规则违反**：明确要求"小步修改"，但 UI 阶段+部署阶段累计超 50 行/30 文件
- **进化方向**：每个 UI 问题修完立即 WIP 备份（git commit "WIP"）

#### 卡点 4：未在本地模拟部署链路
- **现象**：远程端 PM2 失败前，未在本地用相同 tsconfig 跑一次 `npx tsc` 确认输出路径
- **应该做的**：在本地 `cd apps/api-server && npx tsc && ls dist/`
- **影响**：浪费时间 5+ 分钟

#### 卡点 5：审计结果不完整
- **现象**：6 个并行扫描只回来 5 个，安全审查（chart.tsx dangerouslySetInnerHTML）没在第一批
- **用户反馈**："Continue" → 补齐
- **进化方向**：并行任务完成后必须"全部到达"才输出，否则告警"结果不完整"

## 七、问题点全景分析

### 7.1 流程类问题（系统层面）

#### P1：缺乏"分阶段门禁"
- **现状**：UI 修复 + 时辰圆盘重设计 + 部署 + 审计一口气做完
- **应该做的**：每个阶段完成 → 输出结果单 → 用户确认 → 进入下一阶段
- **系统规则违反**：SR4 "每个 Skill 必须产出结果单"
- **影响**：如果中间出错（如部署失败），需要从头排查

#### P2：用户反馈未及时捕获
- **现象**：用户在阶段 A 完成后立刻给了阶段 B 反馈，但 AI 直到阶段 D 才部署
- **影响**：阶段 A→D 之间又有代码修改，引入新风险
- **进化方向**：用户任何"修改指令"立刻同步到当前会话的 in-progress 任务

#### P3：审计并行扫描的结果丢失
- **现象**：6 个并行扫描，5 个回来，1 个漏掉
- **根本原因**：并行调用没有"all-or-nothing"机制
- **修复方案**：Skill 设计上要"等全部完成才输出"

### 7.2 工具/命令类问题

#### T1：PowerShell heredoc 转义痛苦
- **现状**：SSH 远程命令含 `$(date)`、引号等，3 次才成功
- **改进**：所有远程编辑改为"本地编辑 + scp 上传"

#### T2：scp 排除模式不熟
- **现状**：第一次不知道要排除 node_modules，第二次才想起来 tar
- **改进**：在 deploy skill 里固化 `tar --exclude={node_modules,.git,dist}` 模式

#### T3：PM2 启动验证慢
- **现状**：用 `pm2 logs` 看启动错误，要等 5-10 秒
- **改进**：先用 `node dist/main.js` 试跑 1 秒，更快暴露路径/语法错误

### 7.3 决策类问题

#### D1：UI 修复 vs 交互增强，未区分版本
- **现状**：阶段 A（修复）+ 阶段 B（增强）紧耦合提交
- **应该做的**：阶段 A 单独 commit，阶段 B 单独 commit
- **影响**：回滚粒度粗

#### D2：审计执行模式选择不当
- **现状**：6 个维度"并行扫描"
- **更好做法**：分两批，先并行 3 个核心（代码/安全/部署），再并行 3 个补充（端到端/AI/供应链）
- **原因**：核心维度结果先出，可立即判断"能否上线"

### 7.4 认知/方法论类问题

#### C1：未使用"饭要一口一口吃"技能
- **现象**：用户给了 "/plan" 触发技能，但 AI 实际执行的步骤远多于计划
- **改进**：当计划步数 ≤ 8 时严格遵守，超出则停下重新规划

#### C2：审计结果未形成"结果单"
- **系统规则要求**："每个 Skill 执行完成后，必须生成对应结果单"
- **现状**：审计仅口头输出 PASS_WITH_RISKS，未形成 Markdown 结果单
- **改进**：审计技能应强制输出 `.claude/audits/<date>-<topic>.md`

#### C3：复盘技能降级方案缺失
- **现象**：`AWKN 复盘总结` 技能调用超时（IDE Command timeout）
- **应该做的**：当 Skill 调用失败时，AI 应手动按 Skill 框架输出，而非放弃
